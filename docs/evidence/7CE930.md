# 0x7CE930 CVidTile::BltDualTile8To32

## What it is

The 32-bpp target of the dual-tile Render dispatcher 0x7B1F70's bpp switch
(`case 32`, jump at 0x7B21F4). Thiscall on the CVidTile, `ret 0x24` = nine
stack args, same signature shape as BltDualTile8To16 0x7B25E0:
`BltDualTile8To32(DWORD* pSurface, LONG lPitch, BYTE* pData, BYTE*
pDualData, CResTile* pResDualTile, BYTE nDitherSeed, const CSize& blitSize,
LONG nDataJump, DWORD dwFlags)`. Same per-pixel palette blend through the
64x64x32 blend cube, one DWORD per pixel. 927 bytes (0x7CE930-0x7CECEC).

## Decode (annotate 0x7CE930-0x7CECEC)

- Setup identical to the 16-bpp blitter: local `CVidPalette cDualPalette`
  (ctor called at 0x7CE975); six NULL-guarded video-mode reads
  (0x7CE97A-0x7CEA05); m_pBlendTable [0x9060F0] NULL -> BuildBlendTable
  0x7ACCB0 called directly (0x7CEA14) - not an inlined fill loop as in
  0x7B25E0; failure runs the local dtor and returns 0 (0x7CEA1D-0x7CEA41).
- nDitherSeed >>= 3 (0x7CEA44-0x7CEA51); SetPalette #1 0x7CEA73:
  m_cPalette (this+4).SetPalette(pRes->m_pPalette (+0x50), 0x100,
  TYPE_RESOURCE); #2 0x7CEA94: cDualPalette.SetPalette(
  pResDualTile->m_pPalette, ...).
- Realize #1 0x7CEAB9: m_cPalette.Realize(rgbTempPal 0x9064F8, 32,
  dwFlags|0x400000, &m_paletteAffects (this+0x28, 0x7CEA99), 255); #2
  0x7CEAD0: cDualPalette.Realize(rgbDualTempPal 0x9060F4, 32, ...) - bpp
  0x20.
- nSurfaceJump = (lPitch>>2) - width, counted in DWORDs (0x7CEAE1-0x7CEAE4);
  height <= 0 -> local dtor, return 1 (test/jle 0x7CEAE6 -> 0x7CECA4) -
  AFTER both Realizes, kept.
- One pixel loop 0x7CEB74-0x7CEC66 over the width: a cursor walks the dual
  data (row base = pDualData + accumulator; the accumulator grows by
  width+nDataJump per row - 0x7CEB35/0x7CEC89); the primary byte is read
  at [delta+cursor] with delta = pData - pDualData (0x7CEB37). Palette
  entries are DWORDs ([byte*4 + 0x9064F8] / [byte*4 + 0x9060F4]); per
  channel the 16-bpp cube lookup (((x<<6)+y)<<5 + phase); plain DWORD
  store at [edx-4] (0x7CEC52) with dest += 4 and dual cursor inc
  (0x7CEC59).
- Row end 0x7CEC6C-0x7CEC9E: dest += nSurfaceJump DWORDs via lea edx,
  [edx+ecx*4] (0x7CEC8B) - exactly +lPitch; height dec/jne back to the
  width test (0x7CEC9E -> 0x7CEB01). A width <= 0 row (jle 0x7CEB07 ->
  0x7CEC7E) stores nothing and still advances - the original's dest move
  there reads stale registers, but nothing is written and the return is
  unaffected; the port uses the natural per-row advance.
- Success epilogue 0x7CECA4: local dtor, return 1 (0x7CECBC), ret 0x24 at
  0x7CECCC.

## Port

`src/CVidImage.cpp` `CVidTile::BltDualTile8To32`, declaration in
`src/CVidImage.h` after BltStencilTile8To32. Palette plumbing and channel
math mirror the 16-bpp port with Realize bpp 32 and the DWORD-counted
surface jump; the source stride is the correct width + nDataJump (unlike
the 24-bpp sibling's off-by-one, which is that sibling's quirk alone).
Parity ran 0 RED without a waiver.

## Callers

The dual-tile Render 0x7B1F70's `case 32` (0x7B21F4), wired in this task;
sole ultimate caller CInfTileSet::RenderToPrimary 0x5CB260's default-tile
arm.
