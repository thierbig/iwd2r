# 0x71CC90 CGameSprite::sub_71CC90

528 bytes, the CGameSprite member that CheckStatsChange (0x71C0C0)
tail-calls at 0x71CC6D. Plain `ret` = thiscall, no stack arguments.

## Identification

Per-hand weapon/offhand fighting-style and proficiency bonuses at the end
of a stats recompute:

- resolves the selected weapon (`m_items[m_selectedWeapon]`) and the
  current weapon set's offhand slot (`(m_nWeaponSet + 22) * 2` as BYTE
  math, i.e. slot `2*set + 44` mirroring the weapon slot `2*set + 43` in
  sub_73D080 and the `buttonNum + 44` quick-weapon slots in 0x71D4B0);
- drops the offhand item when the selected weapon itself is slot 42
  (0x2a), or when its item type is 47/53/49/41 (the ammunition and
  launcher exclusions, decimal spelling per the 0x71D4B0 port at
  src/CGameSprite.cpp:11892);
- falls back to the fist slot via `SelectWeaponAbility(10, 0, 0, 1)` when
  the selected weapon slot is empty, then re-reads the slot
  (SelectWeaponAbility can change `m_selectedWeapon`);
- adds each hand's specialization damage bonus through sub_71CEA0
  (right hand then offhand);
- then, per range 2: skips the style arms when the weapon is unchanged
  since the last recompute (`m_equipment.field_128`, the cached CItem* at
  sprite+0x4B00 = equipment+0x128), demands the weapon, and applies the
  Dirty Fighting / Dodge / Discipline feat arms (sub_75E930) before
  Release.

## Decode notes

- SEH frame (`push -1 / push 0x83AAA8 / fs:0`): no handler body in the
  function -- the scope table only unwinds; the port keeps plain C++
  control flow, as the 0x71C0C0 port did.
- `push ecx` at 0x71CCA5 allocates the 4-byte nil-CString local
  ([esp+0x10] = `ds:0x8C1758` at 0x71CD5C, never read, dtor 0x7FCC1A at
  0x71CE88 on the nil is a no-op) -- handled in range 2.
- Offhand slot: `mov dl,[esi+0x4C68]; add dl,0x16; shl dl,1` -- BYTE
  arithmetic end to end, so the index wraps at 8 bits; the port casts the
  int product back to BYTE to match.
- Slot 42 (0x2a): raw byte compare against `m_selectedWeapon` before the
  offhand item is even tested for NULL.
- Four separate `GetItemType` calls for the exclusion chain (0x71CCE7 /
  0x71CCF4 / 0x71CD01 / 0x71CD0E) -- kept verbatim with the same FIXME
  marker the 0x71D4B0 port uses for this idiom.
- `SelectWeaponAbility(10, 0, 0, 1)`: args pushed 1 / 0 / 0 / 0xa; the
  two 0s reuse the NULL weapon register (edi). In-tree precedent:
  src/CGameSprite.cpp:11335.
- New member `/* 0128 */ CItem* field_128;` in CGameSpriteEquipment
  (sprite 0x4B00 - equipment base 0x4AD8): read at 0x71CD4F as
  `cmp edi,[esi+0x4B00]`. The exe ctor 0x7123F0 does NOT initialize it
  (it zeroes only [0x00-0xD4]), and no ported or exported function writes
  it yet, so in-tree it holds whatever the allocation left -- exactly the
  exe state. The read is a pointer compare with no dereference, and both
  of its branches sit behind sub_75E930 (the shipping stub returns 0), so
  the indeterminate value is unobservable today. Revisit when the +0x128
  writer is ported.

## Range-2 decode notes

- `bUnchanged` at 0x71CD4F: `cmp edi,[esi+0x4B00]` -- ebx was zeroed at
  0x71CCBE and set to 1 only on equality; the port spells it
  `BOOL bUnchanged = (pWeapon == m_equipment.field_128);`.
- `pAbility->type` low-byte compare `cmp BYTE PTR [eax],0x2` at 0x71CD8E:
  the house spelling is `static_cast<BYTE>(pAbility->type) != 2`
  (CDerivedStats.cpp:379). Type-byte 2 (ranged/melee distinction in the
  ability header) skips every style arm.
- Gate order: flags bit 1 (GetFlagsFile & 2) selects the ranged arm
  (Dirty Fighting, feat 0xE); otherwise the offhand decides -- an item
  still occupying the offhand slot (the raw re-read at 0x71CE11, so an
  excluded-but-present item counts) selects Discipline (feat 0xF,
  m_nACMissileMod += -2/-4), an empty slot selects Dodge (feat 0x10,
  field_6 += 1/2, m_nCriticalHitBonus += 1).
- Rank decode: `dec eax; je A; dec eax; jne exit` = rank 1 takes the
  first arm, rank 2 falls through to the second (which sits earlier in
  the instruction stream), anything else exits. Dirty Fighting rank 1 =
  +2 speed, rank 2 = +4 speed, both +1 m_DamageBonusRight (DWORD inc)
  and +1 m_nCriticalHitBonus.
- All three arms are dead in the shipping exe: sub_75E930 is the stub
  `xor eax,eax; ret 4` (docs/evidence/75E930.md) -- ported verbatim.
- `pWeapon->Demand()` at 0x71CD70 runs before the ability fetch with no
  NULL guard, matching the exe (the fist fallback in range 1 is expected
  to have armed slot 10).
- `m_equipment.m_items[nOffhandSlot]` is re-read raw at 0x71CE11 rather
  than reusing pOffhand -- an offhand item dropped by the range-1
  exclusions still steers to the Discipline arm; kept verbatim.
