# 0x43B080 CBaldurMessage::OnDeleteAreaPoll

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x43B080` and the Ghidra decompile
below; Ghidra names the function `FUN_0043b080`.

## Identity and calling convention

Member of CBaldurMessage in the original's Baldur/CMessage.cpp, dispatched
by 0x4EE020's `DELETEAREA` (k = 107) `/` `s` (115) arm. `__thiscall`,
`ret 0xc`: `(INT nMsgFrom, BYTE* pByteMessage, DWORD dwSize)`; nMsgFrom is
ignored.

## Body

Guards: an established session and `m_bIsHost` false (only a client votes),
else FALSE. The handler decodes `{BYTE areaLen; char area[]}` and votes yes
when all of:
`GetArea(sArea) != NULL`, the area's `m_nCharacters` (+0x1ED) is 0, and the
area is not `CInfGame::m_pGameAreaMaster` (+0x3812). A yes clears the area's
`field_AE6` (+0xAE6, the "delete pending" marker).
`SendDeleteAreaVote(sArea, bVote)` then answers the host; the handler
returns TRUE regardless of the send's own result.
