## Notes

The port is `CBaldurMessage::SendReformPartyAnnounceStatus` in `src/CMessage.cpp`, with the two new
wire constants `MSG_TYPE_REFORMPARTY` (113, 0x84CFAD) and
`MSG_SUBTYPE_REFORMPARTY_ANNOUNCE_STATUS` (115, 0x84CFAF) in `CMessage.h`/`CMessage.cpp`. It
matches the disassembly: the session and hosting guards, `CreateBuffer(sizeof(BOOLEAN))`, the
single `TRUE` byte, the empty-recipient all-players guaranteed send, `DestroyBuffer` and TRUE (the
send's BOOLEAN is ignored, as in the original).

Proof is the unit test
`CBaldurMessage::SendReformPartyAnnounceStatus broadcasts the reform-party packet` in
`tests/test_network.cpp` (`[msg][network]`, no `IWD2_DATA`): a bare `CChitin` (the file's existing
`ChitinScope`) gives a real `cNetwork`; the test drives the closed-session and client guards, then,
with `m_nServiceProvider` set to a non-null value and `m_bIsHost` true, reads the packet out of the
public static `CNetwork::STATIC_MESSAGE_BUFFER`: `[0] = 0xFF` (SPEC_MSG_FLAG_ENABLED), `[1] = 113`,
`[2] = 115`, `[3] = 1` (the payload) and `[4]` untouched. That window exists because
`SendSpecificMessage` marshals the packet before `SendMessage_` returns FALSE in this
DirectPlay-less port (src/CNetwork.cpp:2508-2567); with the null provider it returns before the
buffer is written, which the test pins by clearing the buffer first.
