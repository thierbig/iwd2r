# 0x506000 CMessageSetDialogWait::MarshalMessage

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x506000` and the Ghidra decompile
below; Ghidra names the function `FUN_00506000`.

## Class identity

The owning class is CMessageSetDialogWait, a 0x14-byte CMessage subclass
with LONG m_wait at +0x0C and LONG m_waitTarget at +0x10 (ctor 0x4F5EB0,
GetCommType 0x40A0D0 SEND, GetMsgType 0x40A0E0, GetMsgSubType 0x485A10
subtype 40, Run 0x5062C0). The class is receive-only in single player: the
wait message goes to the machine that controls the waiting sprite.

## Body

`__thiscall void MarshalMessage(BYTE** pData, DWORD* dwSize)`, 453 bytes,
`ret 8`. Share the target (retry SHARED/DENIED); a failed share zeroes the
size and writes nothing. Write the target's remote pair, m_wait and the
m_waitTarget pair ((0, 0xFFFFFFFF) when that id does not resolve); the
payload is 0x14 bytes and the closing assert checks the count (0x5060FA).
## Wire format

Payload (without the 3-byte SPEC_MSG_HEADER): the target's remote pair
(PLAYER_ID m_remotePlayerID, LONG m_remoteObjectID), then LONG m_wait, then
m_waitTarget as a remote pair ((0, 0xFFFFFFFF) when it does not resolve).
Every pair goes through CGameRemoteObjectArray::Find: an unresolved
*target* pair rejects the message, and so does an unresolved wait-target
pair that is not (0, 0xFFFFFFFF).
