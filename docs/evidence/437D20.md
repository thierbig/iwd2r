## Identity and calling convention

Member of CBaldurMessage in the original's Baldur/CMessage.cpp, dispatched
by 0x4EE020's `LEAVEAREALUA` (X) `/` `r` (114) arm. Unlike its sibling
handlers it takes **two** stack arguments -- `ret 8` -- because the buffer
and a `dwSize` it never reads: the dispatcher pushes `pByteMessage` then
`dwSize` (`0x4F468D-0x4F4695` for the LEAVEAREANAME sibling shows the same
form). The port declares `BOOLEAN OnLeaveAreaLuaCancel(BYTE* pByteMessage,
DWORD dwSize)`.

## Body

The two entry guards come first: `m_bConnectionEstablished` must be set and
`m_bIsHost` must be false (the host's own request never reaches this
handler), else FALSE. The body then stores the first payload byte (the
buffer's offset 3, after the 3-byte SPEC_MSG header) into the waiting
slot `m_nLeaveAreaLuaReplyValue` (+0xDC) and marks
`m_bLeaveAreaLuaReplyReturned` (+0xDB) TRUE, returning TRUE. There is no
size check and no other state.
