## Notes

CGameSprite's vtable 0x85BDD4, slot 0x84 (0x728F80's case 21, the dispatcher range 0x7295F5-0x729605: `call 0x751CD0`, store the SHORT result). Both exits return ACTION_DONE (the WORD at 0x8485C4); the body has no error path.

The flow, in the original's order:

1. **Host portrait slot.** Only when `g_pChitin->cNetwork.m_bIsHost` (the byte at CNetwork +0x1033): scan the six slots with `CInfGame::GetCharacterSlot` (0x5BD650) and keep the last index whose id is `m_id` (the local at esp+0x14, a SHORT initialised to -1).
2. **Dying on its feet** (the block entered when `m_baseStats.m_hitPoints < 1` — the SHORT at sprite +0x5C0, CREATURE_HEADER +0x1C — and `m_derivedStats.m_generalState & (STATE_FROZEN_DEATH | STATE_STONE_DEATH)` is clear, `test byte [ebx+0x920], 0xC0`). It shares the protagonist (`CInfGame::GetProtagonist` 0x5BFC40, `GetShare` with THREAD_ASYNCH and INFINITE), then:
   - protagonist's `m_pArea` (the dword at shared +0x12) is NULL: `DropInventory(FALSE, CString(""))`;
   - otherwise takes the protagonist's `GetPos()` (+0x1C), divides it by `CPathSearch::GRID_SQUARE_SIZEX`/`SIZEY` (16/12, the bytes at 0x84D6A0/0x84D6A1), asserts `m_animation.m_animation != NULL` (ObjAnimation.h 0x82D), and calls `CSearchBitmap::GetNearestOpenSquare` (0x548B80, the bitmap at area +0x76C) with that square, `GetTerrainTable()` (vtable +0xA0), the animation type's `GetPersonalSpace()` (vtable +0x5C) and direction -1; scales the answer back (`x * 16 + 8`, `y * 12 + 6`), drops the inventory, asserts the animation again (ObjAnimation.h 0x821), calls `AddToArea(area, pt, 0, CanLieDown() ? CGAMEOBJECT_LIST_BACK : CGAMEOBJECT_LIST_FRONT)` (vtable +0x8; the animation type's `CanLieDown()` is vtable +0x28, the list types are the bytes at 0x84C50C/0x84C50D = 0/1), then `SetSequence(9)` (0x707230) and `SetFacing(GetDirection())` (0x706F80/0x706D50).
   Then `ReleaseShare` (0x599E70).
   NOTE: `CGameObject::AddToArea` (0x4C7BE0) moves the object only when `m_posVertList == NULL && m_pArea == NULL`, so for a creature already in the area this call does nothing — the original no-op is kept.
3. **Party removal.** `CInfGame::RemoveCharacterFromParty(m_id, overflow)` (0x5BD270). If it returns TRUE the body continues; if FALSE the allies/familiars fallback runs (0x7525C4): `RemoveCharacterFromAllies` (0x5BDA50), else `RemoveCharacterFromFamiliars` (0x5BDB20); only if one of them removed the id are the three AI sides set to EA_NEUTRAL; otherwise the action ends at the shared final block.
4. **Party-removed tail.** It walks `m_lstGlobalCreatures` (CInfGame +0x3848, the node value at +0x8) and `CPtrList::RemoveAt` (0x7FB3E3) the id. When `overflow` is FALSE and the area exists: `CMessageChangeDirection(0, m_id, m_id)` (0xE bytes, vtable 0x84C3C4, face byte at +0xC = 0) and the area's `m_nCharacters` (BYTE at +0x1ED) decremented unless it is 0xFF (the original skips the 0xFF case; JoinParty's increment has the mirror-image 0xFF → 1). The three AI sides become `CAIOBJECTTYPE_EA_NEUTRAL` (0x80, the byte at 0x847C3E). Scripts 1..5 through the virtual `SetScript` (vtable +0x94): empty `new CAIScript(CResRef(""))` in 1, 3, 4, 5 and **WTASIGHT** (0x8B8A1C) in 2. The leaving trigger is `CAITrigger(CAITRIGGER_LEAVES` = 5, `m_typeAI`, 0)`, sent to every remaining party member as `CMessageSetTrigger` (0x62 bytes, vtable 0x847BB8, the trigger copied by `CAITrigger::operator=` 0x466480). Then `(m_derivedStats.m_generalState & STATE_DEAD) != 0 && (m_baseStats.m_flags & 0x2) != 0` sets `m_expirationTime` (0x3E74) to the world timer's m_gameTime (0x1B78) — the corpse timer (the exe tests `test ah,0x8` on the state at 0x920 and `test byte [ebx+0x5AC],0x2` on the file flags at 0x7522CC/0x7522D1). Under an established connection `CBaldurMessage::CharacterPartyOrderRequest` (0x432050) is the only unported callee, a `// TODO: 0x432050` in this spot (and the same in sub_751BD0). On the host with a slot: `SetCharacterControlledByPlayer(slot, 0, FALSE, FALSE)`, `SignalCharacterStatus(slot, 12 = CHARSTATUS_SIGNAL_DELETED, TRUE, FALSE)` and `SetCharacterReady(slot, FALSE, TRUE)` (0x518710/0x518BA0/0x518A70; the settings object is CInfGame +0x1BB2).
5. **Overflow refill.** While `m_characterOverflow` (CInfGame +0x3864, the count is the array's own size) is non-empty: read index 0, `RemoveAt(0, 1)` (0x7FB8D0), and when the id is not INVALID_INDEX (-1) call `AddCharacterToParty(id, -1)` (0x5BD070). A FALSE answer puts the id back with `SetAtGrow(GetCount(), id)` (0x7FB967) and ends the loop. On success the object is denied (`GetDeny`, looped over SHARED/DENIED), the sprite's `sub_751BD0` (0x751BD0, the join bookkeeping below) runs on it, and it is released.
6. **Items.** Every `m_equipment.m_items` slot (the `CGameSpriteEquipment` at +0x4AD8, 51 slots; slot 10 = SLOT_FIST is skipped) that holds a `CItem` whose `GetFlagsFile() & 1` is set: `CMessageAddItem(*pItem, m_id, GetProtagonist())` (vtable 0x848BE8), `CInfGame::AddDisposableItem` (0x5BF4B0), `Unequip(slot)` (0x71B7A0) and the slot cleared.
7. **Final.** When the area exists and its `m_nCharacters` reached 0: `SelectCharacter(GetProtagonist(), FALSE)` (0x5AD8A0) and `SelectToolbar` (0x5ADAE0). Then the block is **skipped when the active engine is the world screen** (`pActiveEngine` = CChitin +0x3C4 compared with `m_pEngineWorld` = CBaldurChitin +0x1C88, `je` at 0x75265F); otherwise it reads `pActiveEngine` again and calls its `GetSelectedCharacter` (vtable +0xD0) and, when that equals `GetCharacterPortraitNum(m_id)` (0x5AF4E0), its `OnPortraitLClick` (vtable +0xE0) with the protagonist's portrait number. The active engine is the one called (0x752677 on `esi`, 0x7526A9 on `edi` = `pActiveEngine`), not `m_pEngineWorld`.

`sub_751BD0` (0x751BD0, evidence 751BD0.md) is the join bookkeeping the refill loop runs on the sprite it just added: `CMessageChangeDirection(1, m_id, m_id)`, the area count increment (0xFF → 1), the connection-established TODO, `RecordJoinParty` (0x4CB000) and, on the host, the slot assignment with status 11 (CHARSTATUS_SIGNAL_IMPORTED).
