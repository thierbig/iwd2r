## Notes

Identity: vtable 0x84D510 (subtype 55, CMessageSpriteEquipment) slot 0x10;
the paired Unmarshal is slot 0x14 (0x50B9A0) and Run slot 0x18 (0x50BBC0).
The survey's row 102 names this address correctly.

The 14-byte record is the target's remote id pair (the sprite that
Unmarshal resolves back through CGameRemoteObjectArray::Find), the item
count, the selected weapon as a byte, the selected weapon ability as a word
and the weapon set as a byte. Each equipped slot then follows as a word
slot index, a resref length byte and bytes, the three usage counts, the
item's wear and its file flags. Marshal gets a share of the target sprite
only to read its m_remotePlayerID/m_remoteObjectID; when the share fails it
reports a zero payload. The reported size is payload-only (the receiving
side's dwSize includes CNetwork::SPEC_MSG_HEADER_LENGTH).

Not executed: the network send path itself is omitted in this build, so
the function only runs through the test's direct call. No oracle case or
replay covers it.
