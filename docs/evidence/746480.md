handlers differ in reach, facing, use time, invisibility, the backfire die
count, case-7 effects and the projectile's target. No Ghidra export was
present, so there is no claimed Ghidra decompile here.

  0x746480..0x7473B1; its last instruction is the five-byte jump at
  0x7473AC..0x7473B1 to the common epilogue. Thus the supplied end 0x7473B1

  alignment bytes at 0x7473B1), then eight 32-bit entries run to 0x7473D3 and
  padding reaches the next handler at 0x7473E0.
- The listing below has 1,043 Capstone instructions. Its 45 distinct direct
  CALL targets were extracted separately for the source-call check; indirect
  virtual calls are discussed in the behavior notes.

  ExecuteAction calls it at 0x729AD6 after `GetTargetShareType(1)` at
  0x729AC7. Byte 1 at 0x84C501 is `CGameObject::TYPE_AIBASE`; it sets the
  dispatcher's share flag and goes to the common target-release tail.

## Effect jump table

The raw 32 bytes at 0x7473B4 decode little-endian as:

```
747005 74704B 74705C 747066 74706E 747078 74708A 7470B2
```

`m_targetType - 1` indexes these entries. They are respectively cases 1..8;
a value outside that range goes to the default deletion at 0x7470D0.

## Behavior and port notes

### Target and initial item selection (0x746480-0x746856)

- `field_55A0` is cleared even on an early error. A null target errors. A
  sprite target additionally requires `m_active`, `m_activeAI` and
  `m_activeImprisonment`; their original fields are target+0x50A6,
  target+0x50AA and target+0x50AE.
- A zero `m_actionCount` clears `m_curItem`. A retained item is demanded again.
  Empty string1 treats `m_specificID` as an equipment slot and
  `m_specificID2` as the ability. A non-empty string1 scans the 51 slots in
  order for its resref. Slot and ability are cached in `field_559E` and
  `field_55A0`; all missing-item/ability arms error, releasing the item where
  the original does.
- Ability `usageFlags == 3`, zero usage and a positive maximum emits Unusable
  with the item resref in string1, releases the item and errors.

### Range, approach and facing (0x746856-0x746C74)

- The dead check at 0x746856 reads the dword at target+0x5BC and tests bit
  0x800 (`STATE_DEAD`) on **every** AI object with no sprite gate: on a
  sprite that is m_baseStats' general state, on a door the closed bounding
  rect's bottom edge (m_rClosedBounding at +0x5B0, bottom at +0x5BC), and on
  containers, triggers and tiled objects pointer/list internals (all such
  objects are at least 0x5C0 bytes, so the vanilla read stays in bounds --
  it is type-confused, not out of bounds). The port cannot reproduce those
  cross-type bytes in its own layout, so it applies the dead test only where
  it is meaningful -- a sprite's base general state -- and treats every
  non-sprite target as live. A "dead" target skips the range and LOS
  checks. That dead-target arm at 0x74685F sends CMessageDropPath only when
  field_7118 (+0x7118, the same committed flag the reach and facing arms
  read) is set; it does not consult m_pPath (+0x5382), which is what
  UseItemPoint's drop paths gate on. The ordinary in-range arm joins at
  0x746AA8 and sends no such message; this is intentionally different from
  UseItemPoint.
- Grid coordinates use signed division by 16 and 12. Range is the unsigned
  ability word plus one. Two live sprites contribute
  `((selfSpace-1)>>1) + ((targetSpace-1)>>1) - 1`, retained as a BYTE; a
  non-sprite contributes only the caster's half-space.
- Movement is required when beyond the near limit and `field_7118` is clear,
  when beyond the limit with the extra one-square slack (word 1 at 0x85BC86),
  or when a sprite target fails LOS. LOS is on the caster's area with target
  position, caster position, visible terrain and `target->Orderable(FALSE)`.
  `MoveToObject` supplies the approach; DONE becomes INTERRUPTABLE and the item
  is released before return. Other move results are returned unchanged.
- On a facing mismatch, CMessageSetDirection is sent, the item is released and
  NORMAL is returned without setting `field_7118`. Once facing matches (and on
  later calls with `field_7118` already set), the original still sends another
  CMessageSetDirection and then sets `field_7118 = 1`.
- The cast counter is initialized from -1 to 0 with `m_bStartedCasting = TRUE`.
  On a zero action count with any other counter, started-casting is false but
  the counter itself is not reset. Before the use delay or with started false,
  the item is released and INTERRUPTABLE returned.
- The delay is normally `2 * 100 / 10 = 20` action ticks. Item type 9 or 0x47
  changes the multiplier to zero. These are the raw type tests at
  0x746C18/0x746C29; the types are not guessed from item names.

### Usability, visibility and the second selection (0x746C74-0x746F52)

- `CheckItemUsable == 2` enters `CRuleTables::CheckUseMagicDevice`. Success
  sends FEEDBACK_USEMAGICDEVICESUCCEEDED (0x42); failure sends 0x41, builds a
  piercing-damage backfire with flags bit 1 set and jumps directly to the
  charge tail.
- The backfire differs from UseItemPoint: its die count is
  `max(1, GetMaxEffectSpellLevel())`, **not twice that value**. The original
  requests the level for the comparison, again when positive, and once more
  for the raw spell-level BYTE, so this port does not collapse those calls.
  Six-sided dice, bonus type 0, raw level and final zero are passed in that
  order to 0x585380.
- ForceVisible is queued only when the caller is invisible and target id differs
  from its own. Self-use therefore preserves plain invisibility. Sanctuary is
  dispelled for either target. Both decoded effects have duration type 1.
- After those dispels, the original selects the action's item **again**. Empty
  string1 releases the old item first. Named selection releases it only after
  a match. Empty-string reselect releases a new item whose ability is absent;
  the named reselect error at 0x746F4C does not. These asymmetric release and
  error paths are retained.

### Projectile and effects (0x746F52-0x74725C)

- The projectile comes from the selected ability's missile word, receives the
  item resref and spell level zero. Each item effect receives source position,
  source id and the target object's **direct `m_pos`** fields before
  IcewindMisc::sub_5860F0 applies damage modifiers.
- Case 1 sets flags bit 1 and queues CMessageAddEffect without deleting it.
  Case 2 transfers it to the projectile. Cases 3..8 apply to party, everyone,
  party-excluded, the caster's specific, the target's specific, or everyone
  except the caster, respectively. Case 7 therefore uses the target's specific
  rather than UseItemPoint's delete-only quirk. Those non-transferred effects
  and the default are deleted with their virtual destructor.
- CMessageFireProjectile carries the decoded projectile type, target id,
  target's direct position, height, caster id as both message ids, and final
  zero. Direct Fire repeats DetermineHeight and uses the same target id/point.
  The member is cleared after Fire; ownership stays with the projectile system.
- Projectile type 0x130 alone calls `rand() % 1000000`; its remainder is written
  to both `CProjectileWhirlwind::m_wanderSeed` at +0x356 and the fire message's
  +0x20. There is no other direct rand call in this handler. UMD and downstream
  effects retain their own callees' rolls in their original order.

### Charge and common finish (0x74725C-0x7473B1)

- Both success and UMD backfire spend one usage with the original's WORD
  truncation, then release the item. `removeAbility` computes
  `(usageFlags == 1) & CheckIfUsedUp(slot, ability)`: the bitwise AND is
  deliberate, so CheckIfUsedUp, item removal and Unusable always run even when
  the flag comparison is false.
- A positive maximum creates a default CAbilityId, then changes item type to 2,
  item slot and ability to the cached values. CheckQuickLists receives it, -1,
  the removal flag and FALSE. Selected-character portrait equality triggers
  the button-array update, including the original's possible -1 == -1 case.
  AutoPause(0x40) and ACTION_DONE finish both success and backfire.
