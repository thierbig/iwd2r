# 0x583E60 CLUAConsole::ResolveCommand

Resolves the console's command word: stores the raw word into the member
at +0x4, matches its encoding against the fifteen known command words and
leaves the dispatch id in field_0 (or -1 plus the unknown-word report on a
miss). 635 bytes (0x583E60-0x5840DA); new method declaration on the
CLUAConsole class in src/CLUAConsole.h, body in src/CLUAConsole.cpp; ported
in commit (see report).

## Naming

Ghidra labels it `Get_CLUAConsole_Command_ID`, after the id it leaves in
field_0; the tree names it after the whole action — resolving the entered
word to a command — `ResolveCommand`.

## Body

SEH prologue, esi = this. The word is stored first: `lea ecx,[esi+4]`,
`lea eax,[esp+0x18]` (the parameter) and operator=(const CString&)
0x7FCD07 at 0x583E89. A stack copy of the parameter (copy ctor 0x7FC98F at
0x583E9A) is passed through the scrambler 0x5844E0 at 0x583EA6 — with
`mov ecx,esi` (the console) as ecx, which that free function ignores — and
the encoded result lands in a local via a second 0x7FCD07 call at
0x583EB5; the copy is destructed (0x7FCC1A at 0x583EC3).

Then the chain: from 0x583ED2 on, each arm loads the local's data pointer,
calls strcmp (0x7E7A54, cdecl, `add esp,8`) against a baked literal, and
on equality stores the id into [esi] and jumps to the shared tail
0x5840B8. Literal addresses and ids, in chain order: FIRSTAID 0x8AF644 ->
0xC, HANS 0x8AF650 -> 0xD, MIDAS 0x8AF658 -> 0xE, ADDGOLD 0x8AF660 ->
0x10, ADDSPELL 0x8AF668 -> 0x11, CHECKVAR 0x8AF674 -> 0x12, CREATEITEM
0x8AF680 -> 0x15, ENABLECHEATKEYS 0x8AF690 -> 0x18, EXPLOREAREA 0x8AF6A0
-> 0x19, MOVETOAREA 0x8AF6AC -> 0x1A, SETCURRENTXP 0x8AF6B8 -> 0x1C,
SETGLOBAL 0x8AF6C8 -> 0x1D, SETCHAPTER 0x8AF6D4 -> 0x25, JEFFKATTACKS
0x8AF6E0 -> 0x26, JEFFKDEFENDS 0x8AF6F0 -> 0x27. The literals are the
encoded forms (0x8AF644 = 9C A2 B4 B6 B8 92 A2 98; 0x8AF650 = A0 92 AC
B6; 0x8AF6F0 = A4 9A 9C 9C A6 98 9A 9C 9A AC 98 B6), i.e. the same
doubling transform the exe applies to the entered word, precomputed.

The full miss at 0x5840AB leaves field_0 = -1 (0xFFFFFFFF) and calls
CommandNotFound (0x584320) at 0x5840B3 with ecx = the console. The shared
tail 0x5840B8 destructs the local, restores fs:[0] and returns; eax is not
set on the hit path, so there is no return value — the id is read back
from field_0.

The tree spells each arm as `sEncoded == EncodeCommandWord("WORD")`:
the doubling map (ch+8)*2 is injective over the ASCII letter range, so
comparing encoded(entered) against encoded(literal) is exactly a plain
word comparison, and re-encoding the plain literal at run time equals the
baked bytes the exe compares against (the encoder cases in
tests/test_cluaconsole.cpp pin the transform, including the FIRSTAID
vector the exe stores at 0x8AF644).

## ecx / calling convention

thiscall: ecx is the console (the dispatcher's this); reads/writes
this+0x0, writes this+0x4, hands ecx unchanged to the two member callees.
One by-value CString parameter, callee-cleaned by `ret 4` at 0x5840D8.

## Callers

In the exe: the unported dispatcher 0x5838A0 (its word-split arm) — no
tree call site yet, by design (the dispatcher stays unported,
docs/followups.md). No TODO references this address.

## Test

Resolver cases in tests/test_cluaconsole.cpp [clua] call it on a stack
console: SETGLOBAL -> field_0 = 0x1D with the raw word kept in field_4,
CREATEITEM -> 0x15, JEFFKDEFENDS -> 0x27. The miss arm prints (live world
screen) and is pinned by the listing only.
