## Notes

Ported from the Ghidra listing and the disassembly (0x7543B0-0x75486B, `__thiscall` with one
argument, the target sprite, `ret 4`), called from `CGameSprite::ExecuteAction` for actions 137
(StartDialog) and 198 (StartDialogNoSet) at 0x72A374-0x72A39B: the dispatcher takes the target with
`GetTargetShareType(CGameObject::TYPE_SPRITE)` (the byte at 0x84C507), calls 0x7543B0 and jumps to
the shared release (0x72A059).

The handler is `Dialog` without the distance/LOS/walk logic:

- guards: a NULL target, the actor not `CanSpeak(FALSE, FALSE)`, the target not
  `CanSpeak(FALSE, TRUE)`, or the actor's `m_derivedStats.m_generalState & STATE_CHARMED` all answer
  ACTION_ERROR (0x7543CB-0x754410);
- when the action is not STARTDIALOGUENOSET, the actor's `m_dialog` (+0x56DC) is set from the
  action's `GetString1()` through `CResRef::operator=(const CString&)` (0x78ACC0): the action's
  dialog resource. For 198 the actor's current dialog is kept (0x754416-0x754466);
- both sides' `m_lTalkedTo` take the other's AI type (vtable +0x10 `GetAIType`, CAIObjectType::Set
  at 0x40B6E0; 0x754466-0x75448B);
- `m_actionCount == 0` plays the dialog sound on the actor itself (0x75448C, the same call as
  `Dialog`'s);
- the multiplayer permission (`SendDialogRequestToServer(FALSE)`) runs when the session is open: a
  pending request answers ACTION_NORMAL, 0 or NOT_PERMITTED answers ACTION_ERROR
  (0x7544A0-0x7544E5);
- `CScreenWorld::StartDialog(pTarget, this, FALSE, FALSE)` opens it — note the argument order: the
  *target* is the world's `pCharacter` argument and the actor is the dialog owner (`pTarget->m_dialog`
  inside 0x68EA00), which is the same order `Dialog` uses; a FALSE answer is ACTION_ERROR
  (0x7544E7-0x754504);
- the four messages of `DialogStarted` (0x24031): CMessageClearDialogActions for the target,
  CMessageSetNumTimesTalkedTo for the actor and (when the target is not a party member) for the
  target, both guarded by the actor not being charmed (0x2000) and each side's
  `AIType.m_nEnemyAlly != EA_PC` (the byte at 0x847C35), and the two SAID (TRIGGER.IDS 7)
  CMessageSetTriggers;
- ACTION_DONE (0x8485C4) is returned.

The decompile inlines `DialogStarted`; the port calls the existing helper (the same source the other
two dialog handlers use, "NOTE: Inlined in Dialog and PlayerDialog"). In the decompile the CString
temporary of `GetString1()` and the return value share the [esp+0xC] slot, which is why it prints
`local_c8` both as the temporary and the return. Nothing draws `rand()`.

## Evidence

No oracle case: the handler needs the world screen's dialog UI, a populated area with a real DLG
resource and a party member. Proof is the Catch2 data test `sprite: StartDialog opens the actor's
dialog without walking to the target` (`tests/test_sprite_actions.cpp`, `[ai][data]`,
`IWD2_DATA`): Hedron (the actor, the dialog's owner) starts 10HEDRON with the party member (the
target) at any distance; the action's dialog lands in the actor's `m_dialog`, the world screen opens
it (the dialog panel's `field_54`, the talker), both sides remember the talk, the actor's
NumTimesTalkedTo goes to 1 (the party member's stays 0); StartDialogNoSet keeps the actor's dialog
even when the action names another resource; and a CHARMED actor answers ACTION_ERROR.
