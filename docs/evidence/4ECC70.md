# 0x4ECC70 CtrlAltDelete_AddSpell

Free function in the original's CtrlAltDelete.cpp, `__stdcall`-shaped
callee-cleaned `void AddSpell(CString sSpell, DWORD dwCount)` (`ret 8`),
1447 bytes (0x4ECC70-0x4ED216; the GetSpellType switch's jump table sits
at 0x4ED218). ecx (the console's this) is saved in esi at 0x4ECC8C and
forwarded to CtrlAltDelete_DisplayText 0x4EC1C0 (with the original esi
before the party walk reuses the register) and to every
CtrlAltDelete_AddSpellClass call; none of them reads it. Ported in commit
5830131d1.

## Body

A strcmp chain (0x7E7A54; literals verified in .data at 0x8ABD74
"ALL", 0x8ABD6C "BARD", 0x8ABD64 "CLERIC", 0x8ABD5C "DRUID",
0x8ABD54 "PALADIN", 0x8ABD4C "RANGER", 0x8ABD40 "SORCERER", 0x8ABD38
"WIZARD"). "ALL" walks the seven spellcaster indices
(GetSpellcasterClass 0x5CA730) into CtrlAltDelete_AddSpellClass; each
named class stages its byte id (2, 3, 4, 7, 8, 10, 11) and calls the
same helper. Otherwise the argument is a spell resref: a CResRef is
built from sSpell and looked up in the key table with type 1006
(CDimmKeyTable::FindKey 0x78B410, this = chitin+0x78E; missing prints
"Error File " + sSpell + " does not exist\n" through
CtrlAltDelete_DisplayText — literals 0x8ABD2C/0x8ABD18). On the found
path a second CResRef is built and given to a CSpell local through the
CResHelper construction chain (0x78A970/0x78A960/0x78AD40, vtable
0x8C5CF8) and SetResRef (0x4699F0) — spelled in-tree as `CSpell
cSpellFile; cSpellFile.SetResRef(cResRef, TRUE, TRUE);` (CreateCreature
precedence). The party walk guard's `add 0x3884` test at 0x4ECF98 is a
dead null-game artifact; the live test is the head node at game+0x388E,
then the m_group.m_memberList GetDeny/ReleaseDeny round trip as in
CAIGroup::GroupAction (0x404D00), retrying SHARED and DENIED; rc !=
SUCCESS advances without release.

Per member: nClass starts 0 and is set from the spell file's caster
type (CSpell::GetCasterType 0x54AD90, switch via dec/dec/sub-2): 1 → 11
(WIZARD), 2 → 3 (CLERIC), 4 → the sprite's own GetAIType().m_nClass
(vtable slot 0x10, +8); other values leave 0. Then the game's spell type
(CInfGame::GetSpellType 0x5CAAD0, byte, jump table at 0x4ED218): case 1
adds a known spell — GetSpellLevel 0x5CAC30 with (cResRef, nClass, 0),
and only levels 0 through 8 (`cmp $0x9; jge` skips the add at
0x4ED0A5; level 9 is left out, as in the exe) through AddKnownSpell
0x724930 with (nClass, nLevel, cResRef, dwCount, dwCount, 0); case 2
AddInnateSpell 0x724B10 (cResRef, dwCount, dwCount, 0); case 3 AddSong
0x724B70 (cResRef, dwCount, dwCount, 0); case 4 AddShapeshift 0x724BD0
(cResRef, 0), sub_724C40 (dwCount) and
m_shapeshifts.sub_725D30(dwCount, FALSE) (0x724C40/0x725D30; push order
verified: a1 dwCount by reference, a2 FALSE staged byte). Type 0 and
types above 4 add nothing but still release the sprite.

## Callers

Wired: the console dispatcher CLUAConsole::Execute 0x5838A0 arm 4
(ADDSPELL) — nArgs 2 passes (field_24.GetAt(0), field_10.GetAt(0)),
nArgs 1 passes (field_24.GetAt(0), 10), the 0xA default staged before
the token in the exe; any other count is -2 + CommandNotFound. See
docs/evidence/5838A0.md.

## Test

Not driven directly: every arm needs a live party and the game's spell
lists. The dispatcher arm itself is exercised by
tests/test_cluaconsole.cpp [clua] for the observable edges (wrong
argument count → -2 + CommandNotFound); the add paths route through the
object array and CSpell loads, which the suite does not build.
