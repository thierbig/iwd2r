# 0x5009C0 CMessageSpellHitEffectSecondaryProjectile::MarshalMessage

`void MarshalMessage(BYTE** pData, DWORD* dwSize)` -- the class's own marshal (vtable 0x84D4F4 slot 0x10), not the base `CMessage::MarshalMessage` 0x4051A0. It computes a 35-byte payload (0x23, stored at 0x500A86) and writes it at `*pData`:

| offset | bytes | value |
|---|---|---|
| 0x00 | PLAYER_ID | target's `m_remotePlayerID` (+0x62) |
| 0x04 | LONG | target's `m_remoteObjectID` (+0x66) |
| 0x08 | WORD | `m_projectileType` (+0xC) |
| 0x0A | PLAYER_ID | projectile target's remote player id |
| 0x0E | LONG | projectile target's remote object id |
| 0x12 | LONG | `m_projectileTarget.x` (+0x12) |
| 0x16 | LONG | `m_projectileTarget.y` (+0x16) |
| 0x1A | LONG | `m_height` (+0x1A) |
| 0x1E | int | `field_20` (+0x20) |
| 0x22 | BYTE | `field_1E` (+0x1E) |

The target share's failure at 0x500A42 writes 0 to `*dwSize` and returns; the projectile-target share's failure is represented on the wire as (0, INVALID_INDEX), the sentinel Unmarshal accepts. The 3-byte header is not written here: the message handler allocates the header and passes `buffer + SPEC_MSG_HEADER_LENGTH` as `pData`, which is why `*dwSize` is 35 while the receive-side total is 38.
