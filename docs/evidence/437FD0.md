# 0x437FD0 CBaldurMessage::OnLeaveAreaLuaAnnounce

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x437FD0` and the Ghidra decompile
below; Ghidra names the function `FUN_00437fd0`.

## Identity and calling convention

Member of CBaldurMessage in the original's Baldur/CMessage.cpp, dispatched
by 0x4EE020's `LEAVEAREALUA` (X = 88) `/` `A` (65) arm (0x4F4639-0x4F4649).
`__thiscall`, `ret 0xc`: `(INT nMsgFrom, BYTE* pByteMessage, DWORD dwSize)`,
the standard three-argument handler form.

## Body

The guard is one condition: a connected session **and** `m_bIsHost` false,
else FALSE (0x437Fxx-0x43818A). A client then fetches the announcer's name
(and discards it -- the announce expects no reply) and decodes the payload
after the 3-byte header:

    {DWORD remotePlayerID; DWORD remoteObjectID; LONG x; LONG y;
     SHORT direction; BYTE parchmentLen; char parchment[];
     BYTE areaNameLen; char areaName[]}

The remote pair is resolved through CGameRemoteObjectArray::Find, an
unresolved one becoming CGameObjectArray::INVALID_INDEX, and the decoded
arguments are handed to `CInfGame::LeaveAreaLUA(nCharacterId, x, y,
direction, sAreaName, sParchment)` -- the same call, in the same order, as
the permit-reply handler 0x437950 makes on its granted path. The handler
returns TRUE after the call.
