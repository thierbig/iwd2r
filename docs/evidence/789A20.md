# 0x789A20 CResFile::GetCachingRequirement

Member of CResourceManagerBIFEntry in the original's ChDimm.cpp (our
CResFile), `__thiscall` `DWORD GetCachingRequirement()`, 699 bytes
(0x789A20-0x789CDB), ret 0.
Ported in commit 75276865d.

## Body

Resolves `this` BIF's file name through the resource cache (`pResCache =
&g_pChitin->cDimm.cResCache`, asserted non-NULL and initialized — the
first DWORD of CResCache), then bails out with 0 when the BIF is already
referenced by an open resource (`m_nRefCount > 0`). Calls
GetGameBaseFolder (0x7E9BF7, left as TODO) and bails when that fails; the
buffer it fills is never read, so the port keeps only the failure gate —
with the TODO in place the port cannot observe the gate and documents it.
Dead stores (a copy of `cResCache.m_sDirName` and a re-copy of the KEY
file-name entry into locals that are never read) are omitted with a NOTE.

`GetResFileName(m_nIndex, sResFileName, nDrive, TRUE)` maps the KEY index
to a file name and drive: bit 0 (hd0, local hard disk) or bit 0x200
(configured data directory) means the file is already local — return 0.
Only CD drives (2/4/8/16 = cd0..cd3) proceed. `lAliases.ResolveFileName`
maps the CD path to the local install; open failure returns 0. The open
file's first 12 bytes are then probed: a `BIFCV1.0` signature (case
insensitive) makes the cache requirement the uncompressed size stored at
header+8, every other file is measured with GetLength.
