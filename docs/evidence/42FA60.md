## Notes

The client's handler of PLAYERCHAR/100, the reply to a slot demand. It needs
an open session (`GetSessionOpen`), then reads `{SHORT slot; BOOLEAN
hasCharacter}` from `pMessage + CNetwork::SPEC_MSG_HEADER_LENGTH` (the DWORD
3 at 0x85E670).

**hasCharacter:** the body is `DemandCharacterSlotReply`'s payload (0x42F750)
- `{SHORT slot; BOOLEAN; CSavedGamePartyCreature; creatureData; DWORD
nCustomBio; bio}`. The party creature's `m_creatureOffset` is made
`pMessage`-relative (+3), a `CGameSprite` is built from that data with the
test suite's ctor arguments (`new CGameSprite(data, size, 0, 0, -1, 0, 0,
INT_MAX, CPoint(-1,-1), 0)`), its resref is set from
`m_creatureResRef`, the portrait is enabled, `Unmarshal(partyCreature, TRUE,
FALSE)` applies the party fields, and the sprite goes into the slot. The host
signals `CHARSTATUS_SIGNAL_IMPORTED` (11, 0x84D5A8). A custom bio (the DWORD
at `6 + sizeof(CSavedGamePartyCreature) + m_creatureSize`) becomes a TLK user
entry: fetch the existing one, remove it, set `strRes.szText`, add the user
entry. `m_bInOnObjectAdd` (this+0) is set around the ctor/unmarshal so the
object-add handler does not react to the reconstruction.

**No character:** `ClearCharacterSlot(slot)`; a **client** whose multiplayer
settings hold `CHARSTATUS_CHARACTER` (1, 0x84D5A3) demands the character from
the host (`DemandCharacterSlot(slot, FALSE, (BYTE)m_nHostPlayer)` - the exe
reads a byte at +0x10E0); a **host** signals `CHARSTATUS_SIGNAL_DELETED`
(12, 0x84D5A9, both `bLocalMessage`/`bFlush` TRUE).

**Return:** TRUE after either branch, FALSE for a closed session or a failed
sprite allocation (the exe's `operator_new(0x9D16)` NULL path).

`tests/test_ui_misc.cpp` ("msg: the demand-slot reply answers a closed
session and clears an empty slot", `[uimisc][msg][data]`) runs the no-character
branch on the engine: closed session FALSE; a client clears the empty slot
and demands nobody; the host clears it and signals the deletion. The sprite
path needs a real marshalled block and is read-only here. **It bites**: with
the stub 2 of the 5 assertions fail.

Two tree notes: `CGameSprite::SetResRef` in our tree takes a `CResRef` while
the exe's takes the `CString` (0x78ACC0 assignment); the port converts through
`CResRef(sResRef)`, the same copy. The exe also has an `STR_RES` local whose
`CSound` part is constructed at the top (0x7A8BB0) - that is our `strRes`.
