# 0x6FB630 CGameSprite::AIUpdateFly

## Disassembly reading

`__thiscall` with no arguments. The body runs only while
`m_fCurrCircleChange` (`+0x5334`) is below `m_fCircleChange` (`+0x532C`)
(0x6FB63E-0x6FB650), computes
`fCurrCircleChange = min(m_fCircleChange, m_fCurrCircleChange + 1.0)`
(0x6FB656-0x6FB69D), then:

- when `m_circleFacing` (`+0x533E`) is nonzero, `movsx` at 0x6FB6E4
  sign-extends it for the angle:
  `fAngle = GetMoveScale() * signedSide * fCurrCircleChange / radius +
  m_fDirectionOffset` (0x6FB6AB-0x6FB72F). It writes
  `m_pos.x = m_posOld.x + trunc(cos(fAngle) * radius)` and
  `m_pos.y = m_posOld.y - trunc(sin(fAngle) * radius * 3 / 4)`
  (0x6FB733-0x6FB7AD, through CRT 0x7E7EB4/0x7E7E04/0x7E812C). The direction
  compare at 0x6FB7A0 sign-extends the side and compares it with `FLY_LEFT`
  (1 at 0x85C09E): left adds 4 to `GetDirection`, every other side adds 12
  (0x6FB7DE-0x6FB8D5).
- when the side is zero, the straight branch switches on `m_nDirection`
  (0, 4, 8, 12) and moves `m_pos` by
  `radius * fCurrCircleChange / m_fCircleChange`, with the 3/4 factor on y
  (0x6FB8DA-0x6FB9DB).

Finally `m_fCurrCircleChange` advances by 1.0 (0x6FB9DE-0x6FBA00) and calls
`SetSequence(7)` (READY) if it reaches `m_fCircleChange`
(0x6FBA19-0x6FBA1D).

The side must be signed: `FLY_RIGHT` is 0xFF, and the original's 0x6FB6E4
`movsx` feeds the angle. An unsigned read makes the arc's angular rate 255
instead of -1.

## Notes

Ours sign-extends `m_circleFacing` once into a SHORT local before the nonzero
branch's angle and `FLY_LEFT` test. The data test sets up the action through
`SetTargetFly` for both `FLY_LEFT` and `FLY_RIGHT`, then drives one
`AIUpdateFly` tick: the left and right x coordinates must straddle the start
point and sum symmetrically, which separates -1 from 255. It tests our engine
only, not original-process parity.
