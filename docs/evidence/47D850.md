## Notes

- m_drawPoly (0x8D0) ages first, always: the sign-extended SHORT is
  compared unsigned against the delta, so a negative timer keeps
  decaying and a younger one clamps to zero.
- Only a delta above 0x84EC10 (108,000, one day) on a ground pile
  (m_containerType 4) reaches the walk. Both early returns are TRUE.
- The walk drops a NULL node without a delete, keeps an item whose
  file flags have bit 0 (critical) and clears the return flag, and
  removes and deletes every other item. An emptied pile runs
  RefreshRenderPile, sets m_bDeleteMe (0x863) and returns FALSE.
- A bag item (type 0x3A) ages its store first. With no session the
  bag's local store (type 4) is walked: a critical line goes out as a
  CMessageContainerAddItem whose item carries only the resref, the
  three use counts, the wear and the flags (slot 0x7FFF), every pass
  takes one off a line through RemoveItemExt(resref, flags, -1, 1)
  and the store is marshaled back to m_sTempDir. The bound is
  m_lInventory's count ([store+0xFC]), re-read each pass, so an
  emptied line makes the walk skip the next one.
- In a session the host demands the master copy
  (DemandServerStore(resref, TRUE)) and releases it after; the
  client re-demands a stale copy (m_bLocalCopy 0x12C clear or the
  version at 0x124 not "STORV9.0") with DemandResourceFromServer(1014)
  and otherwise posts a CMessageStoreDemand, then a
  CMessageStoreRelease. Each line posts a CMessageStoreRemoveItem
  that names the bag's resref twice (store and item), index i, count
  1 and the bag item's flags; a critical line also posts the full
  item copy. The client invalidates its copy after the walk.
- A failed demand closes the session and skips the item, tail
  included. The original jumps to 0x47DF45, past the walk-position
  store at 0x47DF41, so its next RemoveAt reuses the bag's POSITION;
  the port keeps the position right (noted in the source).
