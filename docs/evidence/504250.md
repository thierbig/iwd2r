# 0x504250 CMessageRemoveItem::Run

Read against the vanilla disassembly at `0x504250-0x50462F`, after action
223 was found to construct this class (vtable `0x848C04`).

The original repeatedly takes an asynchronous deny on `m_targetId` while
SHARED or DENIED. On SUCCESS and a TYPE_SPRITE target it:

- takes `m_equipment.m_items[m_slot]`; if present, calls
  `CGameSprite::Unequip(m_slot)` (call site `0x5042F5`, body `0x71B7A0`), re-reads the slot and hands
  that item to `CInfGame::AddDisposableItem`, clears the slot, and, when that
  slot was the selected weapon, calls `EquipMostDamagingMelee`;
- queues `CMessageSpriteEquipment(pSprite, pSprite->GetId(),
  pSprite->GetId())`, whether or not an item was found, through the
  three-argument `AddMessage(message, FALSE, message->GetCommType())`
  (0x4F7530; the two-argument wrapper 0x4F7500 is not the original call),
  and invokes the active engine's `UpdatePersonalItemStatus(m_targetId)`;
- for slots 43 through 50, clears the corresponding quick weapon and its
  ammunition-index byte through the two inlined SetQuickWeapon overloads;
  otherwise, for slots 15 through 17, clears the corresponding quick item;
- calls `sub_726F20` when `(m_slot - SLOT_WEAPON) / 2 == m_nWeaponSet`
  (signed division, truncating toward zero);
- updates the button array when the world screen's selected portrait is the
  target's portrait, then releases the deny lock. A non-sprite is also
  released without any of those effects.

The port uses the existing helper methods for the inlined button writes; the
original asserts are those helpers' ObjCreature.h lines 2030-2032. The
focused action 223 test drains the queued removals with AsynchronousUpdate
and checks that every occupied non-fist slot is cleared while the fist is
untouched. No oracle or emulator comparison was run.
