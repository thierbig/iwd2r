## Port

The fork's body carries seven divergences this port fixes against the
disassembly:

- Invented entry guards `m_pSprite == NULL` and `pTarget == NULL` —
  dropped; the only entry test is the inlined IsEmpty on the resref.
- `FindNearbyPassablePoint(&spawnGrid, ...)` — renamed to the in-tree
  `CSearchBitmap::GetNearestOpenSquare` (src/CSearchBitmap.h, // 0x548B80
  in src/CSearchBitmap.cpp); the exe's out-param-first six-argument shape
  (ret 0x18) is spelled as the in-tree CPoint return. CSearchBitmap is
  outside this batch's files, so the call uses the in-tree signature and
  the shape difference is recorded here.
- Invented `pCreatureData == NULL || creatureSize == 0` early-out —
  dropped; the exe goes straight from the resref chain to `new`. The
  exe's plain-new null path (je 0x55FD16) is modeled the way the in-tree
  sibling models it (CGameSprite.cpp SpawnCreature): a `pSpawned == NULL`
  return right after SetResRef/ReleaseData.
- CGameSprite ctor arguments — the fork passes the type third, a WORD -1
  fourth and `spawnPos`/`-1` at the end; the exe pushes data, size, 0,
  type (2 GOOD / 0 EVIL), 0xffffffff expiration, 0, 0, 0x7fffffff
  timeOfDayVisible, CPoint(-1,-1), 0 facing. Position comes later through
  AddToArea, exactly as the sibling does.
- `m_baseStats.m_flags |= CREATURE_FLAG_SUMMONED` — sprite+0x5BC is
  m_baseStats(+0x5A4) + 0x18 = `m_generalState` (FileFormat.h), and the
  constant is in-tree as STATE_SUMMONED_CREATURE 0x10000000
  (src/CDerivedStats.h).
- `SetAIType(type, TRUE, TRUE)` — the exe's virtual call passes FALSE,
  FALSE; and the missing `m_liveTypeAI.Set(type)` copy to sprite+0x3DFA
  (src/CGameSprite.h) is restored.
- A do-while GetDeny retry loop with an `rc != SUCCESS` bail and
  `reinterpret_cast<CGameObject**>(&pSpawned)` — invented; the exe calls
  GetDeny once, ignores the result and reads neither the return nor the
  out object (the code already holds pSpawned). The missing
  CMessageAddSummonLink post is restored: the class is staged in
  src/CMessage.h with only the ctor and the two LONG members (vtable
  0x84D360, 0x14 bytes; the network overrides 0x512310/0x5124D0/0x5125A0
  are omitted per the single-player ADR, like CMessage89/CMessage96),
  and the ctor is defined out-of-line in src/CMessage.cpp marked as
  inlined here.

The fork's `IsGoodByEA`/`AddSummoned` helper names become the in-tree
`IcewindMisc::sub_585310` / `Icewind586B70::sub_586D60`; `GetAnimation()`
becomes the sibling's `m_animation.m_animation` member spelling with the
two UTIL_ASSERTs the exe emits at ObjAnimation.h lines 2093 and 2086.

## Disassembly checks

- The ctor decode above was read push-by-push from a clean dump (two
  misreads of this site in earlier rounds were settled by it): the GOOD
  branch of the 0x585310 test pushes 0x2 as the type argument, the other
  branch ebp (0); expiration is 0xffffffff as a DWORD and the CPoint is
  (-1,-1), not spawnPos.
- 0x548B80 verified five exits `ret 0x18` — six stack arguments with the
  POINT* out slot pushed last (first parameter); GRID_SQUARE_SIZEX/Y are
  the ds:0x84D6A0/0x84D6A1 bytes (src/CPathSearch.h).
- The GetDeny site: one call, `pSpawned->m_id` sampled before it, no
  compare on al afterwards, no loop back edge — contrast with the
  sibling SpawnCreature in CGameSprite.cpp, which does test the result.
- The message ctor's four stores were read at the new 0x14 site: caller
  (+0x4), target (+0x8), m_summonedId (+0xC) all the spawned sprite's id,
  +0x10 the caster's — matching CMessageAddSummonLink's member layout
  (CMessage base +0x4/+0x8, LONGs at +0xC/+0x10 = 0x14 bytes total).
- vtable 0x84D360 read out of the image: +0x10 Marshal 0x512310,
  +0x14 Unmarshal 0x5124D0, +0x18 Run 0x5125A0, all CMessage overrides;
  the staged class inherits the fully-defined CMessage vtable and adds
  none, so only the ctor needs a definition for the link.
- SetAIType slot +0xBC, GetAIType +0x10, GetPos +0x1C, AddToArea +0x8,
  GetTerrainTable +0xA0 on the sprite vtable; +0x5C GetPersonalSpace and
  +0x3C GetListType on the animation-type object (src/CGameAnimationType.h)
  — all present in the in-tree headers.
