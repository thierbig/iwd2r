# 0x43F6D0 CProjectorSubtitles::CProjectorSubtitles

## What it is

The constructor EngineActivated's subtitle block (0x43EC20) runs per movie:
thiscall, `ret 8` = two stack args (`CProjectorSubtitlesLine* pLines`,
`int nWidth`). Initializes the overlay state, creates the subtitle surface in
`pVidMode->pSurfaces[8]`, builds the 4-band rect, and clears the surface with
a color-fill blt so the first line renders on a transparent-looking black band.

## Decode (annotate 0x43F6D0-0x43F8F5)

- Field init: `m_sText = ""` (default CString from [0x8C1758] then LPCSTR
  op= 0x7FCD57), `m_pLines = pLines` (arg1), `field_4 = 0`, `field_C = 0`,
  `m_rgbColor = 0xFFFFFF`.
- Surface descriptor at esp+0x14, zeroed by `rep stosd` of 0x1B dwords:
  `dwSize = 0x6C`, `dwFlags = 7` (CAPS|HEIGHT|WIDTH), `dwWidth = nWidth`
  (arg2), `dwHeight = g_pBaldurChitin->m_pEngineProjector->field_14A
  .GetFontHeight(1) * 4` (movsx then shl 2 - four subtitle bands).
- `ddpfPixelFormat.dwSize = 0x20` (+0x48) and `GetPixelFormat` called on
  `pSurfaces[CVIDINF_SURFACE_BACK]` - index 0: `mov edx,[ecx+0xa0]; mov
  eax,[edx]` where ecx = `g_pChitin->pActiveEngine->pVidMode` (chain +0x3C4
  pActiveEngine, +4 pVidMode, +0xA0 pSurfaces). The filled format is never
  read: dwFlags lacks DDSD_PIXELFORMAT. Kept faithful.
- Rect at this+0x14: `top = 0; left = 0; bottom = dwHeight; right = dwWidth`.
  Ported as `RECT rcRect` replacing field_14/18/1C/20 (same offsets).
- Caps: `DDSCAPS_OFFSCREENPLAIN|DDSCAPS_VIDEOMEMORY` (0x4040) iff
  `cVideo.m_nBpp == 0x10` (word at chitin+0x7EA) AND !`cVidBlitter
  .m_bSoftSrcKeyBlt` (+0x7F4, checked first) AND !`m_bSoftSrcKeyBltFast`
  (+0x7F2) AND !`m_bSoftMirrorBlt` (+0x7F6); else SYSTEMMEMORY (0x840).
- `cVideo.m_pDirectDraw2->CreateSurface(&desc, &pVidMode->pSurfaces[8], NULL)`;
  on failure dwCaps is rewritten to 0x840 only (descriptor not re-zeroed, the
  stale pixel-format fields ride along) and retried; second failure nulls
  `pSurfaces[8]`. Slot 8 is the subtitle surface - the same slot Unload
  (0x43F900) releases.
- Erase blt runs even when CreateSurface failed (pSurfaces[8] == NULL goes
  straight into Blt): `DDBLTFX fx { dwSize = 0x64, dwFillColor =
  pVidMode->ConvertToSurfaceRGB(0) }`, then a do/while of
  `cVidBlitter.Blt(pSurfaces[8], &rcRect, NULL, &rcRect, DDBLT_COLORFILL |
  DDBLT_WAIT, &fx)` + `pVidMode->CheckResults(hr)` retrying on
  DDERR_SURFACELOST (0x887601C2) / DDERR_WASSTILLDRAWING (0x8876021C). The
  same rect pointer is passed as BOTH dest and src rect with a NULL source
  surface - the original's shape, kept as-is.

## Tests

None added: the ctor needs a live CVidMode with a DirectDraw back surface, a
registered CVidFont (GetFontHeight) and the blitter - the test harness has no
video stack, and stubbing it would only re-test the stub. The EngineActivated
wiring sits behind `m_hBinkDLL != NULL` (binkw32 LoadLibrary), unreachable in
the sandbox.
