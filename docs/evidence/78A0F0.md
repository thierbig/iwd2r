# 0x78A0F0 CResFile::GetFileName

Member of CResourceManagerBIFEntry in the original's ChDimm.cpp (our
CResFile), `__thiscall` `BOOL GetFileName(CString& sResFileName)`, 398
bytes (0x78A0F0-0x78A27E), `ret 4`.
Ported in commit a3799f031.

## Body

Fails (FALSE) when the key table is uninitialized or `m_nIndex` is out
of range — an unsigned compare against `m_cKeyTable.m_nResFiles`
(0x78A13F). Otherwise copies the KEY file-name entry
(`m_pResFileNameEntries` + entry's `nFileNameOffset`, the rebased pool
pointer CDimm::CreateKeyTable builds) into a local and into a working
copy, then strips the path with a `Find('\\')` / `Right(len - pos - 1)`
loop (0x78A172-0x78A1C5) and the four-character extension with
`Left(len - 4)`, assigning the result to the out parameter and
returning TRUE. The failure arm leaves the out parameter untouched.

The original also constructs a third local CString that is never used
(initialized at 0x78A10E, destructed at 0x78A218); the port notes it
rather than spelling it, the same dead-store omission as 789CE0.
