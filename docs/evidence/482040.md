## Notes

- Type 0xD2 is the special case: it decodes the plain area projectile
  (0xD3) from the hit object itself and reports the type unoffset; every
  other type decodes through the spell-hit table and reports its type
  offset by 0x1000 in the CMessageFireProjectile.
- A failed projectile allocation still posts the message with the NULL
  projectile pointer (0x4820A3) before Fire is called on it; the
  original does not branch around either.
- The action return is the global ACTION_DONE word (0x482120), so the
  caller arm's forced done matches the callee's own answer.
