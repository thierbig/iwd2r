84g ported across three trigger codes, all in commit 0d0cdf4e. Register
roles as in the other arm batches: edi = this, esi = bResult, the decoded
CAITrigger copy at [esp+0x34], the CString temps sScope/sName/sString on

## Arm notes

- 0x40A5 is the one-string speller of the BitGlobal family: it splits
  its own "SCOPE:NAME" string after uppercasing the WHOLE string
  (Find ':', Left, Right), where the 84f GlobalTimer trio takes the
  scope pre-split from string2. Do not merge them. The missing-variable
  fallback answers the mask against zero only in a scope that was
  found; a scope naming no area answers FALSE outright.
- The OR/XOR blocks in 0x40A5 are dead: execution reaches them only
  after the int1==1 compare released FALSE, so mode 2 and 3 never run
  their tests. The port keeps them as code with comments saying so --
  an else-chain would have resurrected them.
- 0x40A8's write-0xFF happens on every path through a taken case,
  matched or not, which is what makes an equality match one-shot; class
  cannot be blocked by the 0xFF because its answer is the raw AND.
- The three NumCreatures codes share one arm; the port spells them one
  case body with the trigger id read back for the final, as the
  byte-adjacent trio rule asks. The vert-list variant pick is
  GetVertListType against the front-list constant, and a NULL
  vert-list position skips the search leaving the list empty -- both
  mirrored, since the unit harness drives exactly those paths.
