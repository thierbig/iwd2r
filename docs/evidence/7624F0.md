## Notes

- 0x76250F: the reserved type 0xD2 takes the `DecodeProjectile(0xD3, pHitObject, 0)` branch; every other type goes through `DecodeSpellHitProjectile(nType, pHitObject, FALSE)` and reports `nType + 0x1000` to the message ctor, whose own `+ 1` makes the real projectile type `nType + 0x1001`.
- The message ctor's seven arguments, in order, are the reported type, the target id (the action's third argument), the target point, the height, the caller id (this->m_id), the target id (this->m_id again), and 0; the ctor stores target at +4, source at +8.
- A failed `operator new` leaves EAX zero, and AddMessage still receives NULL (0x762592), as in the container sibling.
- Fire is called through slot 0x6C with `(m_pArea, m_id, targetId, ptTarget, nHeight, nType)`; the point is pushed by value (two dwords).
- The return is the global ACTION_DONE word at 0x8485C4 (`mov ax, word ptr [0x8485c4]`), not the action entry default.
- No RNG is read: every input is the action's stored destination/specifics plus the target object's own id, area and position, all pinned by the two tests.
