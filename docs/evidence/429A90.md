## Notes

The port is `CBaldurMessage::OnResourceDemanded` in `src/CMessage.cpp`. It keeps the host guard,
the `GetPlayerName`, the `{DWORD nType; name bytes}` parse, the four helper-backed cases
(1010 area, 1013 game, 1015 world map, 1014 store with `DemandServerStore`), the zeroed reply
`{BYTE nameLen; name; DWORD nType; DWORD nSize; data}` and the 82/82 guaranteed reply to the
requester. The default case keeps the original's `nSize = nType` quirk (0x42A064; the buffer is
zeroed, so it sends that many zero bytes). The four `CResHelper::SetResRef(cResRef, TRUE, TRUE)`
calls are the template methods (the asm shows them inlined); the four releases use
`ReleaseData()`, which `CGameFile`, `CStoreFile` and `CWorldMapFile` now declare as the one-line
`if (pRes) pRes->Release();` the folded 0x5C7B00 body implements (only `CAreaFile` had it before).
A missing resource leaves the helper empty, so the reply carries `nSize = 0`; the helper
destructors release the resource object at the end.

The new wire constant is `MSG_SUBTYPE_RESOURCE_DEMAND_REPLY = 82` (0x84CFB2), the subtype
`DemandResourceFromServer` polls for. It is adjacent to the sender's `MSG_SUBTYPE_RESOURCE_DEMAND`
and may be added by the in-flight demand-sender PR (T132) as well; a merge keeps one copy.

Proof is the unit test
`CBaldurMessage::OnResourceDemanded answers only the host and echoes an unknown type` in
`tests/test_network.cpp` (`[msg][network]`, no `IWD2_DATA`, 14 assertions), using the bare
`TestChitin` fixture: a closed session and a client answer FALSE with the static buffer untouched;
a host gets TRUE for an unknown type (1), which takes the default case, and the reply packet in
`CNetwork::STATIC_MESSAGE_BUFFER` is `0xFF, 82, 82` followed by the 14-byte payload
`{4, "TEST", 1, 1, 0}` (the echoed type as the size and the one zeroed data byte), pinning the
`nSize = nType` quirk. The four resource types themselves
need the game files and the CDimm, which no fixture builds, hence the read-only kind.
