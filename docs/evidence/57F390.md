# 0x57F390 CProjectile85133C::Fire

Type 312's four-bolt spread (vtable slot 0x6C, vtable 0x85133C). It
requires the source object to be present, builds four points around the
source-to-target line and throws one `CProjectileLightningBolt`
(`LightnT`) at each, copying this projectile's effects into every child.
No direct `call 0x57F390` exists in `.text`: the class is reached through
the vtable entry at 0x8513A8, and the row is otherwise spawned by
`CProjectile_DecodeProjectile`'s type-312 case.

## Semantics pinned

- **Guard.** `GetShare(source, THREAD_ASYNCH, &pSource, INFINITE)` must
  return `SUCCESS`; otherwise the body jumps straight to the epilogue
  (0x57F3DB -> 0x57F62B) and nothing is created or released.
- **Corner formula.** With `dx = targetPos.x - sourcePos.x`,
  `dy = targetPos.y - sourcePos.y` and
  `len = trunc(sqrt(dx*dx + dy*dy))` (0x7E8034 then 0x7E812C; no
  rounding constant), the four points are `targetPos` and
  `IcewindMisc::sub_5847B0(sourcePos, dx, -dy, len)`,
  `sub_5847B0(sourcePos, -dx, dy, len)`,
  `sub_5847B0(sourcePos, -dx, -dy, len)`: the target and the other three
  corners of the rectangle whose diagonal is source->target.
- **Child construction.** `operator_new(0x2E8)` then the inlined
  `CProjectileLightningBolt` ctor: base
  `CProjectileSingleTarget(CResRef("LightnT"))`, `m_beamRange = 400`,
  tracker ctor, vtable 0x8513BC, tracker owner = the bolt, strike
  interval 33, service period 2. The retune then makes `m_beamRange`
  300, tracker range 50, `m_speed` 20, `field_1D8` 16, visual effect
  armed, `m_bHasHeight` TRUE, `field_1C2` TRUE, `m_fireSoundRef`
  `TRA_09`. The 400 store is immediately overwritten by 300, exactly as
  the exe does.
- **Effect copying.** For every effect in `this->m_effectList`, call its
  virtual slot 0x4 (`Copy`) and hand the copy to the child's
  `CProjectile::AddEffect` 0x51EA90. The parent's list is untouched and
  keeps ownership of its own effects; each child owns its copies.
- **Launch.** Each child is fired through its own vtable slot 0x6C with
  `pArea = pSource->m_pArea`, `source = pSource->m_id`,
  `target = INVALID_INDEX`, `targetPos = points[i]`, `nHeight = 0`,
  `nType = 0`. The caller's `pArea`, `target`, `nHeight` and `nType`
  arguments are not forwarded.
- **Release.** The source share is released once, after the fourth
  launch (0x57F626), and only on the success path.

## Test

`tests/test_visual_projectiles.cpp`, "the type-312 Fire throws four bolts
at the rectangle corners": drives the missing-source failure branch, then
fires at a source-relative 30/40 target (distance exactly 50, so the
corner and 300-push arithmetic is exact). It pins child count 4 and their
order, each child's `LightnT` cell, beam range 300, tracker range 50 /
owner / service period 2 / strike interval 33, speed 20, `field_1D8` 16,
both flags, `TRA_09`, the source area/id and `INVALID_INDEX` target, and
the final target points: each corner pushed a further 300 along the
source->corner heading (7x the offset at distance 50), which is the
child `Fire`'s own 0x580B30 behaviour. It also pins one copied effect per
child (same id/amount, different object, child projectile type 0) and
that the parent keeps its own effect, plus distinct valid child ids and
zero rand draws.

Result (macOS, `macos-clang`, `IWD2_DATA=~/.local/share/iwd2r/game`):
104 assertions, all passed. The `[visualprojectile]` suite was also run;
the new case passes, while the pre-existing order-dependent Cloudkill and
