# 0x4608A0 CGameAIBase::CreateCreature

Member of CGameAIBase in the original's CGameAIBaseActions.cpp,
`__thiscall` `SHORT CreateCreature()`, 1,209 bytes (0x4608A0-0x460D59).
Ghidra's CGameSprite_B3AUTO_004608a0 name is wrong: the function reads
`this` as a CGameAIBase (m_curAction at 0x476, m_pArea, field_342) and
its only caller loads the CGameAIBase pointer into ecx.

Ported in two ranges, one commit each: 700063bb (0x4608A0-0x460B2A: the
(-1, -1) destination fallback, the key-table probe for the CRE, the
CCreatureFile read and the CGameSprite construction), 906da464
(0x460B2B-0x460D59: the resref fixups, the action 7 / action 228
placement split, the area add, the script name copy, the named-creatures
registration and field_342). The split is at the resref fixup block
0x460B2B, the first statement after the new-CGameSprite null check. The
caller arm is 60791965 (cases 7 and 228 of CGameAIBase::ExecuteAction,
0x44E231-0x44E23F: `returnValue = CreateCreature(); goto done;`).

## Callers

Exactly one, ported in 60791965: the shared case 7 and case 228 arm of
CGameAIBase::ExecuteAction. The exe's arm (`mov ecx, ebx; call
0x4608A0; mov esi, eax; jmp 0x4526F7`) routes the result through the
common done label, not the release tail, so both action ids run the
identical handler and only the action id inside it picks the placement
rule.

## Callees

No new callees: every call is in-tree — CProjectile::GetSourcePosition
(the (-1, -1) branch), CDimm key-table FindKey, the CCreatureFile
ctor/SetResRef/GetDataSize/GetData/GetResRef/ReleaseData/dtor family,
operator new, CGameSprite::CGameSprite, CGameSprite::SetResRef,
CGameAnimationType::GetPersonalSpace and GetListType,
CSearchBitmap::GetNearestOpenSquare, CGameAIBase::GetTerrainTable,
CGameSprite::AddToArea, CString/strcmp/memcpy traffic,
CVariable::SetName and the CVariableHash AddKey, and
CAIObjectType::Set. All were ported before this task.

## Notes

- Actions 7 and 228 share the body; the only difference is the
  placement: 228 snaps to the exact square containing the destination
  (plain grid division), 7 searches GetNearestOpenSquare around that
  square with the new sprite's personal space (from its animation) and
  the acting object's terrain table. Both re-multiply by the grid size
  before AddToArea.
- The sprite is built before either resref is corrected: the
  constructor sees the raw CRE, then SetResRef copies the file's own
  resref, and a second SetResRef immediately overwrites it with the
  action's first string. Both calls are kept because the first keeps
  the sprite consistent with the file it was built from.
- m_curAction.m_specificID is the facing, passed straight through to
  the CGameSprite constructor as a WORD. The constructor stores it
  masked with 0xF, but finishes with SetSequence(SEQ_HEAD_TURN)
  (0x707230), whose `m_nDirection & 0xFE` mask rounds any odd facing
  down to the next even direction before writing it back: a facing of
  13 lands as 12, while 6 survives. The test pins both.
- The script name from the second string is copied into the sprite's
  SCRIPTNAME (32 bytes, GetBuffer growing the CString to fit) whenever
  it is non-empty, and the sprite is then registered in the area's
  m_namedCreatures under GetScriptName with its object id in the
  variable's m_intValue — even an empty second string still registers
  the sprite under whatever script name the CRE left.
- field_342 (the CAIObjectType at 0x342) is Set to the new sprite's AI
  type, so the script that ran the action can address the creature it
  just made. The handler returns ACTION_DONE; only the missing-CRE and
  failed-allocation paths return ACTION_ERROR.
