# 0x4FB500 CMessageContainerItems::MarshalMessage

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x4FB500` and the Ghidra decompile
below; Ghidra names the function `FUN_004fb500`.

## Body

`__thiscall void MarshalMessage(BYTE** pData, DWORD* dwSize)`, 767 bytes,
`ret 8`. Share the target (retry SHARED/DENIED) for its remote pair and
release it; a failed share zeroes the size (0x4FB4B4). The size is
`0xC + sum over the non-null slots (0xD + resref length) + 2 per present
slot` (0x4FB50C-0x4FB5A0), then the header (pair, m_nItems, present count)
and the entries are written; each non-null slot writes its index, the
resref from pItem->cResRef, CItem::GetUsageCount 0..2, m_wear and m_flags.
The closing `UTIL_ASSERT(cnt == *dwSize)` is at 0x4FB7F4.

## Wire format

Payload (without the 3-byte SPEC_MSG_HEADER): the target's remote pair
(PLAYER_ID m_remotePlayerID, LONG m_remoteObjectID, or (0, 0xFFFFFFFF) when
the id does not resolve), then SHORT m_nItems (the container's slot count,
holes included) and SHORT the number of present items, then for each
present slot: SHORT slot index, a length-prefixed resref, the three
CItem::GetUsageCount values (SHORTs), the SHORT m_wear and the DWORD
m_flags. The unmarshal allocates the full slot array and leaves the holes
NULL; unlike its sibling pair, an unresolved target pair is not fatal (the
target becomes INVALID_INDEX and the body is still decoded, TRUE).

sparse-list shape are covered. An unresolved remote pair is decoded (not
