## Notes

CGameSprite's vtable 0x85BDD4, slot 0x84 (0x728F80's case 19, the dispatcher range 0x72958D-0x72959D: `call 0x750F10`, store the SHORT result). Returned in AX; the early exits are ACTION_ERROR (the WORD at 0x8485CA) and ACTION_DONE (0x8485D4).

The guard: `CInfGame::GetCharacterPortraitNum` (0x5AF4E0) with the sprite id (+0x5C). Anything but -1 (already in the party) is ACTION_ERROR.

`CInfGame::AddCharacterToParty(id, -1)` (0x5BD070) returns TRUE with the portrait slot added and m_nCharacters incremented; FALSE means the party is full (six) or the id is already there, and the original branches to the overflow path. Note the exe stores the BOOL in a byte and tests it with `cmp al, 0`, so FALSE is the overflow path. `CInfGame::AddCharacterToOverflow(id)` (0x5C2250) returning FALSE is a plain ACTION_DONE (the creature is neither in the party nor the overflow).

Normal join (0x750F60-0x7513C3), in the original's order: `ClearActions(FALSE)` (vtable 0x6C), `DropPath` (0x6FF2F0), field_722A = the world timer's m_gameTime, m_baseStats.m_fatigue = 0, m_baseStats.m_reputation = 100, `CMessagePartyGold` (0x12 bytes, vtable 0x848C20) with (TRUE, TRUE, the creature's m_gold, id, id) added as a synchronous message (CMessageHandler::AddMessage 0x4F7500, the 0 second argument), m_baseStats.m_gold = 0 and m_derivedStats.m_nGold = 0, m_cGameStats.m_strStrongestKillName = -1 only when it is still 0, `CGameStatsSprite::RecordJoinParty` (0x4CB000), `CMessageChangeDirection` (0xE bytes, vtable 0x84C3C4) face 1, and the area's m_nCharacters incremented (BYTE at area +0x1ED; 0xFF becomes 1).

Overflow join (0x7513C3-0x751590) skips all of the above: no gold message, no reputation, no area count, no change-direction; only the shared tail.

Shared tail of both paths: ClearActions(FALSE), DropPath, field_722A, m_baseStats.m_fatigue = 0; m_nEnemyAlly = CAIOBJECTTYPE_EA_PC (2, the byte at 0x847C35) on m_typeAI, m_liveTypeAI and m_startTypeAI; the six script slots through the virtual `SetScript` (vtable 0x94): 1..5 empty (`new CAIScript()` = operator_new(0x28) + CAIScript::CAIScript 0x78A960 + the CTypedPtrList member's ctor, the 25-byte template instantiation FUN_005F9A80), slot 3 on the normal path instead `new CAIScript()` then `CAIScript::Read(CResRef("DEFAULT"), TRUE)` (0x40F160, 0x8ABDEC), slot 6 `DPLAYER3` (0x8B3AA8) when m_baseStats.m_flags has 0x800, else `DPLAYER2` (0x8B8A10).

The join dialog: `CInfGame` +0x8B0 is `m_ruleTables.m_tPostDialog` (the C2DArray at CRuleTables +0x8B0), `C2DArray::GetAt` (0x403340) with the row `CRuleTables::JOIN_DIALOG_FILE` ("JOIN_DIALOG_FILE", 0x8ADB98) and the column `CString(m_scriptName)` (the sprite's +0x554, CAIObjectType's 32-byte SCRIPTNAME via CString_Construct 0x7FCC88). When the result compares equal to the table's default (`C2DArray::GetDefault` 0x403530), the dialog becomes "multig" (0x8B863C). Under the oracle/single-player the connection is never established, so the `CMessageSetDialogResRef` (0x14 bytes, vtable 0x84C430) is dead; it is ported anyway.

The join trigger: `CAITrigger(CAITRIGGER_JOINS, m_typeAI, 0)` (0x420D10, CAITRIGGER_JOINS is 4), sent as `CMessageSetTrigger` (0x62 bytes, vtable 0x847BB8) to each of the m_nCharacters party members with the portrait ids from `m_characterPortraits[0..5]` (CInfGame +0x382E) as targets, source and actor the sprite id, all synchronous.
