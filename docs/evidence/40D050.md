# 0x40D050 CAIObjectType::sub_40D050

`CGameObject* CAIObjectType::sub_40D050(CGameAIBase* caller, BYTE type,
BOOL checkBackList) const`, 154 bytes (0x40D050-0x40D0E9, ret 0xC), in
tree since 797ec008 (`// 0x40D050` in src/CAIObjectType.cpp) as the
typed cause resolver the trigger arms use; the LOS arm (0x4013, commit
0793bc4a) resolves through it with (this, TYPE_AIBASE, FALSE), the byte
TYPE_AIBASE loaded from 0x84C501 at the arm's call site (0x45461B).

## What it does

Delegates to sub_40D0F0 (the instance walk and NOONE test) with the
caller and the back-list flag -- eax holds checkBackList and edx the
caller from the entry reads (0x40D050/0x40D054), pushed around the
saved esi at 0x40D059/0x40D05A. A NULL answer returns unchanged
(test esi,esi; je 0x40D0E4 at 0x40D062): NOONE, or a share that never
succeeds, skips the type gate entirely. Commit 441558d7 restored this
check -- the earlier port ran straight into the vtable call and
dereferenced NULL; the 84d LOS test is the first caller to reach the
path, so the defect surfaced as a test SIGSEGV only then.

The gate asks the object's type through vtable slot +4 (0x40D06A) and
compares it against the type byte read back off the stack at 0x40D06D
(arg 2, one past the saved esi and the return address). Equal types
pass to the second gate (0x40D0A9); so do TYPE_NONE (test cl,cl at
0x40D07A) and TYPE_AIBASE requests (cmp cl,1 at 0x40D075). The second
gate re-asks the type for a TYPE_AIBASE request (0x40D0B2) and requires
the AIBASE bit (test al,1 at 0x40D0B5). Every mismatch releases the
share (CGameObjectArray::ReleaseShare 0x599E70 at 0x40D09E / 0x40D0D9,
id field +0x5C, THREAD byte 0x851873, INFINITE) and answers NULL
(0x40D0A3 / 0x40D0DE); the pass path returns the shared object as-is
(0x40D0E4).
