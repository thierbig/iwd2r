# 0x50C550 CMessageSpriteUpdate::MarshalMessage

## Identity

`CMessageSpriteUpdate` (subtype 57, getter 0x4F62F0) vtable **0x84D034**:
slot 0x10 = 0x50C550 MarshalMessage, slot 0x14 = 0x50D290 UnmarshalMessage
(the already-ported decoder), slot 0x18 = 0x50D6F0 Run. The survey's row 105
had the Marshal and Unmarshal halves swapped; see 50D290.md.

The function is **3,386 bytes** (0x50C550-0x50D28A: returns at 0x50C5EA for a
failed target share, 0x50CAA3 for "no groups", 0x50D284 for a normal end).
Ghidra has no function here (vtable-only reference), so it is missing from
`functions.tsv`/`callgraph.tsv`; I created it in a project clone
(DisassembleCommand over 0x50C550-0x50D290, CreateFunctionCmd, DecompileInterface)
and worked from that decompile plus the annotated listing.

## What it encodes

A differential encoder against **`CGameSpriteLastUpdate`**, the sprite's
last-sent shadow at CGameSprite+0x7432 (0xFC bytes; modelled in
src/CGameSprite.h, layout evidence in 7432.md). The 12-byte record is the
target's remote id pair (read from a share of `m_targetId`; a failed share
reports `*dwSize = 0`) and the field-group mask. Groups are then written in
the exact order the decoder reads:

| mask | group | size |
|---|---|---|
| 0x400 | area-name length byte + bytes | len + 1 |
| 0x100 | sequence (WORD) | 2 |
| 0x2 | position (2 LONGs) | 8 |
| 0x200 | facing (WORD) | 2 |
| 0x4 | general state (DWORD) | 4 |
| 0x8000 | 256 spell states | 0x20 |
| 0x10000 | 64 base skills, 64 skills, field_106 | 0x81 |
| 0x1000 | fade speed | 1 |
| 0x4000 | translucency | 1 |
| 0x2000 | 32 visual effects (DWORD) | 4 |
| 0x8 | hit points + max hit points | 4 |
| 0x800 | base-stat flags | 4 |
| 0x10 | field_64..field_6A + four AC mods | 0x10 |
| 0x40 | enemy/ally, live, start, moral failure | 4 |
| 0x80 | level-up byte + HP/CON bonus (DWORD) | 5 |
| 0x20 | portrait icon count + LONG ids | 2 + 4n |
| 0x1 | path count + LONGs + curr path + dest + move scale | 4n + 0xD |

then the trailing `field_85` byte (the receiver's hide-animation flag, set
from `GetBaseStats()->field_294` only on the differential path), total
`0xC + groups + 1`, asserted at or below STATICBUFFERSIZE (the compare is
`jbe`, line 0x5B08 = 23304; the `pData`/`dwSize` assert is line 0x59A4 =
22948).

Differential rules (all kept verbatim): a changed path (count/array,
destination or move scale) forces mask 0x303 (path+position+facing+sequence);
a changed sequence to **10** (SEQ_WALK) does the same; position/facing are
not compared when the sequence is 10; the area group is also set whenever
*another* group changed (it gives the receiver the context). The shadow is
updated for every group the encoder sends (path/portrait arrays reallocated),
**the area name included**: after writing the area group the encoder stores
the message's `m_sAreaString` in the shadow (0x50CC94: `push &this->m_sAreaString`,
`lea ecx,[pSprite+0x7476]`, `CString::operator=`), so the next comparison
matches and an unchanged sprite writes nothing at all. A shadow flagged
`m_bFullUpdateRequired` sends all groups (mask 0xFFFFFFFF), clears the flag
and skips the differential path altogether (so `field_85` keeps the
constructor's value), and it stores the area name too.

## Notes

The area-name store at 0x50CC94-0x50CCA2 is a review correction: an earlier
reading of the decompile had the encoder assigning the name to itself.
Adding it makes the zero-size path (`*dwSize = 0` when the computed mask is
zero) reachable, and it is what the tests below pin: a second marshal of an
unchanged sprite returns size 0, while the area-only packet appears only
after the shadow has been cleared (Initialize on an area move) and then
stores the name again.

One original oddity kept: the encoder overwrites the message's portrait-icon
list without freeing the previous one (message +0x76), and frees it once it
has been copied to the shadow.

## Tests

`tests/test_message_sprite_update.cpp`: `sprite update: MarshalMessage
round-trips a full update through UnmarshalMessage` (every group decoded
back, mask 0xFFFFFFFF, shadow flag cleared and its area name stored, a
second marshal returning size 0, the area-only packet after the shadow is
cleared and the empty marshal after it), `sprite update: MarshalMessage sends only
the changed field group and the area`, and `sprite update: MarshalMessage
zeroes the size for an unknown target`. No oracle case or replay: the send
path is dormant in the single-player build; the tests call the encoder
directly.
