# 0x481C50 CGameContainer::CountItemExcept

Member of CGameContainer in the original's GameContainer.cpp, `__thiscall`
`SHORT CountItemExcept(CString sItem)`, 211 bytes (0x481C50-0x481D23).
Ported in commit 0ce83562.

## Body

Walks the item list from the head: a NULL entry breaks the walk
(0x481C83) and returns the count so far. An entry whose resref equals the
parameter adds nothing; any other entry adds `GetUsageCount(0)` when the
item stacks (max stackable > 1), `GetNumberOfItemsInBag(pItem->GetResRef(),
CString(""))` when the item type is 0x3A (the bag type), and 1 otherwise.

## Callers

Not in tree: all six call sites (0x458C83, 0x458E63, 0x459043, 0x4595C5,
0x459745, 0x4598C0) are container arms of the EvaluateStatusTrigger
function at 0x453840, which our tree has not ported. No TODO was placed —
the callers do not exist to carry one.

## Test

Driven directly in tests/test_ai.cpp [ai][data] (ExecuteAction 233/235/
278/... case): a fresh container holds a 3-charge 00POTN01 stack and a
single 00GEM01; `CountItemExcept("00POTN01")` is 1 (the gem) and
`CountItemExcept("00GEM01")` is 3 (the stack's charges). The fresh
container is required because the exe's walk stops at the first NULL
slot, which the 278 drop test leaves behind on the area container.
