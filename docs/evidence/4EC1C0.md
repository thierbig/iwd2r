# 0x4EC1C0 CtrlAltDelete_DisplayText

The first of the debug console's "CtrlAltDelete:" cheat-command handlers,
`__cdecl`-style free function consuming one CString by value (`ret 4`:
0x4EC1C0 pushes nothing, the callee pops the argument), 132 bytes
(0x4EC1C0-0x4EC243). ecx, the dispatcher's this, is not read: the body
goes straight to the globals. Ported in commit (see report).

## Body

Builds an empty CString (the global empty CString at 0x8C5CF8 is the
source at 0x7FC98F's copy-ctor call), loads the DWORD at 0x84C960 (-1 at
rest) into a register, then calls `CScreenWorld::DisplayText`
(0x692460) on the screen world from g_pBaldurChitin+0x1C88 (inlined;
the port spells the accessor `g_pBaldurChitin->GetScreenWorld()`) with
(name = empty, text = the argument, lMarker = the loaded marker,
bMoveToTop = FALSE). The tree's other DisplayText callers pass the -1
literal for that marker (CScreenWorld 0x6893E8 at CScreenWorld.cpp:1206),
which is how the port spells it.

## ecx / calling convention

The dispatcher passes its own this in ecx; every instruction of this
body ignores it. `ret 4` pops the by-value CString argument. The port is
therefore a free function taking `CString sText` by value.

## Callers

In-tree: CtrlAltDelete_MoveToArea (0x4EC250) and
CtrlAltDelete_CreateCreature (0x4EC390) error paths. Not in tree: the
dispatcher 0x5838A0 (deliberately unported; docs/followups.md).

## Test

None: displaying text requires a live world screen with its text
display controls, which no unit test drives; the forward is verified
against the listing above instead.
