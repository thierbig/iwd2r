# 0x4FAE00 CMessageContainerAddItem::MarshalMessage

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x4FAE00` and the Ghidra decompile
below; Ghidra names the function `FUN_004fae00`.

## Body

`__thiscall void MarshalMessage(BYTE** pData, DWORD* dwSize)`, 602 bytes,
`ret 8`. Share the target (retry SHARED/DENIED), take its remote pair
(+0x62/+0x66) and release it; a failed share sets `*dwSize = 0` and writes
nothing (0x4FB05C). The item's resref is copied and upper-cased by
CResRef::CopyToString into a CString, its length becomes the wire length
byte, the size is `0x18 + length` (asserted against STATICBUFFERSIZE), then
the body is written and the closing `UTIL_ASSERT(cnt == *dwSize)` checks it
(0x4FAE??-0x4FB059). The usage counts go through CItem::GetUsageCount (not
the raw m_useCount members).
## Wire format

Payload (without the 3-byte SPEC_MSG_HEADER): the target's remote pair
(PLAYER_ID m_remotePlayerID, LONG m_remoteObjectID; (0, 0xFFFFFFFF) when the
id does not resolve), then:

- +0x08 SHORT m_slotNum, +0x0A BYTE m_bCompressContainer, +0x0B the resref
  length and the resref bytes from +0x0C, then three SHORT usage counts
  (GetUsageCount 0..2), the SHORT m_wear and the DWORD m_flags. Total
  0x18 + resref length. The unmarshal reconstructs the CItem from the resref
  and those five fields and rejects the message when the remote pair does not
  resolve.
