# 0x7B1F70 CVidTile::Render (dual-tile overload)

## What it is

The dual-tile tile-blit dispatcher: thiscall on the CVidTile, `ret 0x1C` =
seven stack args: `Render(LPDIRECTDRAWSURFACE pSurface, INT x, INT y,
const CRect& rClip, CResTile* pResDualTile, BYTE nDitherSeed, DWORD
dwFlags)`. 865 bytes (0x7B1F70-0x7B22C5). Same shape as the plain Render
0x7B1780 but both this tile's and the dual tile's data are demanded and
clipped in lockstep, and the bpp switch dispatches to the dual-tile
blitters. Sole caller: CInfTileSet::RenderToPrimary 0x5CB260's unknown-
tile-code fallback (assert at 0x5CB415, call at 0x5CB42B-0x5CB474).

## Port

`src/CVidImage.cpp` `CVidTile::Render` (dual overload), declaration in
`src/CVidImage.h` after the stencil Render. The 24-bpp (0x7CE3D0) and
32-bpp (0x7CE930) arms were TODOs returning FALSE until this task wired
them to their ports; the Lock-fail and unknown-bpp single-release quirks
are kept and commented.

## Callers wired

CInfTileSet::RenderToPrimary 0x5CB260 (src/CInfinity.cpp), the
unknown-tile-code default arm: the exe asserts FALSE (0x5CB415) and then
falls back to SetRes / SetAddColor / this Render with the tile's
m_pDualTileRes, a zero offset pair and dither seed from the caller's
sixth arg, jumping to the BltFogOWar tail (0x5CB479) so the per-case
stencil/plain Render below is skipped. Previously a UTIL_ASSERT(FALSE) +
break placeholder; now the fallback is ported under the assert.

## Tests
