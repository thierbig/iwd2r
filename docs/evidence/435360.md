## Notes

The port is `CBaldurMessage::SendMapWorldCancelRequestToServer` in `src/CMessage.cpp`, with the
two new wire constants `MSG_TYPE_MAPWORLD` (109, 0x84CF8B) and
`MSG_SUBTYPE_MAPWORLD_CANCEL_REQUEST` (99, 0x84CF8D) in `CMessage.h`/`CMessage.cpp`. It matches
the disassembly: the same three guards, the inlined host-name lookup, the empty-name check, and the
empty guaranteed specific message to the host; the return is TRUE when the packet is handed to
`SendSpecificMessage`, as the original ignores that call's BOOLEAN.

Proof is the unit test
`CBaldurMessage::SendMapWorldCancelRequestToServer sends the MapWorld cancel packet`
in `tests/test_network.cpp` (`[msg][network]`, no `IWD2_DATA`): a bare `CChitin` (the file's
existing `ChitinScope`) gives a real `cNetwork`; the test drives the three guards (closed session,
hosting, no host name) and then, with `m_nServiceProvider` set to a non-null value,
`m_bConnectionEstablished` true and a host name, reads the packet out of the public static
`CNetwork::STATIC_MESSAGE_BUFFER`: `[0] = 0xFF` (SPEC_MSG_FLAG_ENABLED), `[1] = 109`,
`[2] = 99`, and `[3]` untouched because the payload size is 0. That window exists because
`SendSpecificMessage` marshals the packet before `SendMessage_` returns FALSE in this
DirectPlay-less port (src/CNetwork.cpp:2508-2567); with the null provider it returns before the
buffer is written, which the test also pins by clearing the buffer first.
