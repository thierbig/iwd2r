# 0x5842C0 CLUAConsole::AddTextArg

Files one parsed text argument: appends the string to the console's token
store (the CStringArray at +0x24) and bumps the token counter field_C.
96 bytes (0x5842C0-0x58431F); new method declaration on the CLUAConsole
class in src/CLUAConsole.h, body in src/CLUAConsole.cpp; ported in commit
(see report).

## Naming

Not named by any string; the body identifies it. It takes a text argument
and adds it to the store, so `AddTextArg` — the string counterpart of the
value-table append inlined in ParseArgs (0x5840E0).

## Body

SEH prologue, esi = this. The index comes straight from the array header —
`mov eax,[esi+0x2C]` (0x5842D8), the CArray m_nSize inside the member at
+0x24 — and is passed with the parameter's address (`lea edx,[esp+0x14]`,
0x5842DE) to CStringArray::SetAtGrow (0x7FBB6A at 0x5842EC, ecx =
this+0x24): growing at the current size is an append. The store at
0x5842E4 (old [esp+0xC]) is the SEH trylevel, not a local. Then field_C is
incremented through [esi+0xC] (0x5842F1-0x5842F9), the trylevel returns to
-1 (0x5842FC), the parameter is destructed (CString dtor 0x7FCC1A at
0x584304) and `ret 4` at 0x584318 drops it.

The tree spells the index as field_24.GetSize() — the same m_nSize read
the exe inlines.

## ecx / calling convention

thiscall: ecx is the console (handed through from ParseArgs, which gets it
from the dispatcher); reads this+0x2C, writes this+0x24 (through the array
call) and this+0xC. One by-value CString parameter, callee-cleaned by
`ret 4`.

## Callers

In tree: `CLUAConsole::ParseArgs` (0x5840E0, ported after this one) files
each quoted token through it. In the exe: that call (0x58423B) is the only
reference. No TODO references this address.
