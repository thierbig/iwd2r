## Port

One source-level definition per class, each identical to the already
imported `CMessageWeaponImmumityUpdate::GetCommType` (same label, same
body): `return BROADCAST_OTHERS;`. The exe's single folded body is what
all four classes share at runtime; source-level duplication is what the
original source must have carried for the linker to fold. Our tree keeps
the Weapon definition (previous batch) and adds the three missing copies
so each class's vtable slot resolves to the same code.

## Disassembly checks

- The body is a WORD (SHORT) load — matches `SHORT GetCommType()`
  returning a table constant, not a byte.
- 3 = BROADCAST_OTHERS (1 = SEND at 0x848208, 2 = the 0x453510 body's
  value at 0x84820A, 3 here, 4 = BROADCAST_FORCED at 0x84820E via
  0x43E170, 5 = BROADCAST_FORCED_OTHERS at 0x848210 via 0x4536E0).
- The fork labels this address over bodies reading both
  `BROADCAST_OTHERS` and `CMessage::SEND`; the exe byte at 0x84820C is
  3, so the copies import as BROADCAST_OTHERS — the fork's
  `return CMessage::SEND;` body (carried on the trailing-VFX class) is
  not kept (exe wins), and the header's trailing-VFX comment now reads
  "returns BROADCAST_OTHERS (3)" instead of the stale "returns SEND (3)".
- vtable slot 1 of each new class's vtable points here (dwords decoded
  above), so defining these copies is required for the classes'
  vtables to link.
