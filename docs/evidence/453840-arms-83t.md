# 0x453840 CGameAIBase::EvaluateStatusTrigger, Task 83t arms

The dispatcher itself is 453840.md; this file records the eight small arms
Task 83t ported, in commits 51b63e8c (0x401E, 0x4068, 0x4069, 0x40B3) and
111089f6 (0x4095, 0x4096, 0x40D5, 0x40F5). Register roles as in the other
arm batches: edi = this (mov edi, ecx at 0x453869) and ebx = 0 (NULL),
esi = bResult, the decoded CAITrigger copy at [esp+0x34], pSprite/pObject
at [esp+0x10], pObject2 at [esp+0x18], bNoRelease at [esp+0x28]. Five of
the eight arms end in a shared compare tail that jumps `0x45AD4C`, the
release tail whose `mov eax, esi` hands esi to the caller raw; the two
sprite-resolving arms can instead leave through the early epilogue
0x45AB7A (null sprite, nothing shared, returns FALSE), and the two
cause-resolving arms leave through 0x45AB39 (bResult zeroed, then the
release tail) when nothing resolves.

## Notes

- The Time trio is a shared-load family: all three load GetObjectGame ->
  GetWorldTimer -> GetCurrentHour into ebx zero-extended (`xor ebx,ebx;
  mov bl,al; and ebx,0xff`) and call GetSpecifics. Only the compare
  differs: 0x401E answers equality through the sub/neg/sbb/inc sequence
  (1 iff the difference is zero), 0x4068 and 0x4069 compare the operands
  directly (setg, setl). Per the task's instruction the case says so in a
  comment rather than sharing a helper the exe does not have. None of the
  three resolves an object; all end `jmp 0x45AD4C` with nothing acquired.
- The Level pair is likewise shared up to its tail: both call the
  GetTriggerSprite virtual, save its flag and `je 0x45AB7A` on a null
  sprite (early epilogue, FALSE, nothing released -- the port's
  `return FALSE`), then push 0xFFF, call GetDerivedStats (a trivial
  getter, so ecx = the sprite carries through it), GetClassMaskLevel,
  `mov esi,eax` and jump the compare tail -- 0x459A21 for 0x4095
  (GetSpecifics; cmp esi,eax; setg) and 0x456AA3 for 0x4096 (mov esi,eax;
  GetSpecifics; cmp; setl). The compares are signed, so the port reads
  the level as a LONG.
- 0x40B3 resolves its sprite the same way (null -> 0x45AB7A) but never
  reads it: the sprite exists only so the release tail releases it. The
  answer is Icewind586B70::Instance()->GetCount() > specifics through the
  setg tail 0x4569DD (mov esi,eax; GetSpecifics; cmp esi,eax; setg).
- 0x40D5 and 0x40F5 follow the 0x40D7 shape: Decode, GetCause, resolve
  (sub_40CB20 with TYPE_SPRITE for 0x40D5, sub_40CCA0 for 0x40F5), store
  to [esp+0x18] (pObject2) and `je 0x45AB39` on null -- bResult zeroed,
  then the release tail, which the port renders as the if around a bResult
  that is already FALSE. 0x40D5 answers sub_453170's raw return (m_bHiding
  at +0x7240, no boolean normalization); 0x40F5 reads the resolved
  object's base stats flags (`mov esi,[eax+8]; shr esi,0xD; and esi,1`)
  -- bit 0x2000, the flag action 283 SetCriticalPathObject sets and
  clears. NOTE: 0x40F5 does not type-check its object; whatever
  sub_40CCA0 returns is read as a sprite, and the port keeps that.
- Tests (f635b867): 23 assertions, run alone under IWD2_DATA with the
  light harness (AddAIObject, MakeSprite, no NewGame) of the
  Dead/IsActive case. The world timer's m_gameTime is pinned to five
  hours and restored; the level sprite gets m_classMask = 1 and
  m_nClassLevels[0] = 5; the summon registry's entries are saved, pinned
  to one occupied slot (Entry(1,1)) and restored; m_bHiding and the base
  stats flags are set and restored around their CHECKs; every
  object-resolving trigger is also driven with CAIObjectType::NOONE to
  pin its null path.
