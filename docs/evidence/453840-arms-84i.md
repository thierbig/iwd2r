## Arm notes

- GetVisualRange's in-tree body is `return m_pArea->m_visibility.field_E
  * 32;` -- it dereferences the CALLER's area BEFORE the range compare
  (0x454E55), so even the "far target skips LOS" else needs a non-NULL
  caller area. The unit test seats a zeroed CGameArea: field_E zero gives
  range zero, any far distance then skips the LOS block and the same-area
  test alone answers FALSE.
- 0x4074 hardcodes seeInvisible TRUE on both search calls
  (0x454C51/0x454C53), exactly as 0x407D (Task 84h) does -- the trigger
  sees invisible creatures the script resolver sub_40CED0 would hide
  behind GetCanSeeInvisible.
- 0x4074's last-seen shortcut breaks TRUE with NO bookkeeping
  (0x454ED7): no m_canBeSeen tick, no message -- only a fresh object
  (Equal fails) records and posts.
- The two 0x4074 messages differ in payload: the instance path posts the
  FOUND object's GetAIType, the no-instance path posts the DECODED cause
  (the search spec). Both use type CAITRIGGER_SEE 0x401C -- 0x407D's
  message used the literal word 0 instead.
- 0x4092's scale is theta * 180 * pi rather than 180 / pi (the exe
  multiplies by 360, divides by 2, then MULTIPLIES by the truncated
  3.1415926535): the cone the compare against 30.0 admits is roughly 3
  degrees where the intended degrees conversion would admit 30. A unit
  bug, ported verbatim.
- 0x4092's final compare succeeds on NaN as well (the fnstsw/test ah,1
  form after fcomp 30.0 takes the unordered path as success); the port
  spells it `!(scaled < 30.0) && scaled == scaled` -> FALSE. The two
  guards are the other way around: strictly-greater only (test ah,0x41),
  so equality and NaN continue into the math.
- The TRUE tail at 0x457A85 that 0x4090 (Task 84h) jumps to lies INSIDE
  this arm's range; this batch owns the bytes it lands in (the
  0x4075-into-0x407D precedent 84b recorded and 84h repeated). 0x4092
  itself returns directly everywhere -- it holds nothing past the
  position capture, so it shares no release sequence.
