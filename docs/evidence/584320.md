# 0x584320 CLUAConsole::CommandNotFound

The console's shared error reporter: prints one of three texts keyed on the
command id at +0x0 and always leaves the id at -1. 213 bytes
(0x584320-0x5843F4); new method declaration on the CLUAConsole class in
src/CLUAConsole.h, body in src/CLUAConsole.cpp; ported in commit (see
report).

## Naming

Ghidra labels it `Command_Not_Found`; the tree keeps the semantics but the
house spelling `CommandNotFound`, since it is the reporter for more than
the unknown-word case (its -2 and -3 arms serve the argument-count and
unknown-id failures, not just unknown words).

## Body

SEH prologue, then a three-way compare chain on [this+0x0] (0x584344-0x58435B):

- -3 (0x5843B5): constructs the CString at 0x8AF718 — "I don't know how you
  go here, try again!" (the "go" typo is shipped) — into the outgoing
  argument slot via the LPCSTR ctor 0x7FCC88.
- -2 (0x5843A7): same construction from 0x8AF744 — "Wrong Parameters :
  Check the parameter list.  Strings must be in quotes.  Make sure to
  enclose parameters in () and seperate parameters with a comma." (149
  bytes, 0x8AF744-0x8AF7D9; double spaces after "list." and "quotes." and
  the "seperate" typo are shipped).
- -1 (0x58435D): the outgoing argument slot is initialized empty from the
  global empty CString at 0x8C1758, then filled with the prefix at 0x8AF7DC —
  "Command not found : " (trailing space) — via CString::operator=(LPCSTR)
  (0x7FCD57, Ghidra CString_operator_equ); GetCommandWord (0x584400, ecx =
  the console) runs at 0x584372, operator+= (0x7FCFE6, Ghidra
  CString_operator_plus_equ) appends the word, and the copy ctor (0x7FC98F)
  lands the result in the argument slot.
- any other id (0x5843CE): nothing is printed.

The -2/-3/-1 arms all land at 0x5843C6: `lea ecx,[esi+0x38]` and the call
to CtrlAltDelete_DisplayText (0x4EC1C0), which receives &this+0x38 as its
ecx and never reads it. Every path then stores -1 at [this+0x0]
(0x5843D2) before the plain `ret` (caller-cleaned).

## ecx / calling convention

thiscall: ecx is the console (the dispatcher's this). Reads this+0x0,
calls GetCommandWord with ecx = this, hands &this+0x38 to the print path.
No arguments, plain `ret`.

## Callers

In the exe: the resolver 0x583E60's unknown-word path (this run's
ResolveCommand), CountArgs' unknown-id arm 7 (0x584493), ParseArgs' parse
failures (0x58427C), and the dispatcher 0x5838A0's wrong-count and default
arms (0x583DCB, 0x583DC5) — the first three are ported in this run and
call the tree method; the dispatcher stays unported (docs/followups.md).

## Test

No dedicated case: two of the three arms and the concatenation print
through a live world screen (CtrlAltDelete_DisplayText), which the test
harness does not have. The print-free default arm (any id outside
{-3,-2,-1}) and the unconditional field_0 = -1 store are the observable
print-free behaviour; the listing facts above (arm addresses, literal
addresses, the store at 0x5843D2) are verified against the disassembly.
