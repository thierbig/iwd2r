# 0x439250 CBaldurMessage::OnLeaveAreaNameAnnounce

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x439250` and the Ghidra decompile
below; Ghidra names the function `FUN_00439250`.

## Identity and calling convention

Member of CBaldurMessage in the original's Baldur/CMessage.cpp, dispatched
by 0x4EE020's `LEAVEAREANAME` (x = 120) `/` `A` (65) arm
(0x4F46B6-0x4F46C8). `__thiscall`, `ret 0xc`: `(INT nMsgFrom, BYTE*
pByteMessage, DWORD dwSize)`, the standard three-argument handler form.

## Body

One guard: a connected session **and** `m_bIsHost` false, else FALSE. A
client then fetches the announcer's name (discarded -- no reply is sent)
and decodes the payload after the 3-byte header:

    {DWORD remotePlayerID; DWORD remoteObjectID;      ; the character
     DWORD remoteTriggerPlayerID; DWORD remoteTriggerObjectID;
     BYTE areaNameLen; char areaName[]}

Both remote pairs are resolved through CGameRemoteObjectArray::Find, each
miss becoming CGameObjectArray::INVALID_INDEX, and the decoded arguments
are handed to `CInfGame::sub_5C4AD0(nCharacterId, nTriggerId, sAreaName)`
-- the same party-transition function the party-required region path calls
(src/CInfGame.cpp). The handler returns TRUE after the call.
