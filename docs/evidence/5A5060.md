## Notes

**Convention** (MSVC fastcall, `ret 8`):
`BOOL(ECX = BYTE** ppCreature, EDX = LONG* plSize, stack1 = BYTE* pOldCreature, stack2 = void* pUnused)`
— the caller passes `&oldSize` in pUnused; the function never reads it.
Returns TRUE. `*plSize` is **read-only**: read at 0x5a5c15 (allocation),
0x5a67ef (assert), 0x5a6844 (copy-out); no store anywhere. The prologue's
`pOld = pOldCreature ? pOldCreature : *ppCreature` fallback covers the
caller's no-realloc path (delta == -0x240, dead in practice).

**Raw V2.1 file offsets are literal exe constants** (documented in the
port's view structs at src/CInfGame.cpp:11785-11811): flat list pointer
dword @0x3BA / count @0x3BE (stride 0xC: resref[8], SHORT spellLevel,
SHORT type); header pointer @0x3C2 / count @0x3C6 (stride 0x10: SHORT
level, SHORT field_2, SHORT field_4, SHORT type, LONG startIndex, LONG
count); pool pointer @0x3CA (stride 0xC: resref[8], BYTE flags, BYTE[3]).
The type constant **2** (song/shapeshift/innate) is a `.rdata` byte at
0x85BB63, read from the exe and ported as a literal with a comment.

**Dual class-byte normalization, ported exactly**: the prologue rewrites
`pOld[0x387] == 0 || == 0xFF` (raw byte compare, so 0xFF is not -1
sign-extended) to CAIOBJECTTYPE_C_FIGHTER (5) **in the old buffer**; the
build phase later re-checks the same byte and this time normalizes to
CAIOBJECTTYPE_C_BARD (2) — dead after the prologue already rewrote it,
an exe artifact, ported as written. Only then does `offsets->m_class`
read it. The caster switch {C_BARD, C_CLERIC, C_DRUID, C_PALADIN,
C_RANGER, C_SORCERER, C_WIZARD} gates GetSpellcasterIndex; any other
class leaves nClassIndex 0.

**Loop 1** asserts `spellLevel >= 0 && < 9` per entry (InfGame.cpp:5905,
house idiom `// __FILE__:` + `// __LINE__: 5905`). type==2 searches the
game tables in order **m_songs → m_shapeshifts → m_innateSpells**
(sprite-adjacent globals at +0x4C08/+0x4C10/+0x4C00 on the game object);
a hit lands in the matching extra via the 4-arg `Add(nID, 1, 1, 0)`,
unconditional. type≠2 searches m_spells; a hit lands in
`spells.Get(nClassIndex)` via the 5-arg Add at the entry's own level.
Every miss runs the obsolete arm: a 9-byte NUL-terminated resref buffer,
`CString(" ").Format("*** OBSOLETE SPELL FILE: %s", buffer)` — the
result is discarded; the port keeps the construction because the exe
performs it.

**Loop 2** gates every Add behind a Find (unlike loop 1): type==2 needs
the table hit **and** `Find(nID, &nIndex)` on that extra list before
`Add(nID, 1, flag, 0)`; type≠2 needs the m_spells hit and
`Find(nID, level, &nIndex)` on the class grouped list before its 5-arg
Add — and then, **regardless of that Find**, runs `Find` on domainSpells
at the same level to gate a domain Add. That domain arm is dead code in
the exe (domainSpells starts empty this call and only the dead arm could
fill it) — ported exactly, flagged untestable.

**Flag computation**: `nFlags = pKnown->m_flags & 1` — the asm is
test/branch (`(flag & 1) ? 1 : 0`), not an and-instruction; same value.

**nOldSpellBytes** (the V2.1 spell bytes the tail skips): the asm
accumulates flatCount×0xC at 0x5a553d-0x5a554d (`lea eax,[eax+eax*2];
shl eax,2` — no imul anywhere), per-header `m_count`×0xC at
0x5a5a91-0x5a5aae, and headerCount×0x10 once at 0x5a5acc-0x5a5ae1. The
port spells it `nCount * 0xC` + `0x10 + m_count*0xC` per header —
algebraically identical. **Sizing** walks all 63 grouped + 9 domain + 3
extra lists (`count*0x10 + 8` each; the +8 is the trailing
field_14/field_18 pair); `nDelta = nTotalBytes - nOldSpellBytes`.
Decoupling worth knowing: nSpellOffset's end value is
`0x62E + nTotalBytes` — independent of nOldSpellBytes, which only moves
the tail (via nDelta) and sets the tail's source offset. So assert 6423
(`(nSpellOffset + nLastBlockSize) == *plSize`, InfGame.cpp:6423)
validates the caller's precomputed size even when nOldSpellBytes is
wrong — a wrong value displaces the three tail slots without failing
the assert. The unit test was pinned against the asm's formula
(flatCount×0xC + Σm_count×0xC + headerCount×0x10).

**Build phase**: `new BYTE[*plSize]`, zero-filled (which makes the exe's
separate 0x2AA-byte zeroing of new+0x384..0x62D a subsumed dead store,
ported as the single memset), "CRE V2.2" signature, then 0xDF dwords
old+8 → new+8. The scattered header copies: bytes 0x384/0x385/0x386,
the second class normalization, 0x388 (m_specifics) and 0x389
(m_gender) **are** copied (unlike some sibling formats), dword 0x38A
(5 bytes via m_specialCase), 0x38F, dword 0x390, m_name 0x394..0x3B3
(SCRIPTNAME_SIZE), 0x3B4 (m_avClass), the exe's dead zero-stores at
0x3B6/0x3B8 before dword 0x3B6 (m_classMask) ← old. All offsets come
from our CCreatureFileOffsets declaration (FileFormat.h; table at
new+900 = 0x384, data from 0x62E = 900 + sizeof(CCreatureFileOffsets)).

**Offsets table**: slot-then-count per list, **unconditionally** — an
empty list still gets its slot (cursor does not advance past the +8
pair). Tail: the three offsets (m_equipmentListOffset/m_itemListOffset/
m_effectListOffset from old 0x3D2/0x3D6/0x3DE) each get `+0x240 +
nDelta`; the counts (0x3DA/0x3E2) and the m_dialog RESREF (0x3E6) are
copied verbatim.

**Copy phase** (order: grouped 7×9, domain, innate, songs, shapeshifts):
the exe stages each list through `operator new(count*0x10)` temp buffers
(zero-fill, copy entries in one by one through the inlined Get, memcpy
into place, delete) — idiom traffic with identical output bytes; the
port writes `memcpy(pNew + nSpellOffset, pList->Get(nIndex),
sizeof(CCreatureFileSpell))` directly from the in-memory lists (this is
the accepted staging deviation the parity waiver covers). The inner
bound is the stored count slot, not the live list size. The
field_14/field_18 pair is written **always** — including after an empty
list (the +8 in sizing), via two `unsigned int` stores and
`nSpellOffset += 8`.

**Last block**: `nLastBlockSize = old[0x3DA]×0x14 (CCreatureFileItem) +
0x68 (CCreatureFileEquipment) + old[0x3E2]×(pNew[0x33] == 0 ? 0x30 :
0x108)` — the effect-size flag byte at raw 0x33 rides in on the bulk
header copy; assert 6423; then `memcpy(pNew + nSpellOffset, pOld +
0x3EE + nOldSpellBytes, nLastBlockSize)`. **Copy-out**:
`memcpy(*ppCreature, pNew, *plSize)`, `delete[] pNew`, return TRUE.

**Struct layout**: the exe's CGameSpriteSpellList is the MSVC
0x10-container form {dword, begin, end, cap} + field_10/field_14/
field_18 (0x1C); ours compiles the same logical layout on a std::vector
container (sizeof 0x18) — the accepted tree-wide deviation, same as
every other ported consumer. CGameSpriteGroupedSpellList is 9×0x1C +
m_nHighestLevel@0xFC = 0x100 both sides (the stale `/* 0048 */`
annotation in CGameSpriteSpells.h:64 is a known tree note, untouched).

(no V2.1 CRE exists in the shipped data); the unit test is the only
driver. Behavior is pinned by tests/test_creature_upgrade.cpp: 3 cases /
84 assertions (populated conversion, empty buffer + class
normalization, caster-class mapping).
