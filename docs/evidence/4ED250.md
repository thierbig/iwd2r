# 0x4ED250 CtrlAltDelete_AddItemPack

A debug console "CtrlAltDelete:" cheat-command handler, free function
taking nothing (`ret`), 97 bytes (0x4ED250-0x4ED2B0). Ported as a stub
in commit (see report).

## Body

Three identical call sites. Each reserves a stack slot, copy-constructs
a CString from a literal (0x7FCC88), then calls 0x4ED500 — the item
handout routine, deliberately not ported — with ecx restored from esi
(the dispatcher's this) and (CString by value at [esp], count, 0, 0)
pushed right to left:

1. literal 0x8ABD88 "potn08", count 5;
2. literal 0x8ABD80 "potn20", count 5;
3. literal 0x8ABD78 "scrlpet", count 1.

The literals were read out of the exe image at those RVAs. The port is
a stub holding the TODO:

```cpp
// TODO: 0x4ED250 calls 0x4ED500 (not ported).
```

When 0x4ED500 lands, the body is three calls to it with those
arguments.

## ecx / calling convention

ecx is saved into esi at entry and forwarded as the this of every
0x4ED500 call. No arguments of its own; `ret`. Free function.

## Callers

Not in tree: the console dispatcher 0x5838A0 (deliberately unported;
docs/followups.md).

## Test

None: the body is a stub; the real effect is the unported callee's.
Verified against the listing above.
