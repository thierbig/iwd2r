## Notes

The query handler. It wraps the query id (increment, 0 at 100) and clears the
per-query counter, allocates the 0x578-byte reply buffer, then runs the keys in
the protocol's order:

- `secure`: the six-byte challenge is copied out (and the extracted value
  freed); it rides on every validate;
- `basic`: response type 0, no validate first;
- `info` / `rules` / `players`: types 1/2/3, each preceded by a validate when
  the reply buffer already holds something (which flushes it);
- `status`: all four response types 0..3, each preceded by a validate;
- `echo`: a validate, then `\echo\` plus the extracted value;
- the final: when the buffer is non-empty, 0x4D1220 appends the last validate
  and `\final\` and flushes.

Each response is appended with the 0x546 flush threshold, and its buffer freed
only when its length is non-zero (the exe's condition).

The unit tests run a basic query and a status query end to end and pin the
resulting datagrams, including the status fan-out's four sends.
