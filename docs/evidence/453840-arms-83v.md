# 0x453840 CGameAIBase::EvaluateStatusTrigger, Task 83v arms

The dispatcher itself is 453840.md; this file records the eight small arms
Task 83v ported, in commits 74093d3d (0x4014, 0x4015, 0x4016, 0x40EC) and
3ad8b370 (0x40B2, 0x40B4, 0x40E1, 0x40F4). Register roles as in the other
arm batches: edi = this (mov edi, ecx at 0x453869) and ebx = 0 (NULL),
esi = bResult, the decoded CAITrigger copy at [esp+0x34], pSprite/pObject
at [esp+0x10], pObject2 at [esp+0x18], bNoRelease at [esp+0x28]. Four of
the eight arms resolve the trigger sprite through the vtable+0xA4 call and
leave through the early epilogue 0x45AB7A when it comes back NULL (nothing
shared, returns FALSE); the IsCreatureAreaFlag arm instead zeroes its
result inside the arm (0x454606) and falls into the release tail 0x45AD4C;
the two setter arms resolve their cause through sub_40CCA0 into pObject2
and always answer TRUE via the shared `mov esi,1` tail 0x45AD47.

## Arm notes

- 0x4014/0x4015/0x4016 share their loads exactly (sprite, base stats,
  movzx of the morale byte, the specifics' low byte) and differ only in
  the normalizer: sete for the equality, and for the orderings an sbb/neg
  pair whose operand order flips between GT (specifics first) and LT
  (morale first) -- both byte compares are unsigned. The port keeps one
  case body with the trigger ID picking the test, as StateCheck/
  NotStateCheck (0x4037/0x4038) already do.
- 0x40B2/0x40B4 share their loads with 0x40B3 SummoningLimitGT (sprite
  resolution for release, then Icewind586B70::GetCount, then the
  specifics); 0x40B2 normalizes with the sub/neg/sbb/inc equality idiom
  (as Happiness 0x4065) and 0x40B4 with the signed setl. One case body
  picks the test by trigger ID.
- 0x40E1/0x40F4 are byte-identical except for the final setter callee
  (sub_4530F0 vs sub_45B6E0); no helper was invented for the pair -- one
  case body picks the setter by trigger ID, with a comment saying so.
  Both store CAIObjectType::NOONE (0x8C7708) when the cause resolves to
  nothing, and both always answer TRUE (the shared `mov esi,1` at
  0x45AD47 before the release block), matching how the engine treats
  these "set and continue" triggers.
- 0x40EC is the only arm of the batch whose null-sprite path does NOT
  take the early epilogue: it zeroes bResult at 0x454606 and falls into
  the release tail. Same observable answer (FALSE), different cleanup
  path; the port notes this in the case comment.
