## Body

Prologue resets the static CResCache transfer record
(`stru_8FB90C[0..7]` cleared against the empty-string singleton at
0x8c5cf8, `dword_8FB92C = 1`, `stru_8FB90C[0] = areaName`), so callers
read the tail of the previous transfer even on the early exits.

Constructs a scoped CAreaFile for the area (`push 0x3f2` — type 1010,
CResHelper<CResArea, 1010>), inlines its SetResRef (CancelRequest /
GetResObject / ReleaseResObject) against the areaName resref, calls
GetData with no NULL check (a missing area crashes here, faithfully
preserved), takes the WED resref from pAreaData+8 via CResRef, resolves
it with GetResID type 0x3EB (1003 = WED), and gets the BIF with
GetResFilePtr. NULL → destruct the area file, return FALSE.

Single-player gate on byte [0x8cf6d8+0x1032] (m_bConnectionEstablished):
no connection → the WED BIF is the whole story — LoadCache, UnCache,
return TRUE. Multiplayer instead resolves the area-linkage caching
matrix at this+0x9d0 (m_ruleTables.m_tAreaLinkageCaching): GetFileName
(0x78A0F0, in-tree FALSE stub, return value ignored — sBifName stays
empty), then Find 0x4037A0 (CPoint out, TRUE) and Find 0x403550 (two
CString outs, the y-label row); either Find failing, or the row's
nCount coming back 0, lands in the shared tail that caches just the WED
BIF (LoadCache/UnCache) and returns TRUE. The cell fetch is
bounds-checked against the matrix's width/height words ([esi+0x20] /
[esi+0x22], cells at [esi+0x18]+(y*width+x)*4, default [esi+0x1c]) and
parsed with GetBuffer + ToNumber (CRT atol).

nCount < 0 skips both walks and returns TRUE with no WED load. Walk 1
(i = 0..nCount): GetResFilePtr NULL → FALSE; GetCachingRequirement()
== 0 → LoadCache/UnCache; advance the cell, GetResFileID(sYLabel).
Walk 2 re-runs GetResFileID(sYLabel) first, then for j = 0..nCount:
GetResFilePtr NULL → FALSE; append the lagging BIF name to the transfer
record (`stru_8FB90C[dword_8FB92C++] = sBifName` — the name recorded is
the PREVIOUS iteration's, matching the original); requirement != 0 →
LoadCache/UnCache; advance the cell, GetResFileID. Completion returns
TRUE with no WED load.

The exe's four LoadCache sites (0x5a0b17, 0x5a0c79, 0x5a0d43, and the
shared 0x5a0ead tail) appear as five textual call sites in the port —
the shared tail is spelled once per entry arm; functionally identical.
