## Notes

The port is `CBaldurMessage::SendChatMessage` in `src/CMessage.cpp`. It keeps the three formats
exactly: the disconnected joke `"You talking to me?"`, the plain `"[sender]:  text"`, and the
whisper `"[sender->target]:  text"` where the target is a player name before the first `:` and the
text is everything after the colon (the user's space included, hence the three spaces after
`]:`). It rewrites the caller's `CString`, adds the same text to `m_cChatBuffer`, and, only with
the session open, sends the raw `{BYTE length, text}` packet to the target (or to all players with
`SEND_ALL_PLAYERS | SEND_JOINING_PLAYERS` when the target is empty) with `SEND_GUARANTEED`; the
send's BOOLEAN is ignored and the handler answers TRUE, as the original does.

Proof is the unit test
`CBaldurMessage::SendChatMessage formats the local, target and disconnected chat` in
`tests/test_network.cpp` (`[msg][network]`, no `IWD2_DATA`, 16 assertions), using the file's bare
`TestChitin` fixture: it drives a plain message (`"[sender]:  hello"`), a whisper to a visible
player (`"[sender->target]:   whisper"`, with the text after the colon), an unknown name (stays
in the plain text), and a closed session (`"You talking to me?"`), checking both the rewritten
argument and the last `CChatBuffer` message. The network send itself is not observable in this
fixture: the function uses `CNetwork::SendMessage_`, which only touches `STATIC_MESSAGE_BUFFER`
for payloads of 128 bytes or more (compression); a small chat packet reaches the DirectPlay check
and returns FALSE without a plain-packet buffer window (`src/CNetwork.cpp:2508-2556`).
