# 0x5114D0 CMessageVisualEffect::Run

Message handler in the original's Message.cpp; in-tree at
src/CMessage.cpp:16529. Small function: GetDeny the target with the
SHARED/DENIED retry loop, TYPE_SPRITE check, then effectType 3 ->
m_nMirrorImages = m_nEffectProperty; effectType 23 (0x17) ->
m_nStoneSkins = m_nEffectProperty, and when the property is zero reset
the animation's color ranges and clear the color effects (stone-skin
visual teardown), else SetColorRange(14); then ReleaseDeny.

## Callers

- `CMessageHandler::AsynchronousUpdate` (0x4EE020) dispatches `Run()`
  through the vtable on queued messages.
- Constructed by the effect system when it reports a visual effect to
  the other machines (see tests/test_effects_save.cpp:748 for the
  mirror-image construction site the tests exercise).

## Callees

All in-tree, 0 newly ported, 0 stubs:

- `CGameObjectArray::GetDeny` / `ReleaseDeny` (retry loop, THREAD_ASYNCH,
  INFINITE), `CGameObject::GetObjectType`.
- `CGameAnimation::SetColorRange` / `ClearColorEffectsAll`
  (vtable+0xA4 / vtable+0x98 through the animation pointer at
  sprite+0x50F0, each guarded by the dropped UtilAssert), sprite-side
  `CGameSprite::SetColorRange(14)`.
- Base/derived stat writes: m_nMirrorImages (sprite+0xA60),
  m_nStoneSkins (sprite+0xA08).

## Notes

**The m_colors[7] overrun (fixed 2026-11-07).** The stone-skin reset
loop runs 8 iterations; the disassembly at 0x51157D-0x5115C4 reads
`BYTE PTR [esi + sprite + 0x5C8]` with esi 0..7 (`cmp esi,0x8; jl`) -
sprite bytes 0x5C8..0x5CF, pushed as the color for SetColorRange(esi).
`m_colors` is BYTE[7] at 0x5C8, so the in-tree port's
`m_colors[colorRange]` read out of bounds on iteration 7; byte 0x5CF is
the adjacent member `m_effectVersion`. The fix resolves the 8th
iteration the same way the CMessageSpriteUpdate::Run port did
(src/CMessage.cpp:14794): `(colorRange < 7) ? m_colors[colorRange] :
m_effectVersion` - SetColorRange receives the exact byte the exe
passes, with no out-of-bounds access. The in-tree TODO that suspected
the overrun is resolved by the disassembly, not by a debugger run.

**Dropped asserts** (house style): UtilAssert 0x83F (SetColorRange,
called per iteration at 0x5115A3) and 0x83C (ClearColorEffectsAll,
0x5115E6) - the GetAnimation()-non-null wrappers at ObjAnimation.h
2108/2111 region.
