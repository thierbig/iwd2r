# 0x7A3DF0 CNetworkWindow::TimeoutCall

## Decompiled

Bundle row 0x7A77D0 reaches this through
`CNetwork::SlidingWindowTimeouts`, which calls it once per connected
player on the sliding-window slot. The port is anchored on the exe
bytes (see exemption). What the exe does, in order:

1. Reads `dwTickCount = GetTickCount()` (the thunk address is cached
   in `ebp` at 0x7a3df3 and reused for every call).
2. If the pending frame's resend timer is armed
   (`m_pbTimeOutSet[0]`) and expired (`dwTickCount >
   m_pnTimeOut[0]`, unsigned), it recomputes that frame's number
   from `m_pOutgoingBuffers[0].pData` bytes 1-2 and resends it.
3. The three sends below share one shape: `FrameSend(...)` followed
   by `m_bSomethingHappened = TRUE`.
   - Expired pending frame: `FrameSend(0, nFrameNumber)`.
   - Ack timer: when `m_bAckTimerSet` and
     `GetTickCount() >= m_nAckTimer` (unsigned), `FrameSend(1, 0)`.
   - No-message timeout: when `m_nNoMessageTimeout <
     GetTickCount()` (unsigned), resend `FrameSend(1, 0)` unless
     this window is the local player's
     (`GetPlayerID(m_nPlayerNumber) == m_idLocalPlayer` suppresses
     the resend), then re-arm the timer through the inlined
     `SetNoMessageTimeout` (`GetTickCount() + 200`, DWORD_MAX on
     overflow).
4. If anything was sent, `m_nNextEvent = GetTickCount()` and return.
5. Otherwise `m_nNextEvent` becomes the earliest of the armed
   timers (`m_nAckTimer`, then `m_pnTimeOut[0]` if smaller), or -1
   when none is armed.

## Port

```cpp
// 0x7A3DF0
void CNetworkWindow::TimeoutCall()
{
    DWORD dwTickCount = GetTickCount();
    BOOLEAN v1 = FALSE;
    WORD nFrameNumber;

    if (m_pbTimeOutSet[0] && dwTickCount > m_pnTimeOut[0]) {
        v1 = TRUE;
        nFrameNumber = m_pOutgoingBuffers[0].pData[2] + (m_pOutgoingBuffers[0].pData[1] << 8);
    }

    if (v1 == TRUE) {
        FrameSend(0, nFrameNumber);
        m_bSomethingHappened = TRUE;
    }

    if (m_bAckTimerSet == TRUE && GetTickCount() >= m_nAckTimer) {
        FrameSend(1, 0);
        m_bSomethingHappened = TRUE;
    }

    if (m_nNoMessageTimeout < GetTickCount()) {
        if (g_pChitin->cNetwork.GetPlayerID(m_nPlayerNumber) != g_pChitin->cNetwork.m_idLocalPlayer) {
            FrameSend(1, 0);
            m_bSomethingHappened = TRUE;
        }

        // NOTE: Uninline.
        SetNoMessageTimeout();
    }

    if (m_bSomethingHappened == TRUE) {
        m_nNextEvent = GetTickCount();
        return;
    }

    BOOLEAN bHasNextEvent = FALSE;
    DWORD nNextEvent;

    if (m_bAckTimerSet == TRUE) {
        bHasNextEvent = TRUE;
        nNextEvent = m_nAckTimer;
    }

    if (m_pbTimeOutSet[0] == TRUE) {
        if (bHasNextEvent) {
            if (m_pnTimeOut[0] < nNextEvent) {
                nNextEvent = m_pnTimeOut[0];
            }
        } else {
            nNextEvent = m_pnTimeOut[0];
            bHasNextEvent = TRUE;
        }
    }

    if (!bHasNextEvent) {
        nNextEvent = -1;
    }

    m_nNextEvent = nNextEvent;
}
```

## Notes

The compiler-local quirk at 0x7a3e13 (`mov [esp+0xc],ecx`) stores
the timeout value into the stack slot `nFrameNumber` occupies, but
only on the v1 = TRUE path where the slot is about to be consumed
by `push eax`. On the FALSE path the reload at 0x7a3e2d reads
whatever is in the slot, yet the send guard at 0x7a3e31
(`cmp dl,bl; jne`) always jumps — `dl` is 0 and `bl` is 1 — so the
garbage value never reaches FrameSend. The port's uninitialized
`WORD nFrameNumber` declared outside the if has exactly those
read-before-write semantics.

`m_nNextEvent` is `int` in the tree and `nNextEvent` is `DWORD`;
the exe writes the full dword either way (0x7a3eba / 0x7a3efa /
0x7a3f06), so the -1 sentinel and timer values land bit-exact.

The function body ends at 0x7A3F0D; the two nops to 0x7A3F0F are
alignment padding, and the bytes at 0x7a3f10 onward are CRT
dynamic-initialization stubs for the statics at 0x8FB9C8/CC/D0
(the `MAX_TIMEOUT_TICK_COUNT` runtime copies) — not part of this
function.
