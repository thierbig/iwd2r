# 0x453840 CGameAIBase::EvaluateStatusTrigger, Task 83s arms

The dispatcher itself is 453840.md; this file records the eight small arms
Task 83s ported, in commits 0ba48faa (0x4027, 0x404E, 0x404F, 0x4050) and
69ee4738 (0x4066, 0x406A, 0x406B, 0x406C). Register roles as in the other
arm batches, with the correction the listing forces over 83r's note: edi =
this (mov edi, ecx at 0x453869) and ebx = 0 (NULL), esi = bResult, the
decoded CAITrigger copy at [esp+0x34]. Seven of the eight arms end
`jmp 0x45AD4C`, the shared release tail whose `mov eax, esi` hands esi to
the caller raw; 0x4066 alone can instead leave through the early epilogue
0x45AB7A (null sprite, nothing shared, returns FALSE).

## Notes

- 0x4027 (0x4550E2-0x4550EB): eax = [edi+0x54C] (this sprite's AI round
  counter, which CGameSprite::ProcessAI increments when it runs this
  sprite's AI), cdq, idiv ecx (the specifics), then movsx of the short at
  [edi+0x550] (the offscreen rounds counter ProcessAI raises while the
  sprite is out of the viewport, capped at 120) and setle -- the remainder,
  signed, compared by <=. Both counters are members of the AI object
  itself, not the trigger sprite; the test sets and restores them.
- The two trios are shared-load arms: 0x404E/0x404F/0x4050 all load
  GetObjectGame -> GetGameSave -> [save+0xC] and GetSpecifics, and
  0x406A/0x406B/0x406C all load GetNumCharacters (movsx of its short) and
  GetSpecifics. Only the compare differs: 0x404E answers inline with sete
  while 0x404F and 0x4050 each answer a carry pair (cmp/sbb/neg: 1 iff the
  first operand is below the second as unsigned -- `cmp eax,[esi+0xC]` for
  0x404F, i.e. specifics <u gold; `cmp [esi+0xC],eax` for 0x4050); 0x406A
  answers equality through the sub/neg/sbb/inc sequence (1 iff the
  difference is zero) while 0x406B/0x406C compare that difference's
  operands directly (setg, setl). Per the task's instruction the cases say
  so in comments rather than share a helper the exe does not have.
- 0x4066 resolves its object first: the virtual GetTriggerSprite call,
  bNoRelease saved, then `cmp pSprite, ebx(0); je 0x45AB7A` -- a null
  sprite leaves through the early epilogue with nothing released (the exe
  releases nothing there, and neither does the port). A live sprite gets
  `call GetHappiness` (ecx = the sprite) and `jmp 0x45683F` straight into
  0x406B's compare tail (movsx esi,ax; GetSpecifics; setg), so the
  greater-than compare is that other arm's code, entered with a different
  ax -- shared code, reproduced as the plain operator.
- 0x4567C0-0x4567FC (between HappinessGT and NumInParty) is a different,
  still-unported arm (an inline setl over the same happiness load);
  this batch does not touch it.
- Tests (877b1b62): 23 assertions, run alone under IWD2_DATA. The harness
  is the 83r one (pump thread, NewGame, LoadArea AR1000, AddAIObject); the
  AI counters, party gold and character count are set and restored around
  the CHECKs, the happiness sprite comes from MakeSprite with an
  instance-id cause, and CAIObjectType::NOONE pins the early return.
