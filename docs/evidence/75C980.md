Ported as `SHORT CGameSprite::RemoveSpell()`, the action-147 handler
(`CGameSprite::ExecuteAction` case 147, dispatcher 0x72A4FE-0x72A50E:
`returnValue = RemoveSpell()`). The spell is the action's string1; when that is
empty, `DecodeSpell(m_curAction.m_specificID, sSpell)` builds it and an empty
result answers ACTION_ERROR (the WORD at 0x8485CA).

`sub_727720` then finds the list entry (class, specialization mask and 1-based
level; `nLevel - 1` is the removers' 0-based level). The switch on
`CInfGame::GetSpellType(res)`:

- 1: `RemoveKnownSpell(nClass, nLevel - 1, res, 1, 0, 0)` erases the memorized
  entry; when the entry came from the domain list (sub_727720 sets
  `nSpecialization` from the caster's specialization mask)
  `RemoveDomainSpell(nLevel - 1, res, 1, 0, 0)` erases it there too;
- 2: `RemoveInnateSpell(res, 1, 0, 0)`;
- 3: `RemoveSong(res, 1, 0, 0)`;
- 4: `RemoveShapeshift(res)`.

the memorized entry is erased (with the cleric list's level coverage the
domain removal asserts on, as the original expects a cleric), the innate entry
