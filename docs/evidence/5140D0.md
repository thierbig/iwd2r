The key readings against the disassembly:

- The whole body, including ReleaseShare, sits under the SUCCESS result;
  a non-SUCCESS share jumps straight to the epilogue.
- The type gate reads the sprite type through [vtable+0x4] (GetObjectType)
  and compares against 0x31 (CGameObject::TYPE_SPRITE); the script setup
  runs only for sprites, ReleaseShare for every SUCCESS.
- The 0x78a9d0 call is the CResRef(BYTE*) converting ctor (confirmed
  directly: it forwards to 0x78AC50 = operator=(BYTE*), whose body is
  memcpy of RESREF_SIZE followed by a byte loop subtracting 0x20 from
  a-z — MakeUpper). Its argument is `&m_resScript` from an inlined
  GetResRef(), so both by-value CResRef arguments — SetResRef's and
  Read's — are uppercased copies of the message's resref.
- SetResRef (0x514220) is a thin wrapper assigning m_cResRef through
  0x78AC30 = operator=(const CResRef&).
- Read (0x40F160) gets TRUE as playerScript; SetScript receives the
  script number zero-extended from the WORD at [this+0xC].

## Port

The fork's body had `pScript->SetResRef(m_resScript); pScript->Read(m_resScript, TRUE);`.
Our tree has no CAIScript::SetResRef, but m_cResRef is public
(src/CAIScript.h) and CResRef::operator=(const CResRef&) is defined in
src (src/CResRef.cpp, // 0x78AC30). Because the exe's arguments are
uppercased copies, the port makes one copy and normalizes it before
installing and reading, keeping the exe's net behaviour:

```cpp
CResRef resScript(m_resScript);
resScript.MakeUpper();
pScript->m_cResRef = resScript;
pScript->Read(resScript, TRUE);
```

(The direct `GetResRef()` spelling the exe implies is not expressible:
GetResRef() returns const BYTE* while the converting ctor and
operator= take BYTE*.) The new CAIScript is the default-constructed
form (0x78A960); the CAIScript(CResRef) ctor is deliberately NOT used —
it calls Read(ref, FALSE), while the exe reads with TRUE. SetScript
takes SHORT in our tree, so the port casts. `#include "CAIScript.h"`
was added to src/CMessage.cpp (CAIScript was only forward-declared
there before).

## Disassembly checks

- GetShare 0x599A50 / ReleaseShare 0x599E70 keyed on [this+0x4]
  (m_targetId), THREAD_ASYNCH ds:0x851873, INFINITE — same pairing as
  the 0x513F00 marshal of this class.
- Type gate [vtable+0x4] == 0x31 matches CGameObject::GetObjectType /
  TYPE_SPRITE (src/CGameObject.h); SetScript slot [vtable+0x94] matches
  CGameSprite::SetScript(SHORT, CAIScript*) (src/CGameSprite.h).
- operator new(0x28) + ctor 0x78A960 + the inlined CTypedPtrList init
  on +0xC (list vtable 0x847D8C, `field_8 = 0`) match the CAIScript
  layout in src/CAIScript.h (m_cResRef 0x0, field_8 0x8, m_caList 0xC)
  and sizeof 0x28.
- 0x78A9D0 disassembled and confirmed as CResRef(BYTE*) (forwards to
  0x78AC50 = operator=(BYTE*): memcpy + MakeUpper), matching our
  src/CResRef.cpp // 0x78A9D0; 0x514220 confirmed as the m_cResRef
  assignment wrapper around 0x78AC30.
- Read 0x40F160 is in-tree (src/CAIScript.cpp, // 0x40F160,
  `void Read(CResRef cNewResRef, BOOL playerScript)`) — the port's
  by-value pass matches its signature.
