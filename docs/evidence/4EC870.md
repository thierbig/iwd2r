# 0x4EC870 CtrlAltDelete_CreateItem

The CREATEITEM handler of the debug console's "CtrlAltDelete:" cheat-command
layer, free function `void CtrlAltDelete_CreateItem(CString sItem, WORD
wUseCount1, WORD wUseCount2, WORD wUseCount3)` — `__cdecl` with the CString
by value on the stack (`ret 0x10`, the callee destructing it), 517 bytes
(0x4EC870-0x4ECA75). Ported in commit (see report).

## Naming

No string names this function directly; the name comes from the dispatch
chain. The console stores its command words obfuscated — each byte as
`2*ch + 0x10` (every encoded byte in the 0x8AF630-0x8AF6F0 table is even,
0x92-0xC2) — and the literal at 0x8AF680 decodes to "CREATEITEM". The
dispatcher's resolver (0x583E60) matches it (0x583F92) and stores id 0x15
at 0x583FA4; the dispatcher's index table at 0x583E34 maps id 0x15 to
byte 6, whose jump-table slot (state jump table 0x583DF4, `jmp
[ecx*4+0x583df4]`; 0x583E50 is the CREATEITEM arm's inner argc table,
below) lands on the arm at
0x583B81. The same chain pins ten already-ported handlers (FIRSTAID →
0x4ED250, MIDAS → 0x4ED230, ADDGOLD → 0x4ECAB0, ENABLECHEATKEYS →
0x4EC350, EXPLOREAREA → 0x4ECA80, MOVETOAREA → 0x4EC250, SETCURRENTXP →
0x4EC370, SETGLOBAL → 0x4ECAD0 lead, JEFFKATTACKS → 0x4EDF60,
JEFFKDEFENDS → 0x4EDF80), so the scheme is cross-validated.

## Body

Byte-for-byte the CtrlAltDelete_AddItem (0x4ED500) handout. Reads
`g_pBaldurChitin->GetObjectGame()` (chitin+0x1C54, global at 0x8CF6DC) and
builds a CResRef from sItem (0x78A970, local at the frame's 0x18 slot).
FindKey (0x78B410) on chitin+0x78E (`cDimm.m_cKeyTable`) with res type
0x3ED = 1005 (item, as in CItem's `CResHelper<CResItem, 1005>`); NULL
takes the error path — the MoveToArea miss shape: "Error File " + sItem +
" does not exist\n" (0x7FCED7/0x7FCE63) into DisplayText 0x4EC1C0, with
ecx (the dispatcher's this, saved in esi at 0x4EC88C) forwarded on this
one call.

The handout walks the party: count WORD game+0x3846 (`m_nCharacters`),
ids game+0x382E (`m_characterPortraits[nIndex]`), the object array
game+0x372C (`m_cObjectArray`). Per member:

- `GetDeny(id, THREAD_ASYNCH, &object, INFINITE)` (0x599C70), retrying
  (0x4EC966) while it returns SHARED (0x851870); DENIED is not retried,
  anything but SUCCESS (0x85186C) skips to the next member.
- On SUCCESS the denied object is scanned for its first NULL
  personal-inventory pointer: array at sprite+0x4B20 —
  `m_equipment.m_items[18 + n]`, count from 0x855128
  (`CScreenInventory::PERSONAL_INVENTORY_SIZE`, 24).
- No free slot: `ReleaseDeny(id, THREAD_ASYNCH, INFINITE)` (0x59A010) and
  next member.
- Free slot: `operator new(0xEE)` (0x7FC95B) — this function, unlike
  0x4ED500, guards it (0x4EC9F2 `test ebp,ebp` / 0x4ECA2A `xor eax,eax`
  stores NULL) — then a CResRef temp from sItem (0x78A970) and the CItem
  ctor 0x4E7E90 with (CResRef, wUseCount1 [+0x34], wUseCount2 [+0x38],
  wUseCount3 [+0x3C], 0, 0), stored into the slot, ReleaseDeny, and the
  epilogue: one item per call, into the first party member with a free
  slot.

The listing's INVALID_INDEX arm at 0x4EC954 (edi from 0x851878 when
nIndex >= m_nCharacters) is unreachable — 0x4EC93D returns when the count
is not positive and the loop at 0x4EC9D5 exits at nIndex == count — and is
omitted from the port.

## ecx / calling convention

ecx (the dispatcher's this) is saved into esi at 0x4EC88C and forwarded
to 0x4EC1C0 on the error path only, which never reads it. Free function.

## Callers

Not in tree: the console dispatcher 0x5838A0's CREATEITEM arm 0x583B81,
which calls here from four sites — 0x583BDA (argc 1: name only, three
zero counts), 0x583C1E (argc 2), 0x583C50 (argc 3), 0x583C77 (argc 4) —
selected by `dec eax; cmp eax,3; ja usage` over the parsed argument
count (jump table 0x583E50). The dispatcher is deliberately unported
(docs/followups.md).

## Test

None: driving the handout needs a live CInfGame with party sprite ids in
the object array and a loaded key table; the console layer has no test
harness (no dispatcher). The pinned facts above — res type 1005, the
party array and count, the m_items[18] slot base with
PERSONAL_INVENTORY_SIZE, the CItem argument order, and the allocation
guard — are verified against the listing.
