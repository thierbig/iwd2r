# 0x4EC250 CtrlAltDelete_MoveToArea

A debug console "CtrlAltDelete:" cheat-command handler, free function
consuming one CString by value (`ret 4`), 252 bytes (0x4EC250-0x4EC34B).
Ported in commit (see report).

## Body

Constructs a CResRef from the argument (0x78A970) and looks it up in
the key table at g_pBaldurChitin+0x78E (`cDimm.m_cKeyTable`, 0x542+0x24C)
with `CDimmKeyTable::FindKey` (0x78B410), res type 1010 (area, matching
CAreaFile's CResHelper<CResArea, 1010>) and the warning flag set. On a
miss it builds "Error File " + argument + " does not exist\n"
(literals at 0x8ABD2C / 0x8ABD18) and hands it to
CtrlAltDelete_DisplayText (0x4EC1C0). On a hit it copy-constructs the
argument into a new slot and calls `CScreenWorld::MoveToArea`
(0x690410) on `g_pBaldurChitin->GetScreenWorld()` (0x438550, the one
call the original does not inline).

## ecx / calling convention

ecx is saved into esi at entry and moved back into ecx only for the
0x4EC1C0 error-path call, where it is ignored again; nothing else reads
it. Free function, `ret 4`.

## Callers

Not in tree: the console dispatcher 0x5838A0 (deliberately unported;
docs/followups.md).

## Test

None: the hit arm needs a loaded game with an area to move to, and the
miss arm's observable effect is world-screen text, which no unit test
drives. Verified against the listing above.
