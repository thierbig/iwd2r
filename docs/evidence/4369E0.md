## Notes

The host's announce of the movie it just started. It needs the session open
(`GetSessionOpen`, 0x8CF6D8 + 0x1032) **and** owned (`GetSessionHosting`
+0x1033), else FALSE; there is no addressee name (the empty `CString` at
0x8C5CF8 is passed) and the flags are `SEND_ALL_PLAYERS | SEND_GUARANTEED`
(0x100 | 0x200). The payload is the same `{BYTE length; char resref[length]}`
built from `CResRef::CopyToString` (0x78A9F0) and `GetBuffer(length)`; the
wire is type 78 `MSG_TYPE_MOVIE` (0x84CF92) and subtype 65
`MSG_SUBTYPE_MOVIE_ANNOUNCE` (0x84CF94), both new constants here (WSO has no
names, T122 §3). A failed `CreateBuffer` returns FALSE; otherwise the
function returns TRUE and ignores the send's result (the original does too).

Wire bytes under `MINIMAL_PACKET_SIZE`: `[0] = 0xFF`, `[1] = 78`, `[2] = 65`,
`[3] = length`, `[4..3+length] = the resref` (12 bytes for an 8-character
resref, 4 for an empty one). `tests/test_network.cpp` ("msg: the movie
request and announce carry the length-prefixed resref", `[network][msg]`)
selects `SERV_PROV_TCP_IP` and pins the closed-session and client guards
(buffer untouched), the eight-character resref travelling whole and the
empty resref sent as length 0. Against the stubs 13 of its 24 assertions
