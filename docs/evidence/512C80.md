## Recovered body

`src/CMessage.cpp` (`// 0x512C80`). The asymmetry is exact:

- an unresolved FIRST id stores `CGameObjectArray::INVALID_INDEX` at +0x0C
  and the message is still accepted;
- an unresolved SECOND id is accepted only when the wire pair is
  `(PLAYER_ID 0, LONG INVALID_INDEX)`, which Marshal writes when it cannot
  share the second object; any other unresolved second pair returns FALSE.

On FALSE the first id has already been stored and the second member is left
unchanged. There is no trailing size guard (the original reads 16 bytes from
`SPEC_MSG_HEADER_LENGTH`, like its sibling 0x513100).
