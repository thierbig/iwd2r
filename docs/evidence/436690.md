## Notes

The client's request to start a movie. Guards by offset: the session must be
open (`GetSessionOpen`, 0x8CF6D8 + 0x1032) and **not own it** - the exe
returns FALSE when `GetSessionHosting()` (+0x1033) is 1, so the host never
sends a request; then the host player's name is resolved inline
(`m_nHostPlayer` at +0x10E0, `m_psPlayerName` at +0x1088, else ""), and an
empty name returns FALSE instead of sending to nobody. The payload is
`{BYTE length; char resref[length]}` - the resref converted with
`CResRef::CopyToString` (0x78A9F0) and copied from `GetBuffer(length)` - and
it is addressed to the host name with `SEND_GUARANTEED` only. The wire is
type 78 `MSG_TYPE_MOVIE` (byte at 0x84CF92) and subtype 82
`MSG_SUBTYPE_MOVIE_REQUEST` (0x84CF93); both constants are new here (WSO has
no names, T122 §3). A failed `CreateBuffer` returns FALSE; the
`SendSpecificMessage` result is ignored and the function returns TRUE (the
original does the same - `SendMessage_` reports failure in this
direct-play-less build).

Wire bytes under `MINIMAL_PACKET_SIZE`: `[0] = 0xFF`, `[1] = 78`, `[2] = 82`,
`[3] = length`, `[4..3+length] = the resref` (11 bytes for a 7-character
resref). `tests/test_network.cpp` ("msg: the movie request and announce carry
the length-prefixed resref", `[network][msg]`) selects `SERV_PROV_TCP_IP`,
pins the closed-session and hosting guards, the missing-host-name failure
(buffer untouched), the 7-byte resref bytes and, in its second half, the
announce's 8-character and empty cases. Against the stubs 13 of its 24
assertions fail.
