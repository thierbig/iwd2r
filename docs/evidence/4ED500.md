# 0x4ED500 CtrlAltDelete_AddItem

The add-item helper of the debug console's "CtrlAltDelete:" cheat-command
layer, free function `void CtrlAltDelete_AddItem(CString sItem, WORD
wUseCount1, WORD wUseCount2, WORD wUseCount3)` — `__cdecl` with the CString
by value on the stack (`ret 0x10`, the callee destructing it), 557 bytes
(0x4ED500-0x4ED72D). Ported in commit (see report).

## Body

Reads `g_pBaldurChitin->GetObjectGame()` (chitin+0x1C54) and builds a
CResRef from sItem (0x78A970, local at the frame's 0x18 slot). FindKey
(0x78B410) on chitin+0x78E (`cDimm.m_cKeyTable`) with res type 0x3ED = 1005
(item, as in CItem's `CResHelper<CResItem, 1005>`); NULL takes the error
path, which is byte-for-byte the MoveToArea miss shape: "Error File " +
sItem + " does not exist\n" (0x7FCED7/0x7FCE63) into DisplayText
(0x692460) on the world screen (chitin+0x1C88) with the empty-string name
(0x8C5CF8) and lMarker from 0x84C960, spelled as the tree's -1.

The handout walks the party: count WORD game+0x3846
(`m_nCharacters`), ids game+0x382E (`m_characterPortraits[nIndex]`), the
object array game+0x372C (`m_cObjectArray`). Per member:

- `GetDeny(id, THREAD_ASYNCH, &object, INFINITE)` (0x599C70), retrying the
  call (0x4ED63C) while it returns SHARED (0x851870) — DENIED is not
  retried; anything but SUCCESS (0x85186C) skips to the next member.
- On SUCCESS the denied object (written to the 0x10 frame slot) is scanned
  for its first NULL personal-inventory pointer: array at sprite+0x4B20 —
  `m_equipment.m_items[18 + n]` (m_equipment at 0x4AD8, m_items at +0), the
  count read from 0x855128 (`CScreenInventory::PERSONAL_INVENTORY_SIZE`,
  24).
- No free slot: `ReleaseDeny(id, THREAD_ASYNCH, INFINITE)` (0x59A010) and
  next member.
- Free slot: `operator new(0xEE)` (0x7FC95B), a CResRef temp from sItem
  (0x78A970) built into the outgoing argument area, `CItem` ctor 0x4E7E90
  with (CResRef, wUseCount1 [arg at +0x34], wUseCount2 [+0x38], wUseCount3
  [+0x3C], 0, 0) matching the tree signature, the result (NULL if the
  allocation failed — no NULL check) stored into the slot, then
  ReleaseDeny and the epilogue: one item per call, into the first party
  member with a free slot.

The listing's INVALID_INDEX arm at 0x4ED60C (edi from 0x851878 when
nIndex >= m_nCharacters) is unreachable — 0x4ED5FB returns when the count
is not positive and the loop at 0x4ED68F exits at nIndex == count — and is
omitted from the port.

## ecx / calling convention

ecx (the dispatcher's this, which 0x4ED250 forwards on each of its three
calls) is never read; first touch is the frame write at 0x4ED527. Free
function.

## Callers

In tree: CtrlAltDelete_AddItemPack (0x4ED250, wired in this task). Not in
tree: the console dispatcher 0x5838A0 (deliberately unported;
docs/followups.md).

## Test

None: driving the handout needs a live CInfGame with party sprite ids in
the object array and a loaded key table; the console layer has no test
harness (no dispatcher). The pinned facts above — res type 1005, the party
array and count, the m_items[18] slot base with PERSONAL_INVENTORY_SIZE,
and the CItem argument order — are verified against the listing.
