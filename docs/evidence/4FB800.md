# 0x4FB800 CMessageContainerItems::UnmarshalMessage

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x4FB800` and the Ghidra decompile
below; Ghidra names the function `FUN_004fb800`.

## Body

`__thiscall BOOL UnmarshalMessage(BYTE* pData, DWORD dwSize)`, 550 bytes,
`ret 8`. Resolve the target pair through the remote object array; a miss
stores INVALID_INDEX and decoding continues (0x4FB85F-0x4FB88E). Read
m_nItems and the present count, allocate `new CItem*[m_nItems]` (asserted
non-null), NULL every slot, then for each present entry read the slot
index, resref, usage counts, wear and flags, build the CItem through its
six-argument constructor and store it at the slot (0x4FB8F0-0x4FB9F0).
The closing assert is `cnt == dwSize`; the original returns TRUE either
way. The resref copy is bounded to 8 bytes in the port (P4-10).

## Wire format

Payload (without the 3-byte SPEC_MSG_HEADER): the target's remote pair
(PLAYER_ID m_remotePlayerID, LONG m_remoteObjectID, or (0, 0xFFFFFFFF) when
the id does not resolve), then SHORT m_nItems (the container's slot count,
holes included) and SHORT the number of present items, then for each
present slot: SHORT slot index, a length-prefixed resref, the three
CItem::GetUsageCount values (SHORTs), the SHORT m_wear and the DWORD
m_flags. The unmarshal allocates the full slot array and leaves the holes
NULL; unlike its sibling pair, an unresolved target pair is not fatal (the
target becomes INVALID_INDEX and the body is still decoded, TRUE).
