## Port

The fork's body is close in shape but wrong or lossy in several
readings, all fixed:

- The charge tail opened straight on the removal flag; the exe first
  spends the charge and lets the item go — GetUsageCount(field_55A0),
  dec, SetUsageCount(field_55A0, count-1) (0x4E8760), Release
  (0x747dc3-0x747df1) — before any flag work. Restored at the shared
  `consumeCharge` label, so the use-magic-device backfire jump consumes
  its charge too, as in the exe.
- The tail's quick-bar sync was `UpdateQuickButtons(..., FALSE, ...)`
  with an UNIMPLEMENTED note; the exe calls CheckQuickLists
  (0x71ABA0) with a stack CAbilityId{2, field_559E, field_55A0},
  -1, and a removal flag folded from usageFlags == 1 and
  CheckIfUsedUp(0x75D450) — both operands always evaluated, the flag
  computed before the maxUsageCount gate so the Unusable trigger side
  effect runs even when the gate closes. Ported faithfully as a
  bitwise &.
- The far limit lacked the exe's one-square slack: `farLimit =
  range + 1 + personalHalf + 1`, the +1 being the WORD global at
  ds:0x85BC86 (value 1, movsx) added at 0x747834.
- Names brought onto the in-tree spellings: MoveToPointRange ->
  MoveToPoint(castPoint, 0) (0x73FEC0); CheckInvisibility ->
  IsVisibleToCaller(FALSE) (0x727B80); ApplyEffect ->
  ApplyEffectToSprites (0x46E130); CreatePiercingDamageEffect ->
  IcewindMisc::sub_585380; ApplyDamageModifiers ->
  IcewindMisc::sub_5860F0; CAITrigger::UNUSABLE ->
  CAITRIGGER_UNUSABLE (9, ds:0x847DAA); the projectile's
  m_casterResRef -> m_sourceRes (proj+0x18A); the raw feedback ids
  0x41/0x42 -> FEEDBACK_USEMAGICDEVICEFAILED / _SUCCEEDED; the fork's
  static CRuleTables call -> game->m_ruleTables.CheckUseMagicDevice
  (the in-tree method is a non-static member, which is also how the
  exe reaches it — off the game object inlined at 0x7479D9).
- The backfire dice and level: two dice per max(1, level) of
  GetMaxEffectSpellLevel (0x4EA3F0), sides 6, the raw level as the
  spell-level byte, flags |= 2 — as the fork had it, kept.

The item resolution (slot pair on an empty string1, equipment scan
otherwise, Demand/GetAbility with the field_559E/field_55A0 cache and
ACTION_ERROR on every miss), the depleted Unusable trigger with the
resref string, the grid distance and near/far/LOS gate, the
drop-path/orient/drop-path/cast-counter sequence, the dispel pair,
the projectile seeding and the jump-table effect dispatch, the
whirlwind seed mirrored into the fire message, and the closing
AutoPause(0x40) + ACTION_DONE all match the exe as the fork wrote
them.
