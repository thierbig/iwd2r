# 0x44DC10 CGameAIBase::ExecuteAction, action 294 arm

The dispatcher itself and its exit tails are 44DC10.md; this file records
the one arm this change ports, case 294 XEquipItem (0x451D30-0x451D7F),
whose call to 0x7625F0 replaced its TODO.

Register roles as in 83d: ebx = this, edi = &m_curAction (this+0x476),
ebp = pTarget, esi = returnValue, [esp+0x10] = bShare.

## The arm

- 0x451D30-0x451D3B: `GetTargetShareType(0x84C507)` (0x45BDD0), the
  byte at 0x84C507 = 0x31 = CGameObject::TYPE_SPRITE.
- 0x451D42-0x451D44: a null target jumps to 0x44E1DB, the tail that forces
  ACTION_DONE **before** bShare is set (so nothing is released); the entry
  default ACTION_ERROR is not what the exe answers. Covered by the 83e case
  ("ai: ExecuteAction 294 295 296 and 297 ...").
- 0x451D4C: bShare = TRUE.
- 0x451D4A-0x451D71: `GetSpecifics2()` pushed (arg3), `GetSpecifics()`
  pushed (arg2), then `GetString1` (0x41E1B0) fills the CString temp in the
  arg1 slot -- the push-ecx sret slot tracked at [esp+0x34] -- so the call
  receives `(CString, GetSpecifics(), GetSpecifics2())`.
- 0x451D73: `call 0x7625F0` with ecx = ebp (the target sprite); the SHORT
  result goes to esi (the action return) and the arm jumps 0x44E1DE, the
  plain release test.
- The whole 0x451D30-0x451D7F range is now `returnValue =
  static_cast<CGameSprite*>(pTarget)->XEquipItem(...)` in src/CGameAIBase.cpp;
  the callee is CGameSprite::XEquipItem, evidence 7625F0.md.

## Tests

`tests/test_ai.cpp`, "ai: ExecuteAction 294 XEquipItem equips with a swap and
unequips to the pack" ([ai][data][ar3000]) sets the action's actee to a live
sprite's id and runs `CGameAIBase::ExecuteAction`: the success path (equip
swap, unequip move, full-pack drop) answers ACTION_DONE and a missing item
answers ACTION_ERROR -- the callee's two return words, through this arm's
`returnValue` and 0x44E1DE. The null-target forced ACTION_DONE stays pinned
by the existing 83e case.
