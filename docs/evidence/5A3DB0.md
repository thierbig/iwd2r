# 0x5A3DB0 UpgradeCreatureFileV20ToV21

Free function in the original's InfGame.cpp; declared at
src/CInfGame.h:104 and defined at src/CInfGame.cpp:11820. No Ghidra
pseudo-code embed: written and verified against the instruction-level
disassembly (the decompiler times out on bodies this size — the 0x5A5060
port hit the same 330 s window — and the disassembly is the stronger
authority anyway; every byte offset below was read from the exe).

## Callers

- 0x5A792F inside 0x5A7740's version dispatch (the gate
  `CGameSprite::Unmarshal` calls): "CRE V2.2" returns, "CRE V2.1" goes to
  0x5A5060, "CRE V2.0" calls this function, anything else draws
  UtilAssert 0x1ae5 "Corrupt or Obsolete creature data".
- The caller sizes the destination itself and grows `*plSize` by 0xCA
  **before** the call — the buffer passed in is already V2.1-sized with
  the V2.0 image at the front, and `*plSize` is read-only here (read for
  the pNew allocation and the copy-out; no store anywhere in the body).
- The Unmarshal wiring stays a TODO by design: 0x5A7740 belongs to that
  wiring task, not this port.

## Callees

Everything is in-tree; 0 newly ported, 0 stubs (callee budget 0/6):

- `operator new[]` 0x7FC95B / `operator delete[]` 0x7FC984 — the pNew
  staging image and its copy-out destruction (allocation traffic; see the
  parity waiver).
- memcpy/memset — all inlined as rep movs/stos by the compiler, no
  out-of-line calls.
- **No game calls at all** — the body never touches the engine, which is
  what makes it drivable as a pure-data unit test.

## Notes

**Convention**: `BOOL UpgradeCreatureFileV20ToV21(BYTE** ppCreature,
LONG* plSize)` — the caller's buffer is both source and destination:
`pOld = *ppCreature`, the V2.1 image is built into
`pNew = new BYTE[*plSize]`, and the tail copies back with
`memcpy(*ppCreature, pNew, *plSize)`; `delete[] pNew`; return TRUE.
The function also **writes back into the old buffer** in three places
(the class-byte normalization, the level floor, and the halve/thirds
lambdas below) — ported as written.

**Prologue and header moves** (0x5A3DB0-0x5A4365, port at
src/CInfGame.cpp:11820-11916): "CRE V2.1" signature; a second literal
zeroing of dwords 8..0xE2 kept as `memset(pNew+8, 0, 0xDF*4)` (subsumed
by the fresh allocation, ported anyway); XP dword at 0x14 rides the
identity memcpy(pNew+8, pOld+8, 0x10); identity moves 0x18 (0x2D) and
0x46←0x48 (0xF compact-by-2); the sparse R2 block (0x55←0x59 4B,
0x59←0x5D signed/10, 0x5A←0x5E 6B, 0x65←0x6B 3B, 0x68←0x82,
0x6A←0x84 0x20B, 0xAC←0xA4 0x114B, and the state-block relocations
0x258..0x26E ← 0x220..0x243); `memset(pNew+0x218, 0, 6)`.

**XP ladder** → `pNew[0x25A]` (0x5A3EE5 region, port at :11838-11877):
signed-compare thresholds >0xC350→17, >0x7530→16, >0x4E20→15, >0x3A98→14,
>0x2EE0→13, >0x2710→12, >0x1F40→11, >0x1770→10, >0xFA0→9, >0x7D0→8,
>0x578→7, >0x1A4→6, >0xAF→5, >0x78→4, >0x5A→3, >0x3C→2, >0→1, else 0.

**Stat divides and skills** (0x5A4365-0x5A45A0, port at :11918-11960):
unsigned /10 for 0x21E←0x45, 0x221←0x68, 0x222←0x67, 0x223←0x6A,
0x224←0x69, 0x226←0x231, 0x227←0x83 (0x220←0x66 moves undivided,
0x225 is a literal 0); kit dword 0x270 zeroed (re-filled per class arm);
skills 0x274←0x248 (0x2B), 0x2A0←0x274 (0x4A), 0x2EA←0x2BE,
0x2EC←0x2C0 (0x18); `memset(pNew+0x384, 0, 0x6A)` for the class/level
block.

**Class dispatch** (0x5A45A0-0x5A4B9C, port at :11974-12196): switches
on the BG1 class.ids byte pOld[0x2DB] after normalizing 0/0xFF → 2
(FIGHTER, written back into pOld); each arm fills the mask dword
0x3B6 (CLASSMASK_* constants, CAIObjectType.h), the primary-class byte
0x387 (CAIOBJECTTYPE_C_*), the combined level 0x8A and the alphabetical
per-class slots 0x8B..0x95 (barbarian..wizard). Levels below 1 floor to
1 **in pOld** before the arm runs; dual classes halve each source level
(lambda `v <= 3 ? 1 : v/2`, written back to pOld), triple classes take
`max(v/3, 1)`. Quirks ported literally:

- MAGE (1, alias 202): kit dword 0x270 = 0x4000.
- F/M (7): 0x8F is stored twice — halved pOld[0x234] at 0x5A4665 then
  overwritten by halved pOld[0x235] at 0x5A4675 — and 0x95 is never
  stored at all; 0x8A is the sum.
- C/M (14), C/T (15), C/R (18): class byte CAIOBJECTTYPE_C_CLERIC (3),
  store at 0x5A4B9C.
- DRUID (11): 0x8A is the halved first level, not a pair sum.
- RANGER (12): no halving, 0x8A = 0x234.
- PALADIN (6): kit dword 1; MONK (20): kit dword 8; SORCERER (19): no
  kit store.
- Default (unknown ids, incl. 21..201 and 210..255): the FIGHTER arm.
- F/M/T (10) and F/M/C (17): 0x8A is the sum of all three halved/thirds
  levels (0x5A4C46).

**Common tail** (0x5A4B9C-0x5A4F2D, port at :12198-12289): class-byte
mirror 0x3B4 ← 0x387; 0x388←0x2DC (0x2C); then the V2.0 spellbook
sub-header at 0x308..0x33B re-based into the V2.1 sub-header at
0x3BA..0x3EA — the six offset dwords (0x308/0x310/0x318/0x320/0x324/
0x32C) each get +0xB2, the counts (0x30C/0x314/0x31C/0x328/0x330) and
the dialog resref (0x334) are copied verbatim. Read against the V2.1
sub-header slot map the tail sections are:

- **Memorized spells** (slot pair 0x3BA/0x3BE): gated on the signed sum
  [0x30C]+[0x314]+[0x31C] > 0; size = 12·[0x30C] + Σ over [0x314]
  headers (0x10 stride at pOld+[0x310]) of 12·(dword at record+0xC)
  + 16·[0x314]; copied verbatim from pOld+0x33C to pNew+0x3EE.
- **Item slots** (0x3D6/0x3DA): ungated, 20 bytes per [0x328] entry,
  verbatim from pOld+[0x324] to pNew+[0x324]+0xB2.
- **Effects** (0x3DE/0x3E2): gated on [0x330] ≠ 0, [0x330] ×
  (pNew[0x33] ≠ 0 ? 264 : 48) bytes verbatim — the last-block flag at
  byte 0x33 (riding in on the header memcpy) is the same flag the
  V2.1→V2.2 upgrade keys its 0x30/0x108 effect stride on.
- **Equipment header** (0x3D2): ungated rebuild — 0x68 bytes at
  pNew+[0x320]+0xB2 filled 0xFF (rep stosd of -1, the empty-slot
  sentinel), then the V2.0 header's first 0x1A bytes 1:1, 0x1A..0x4B
  shifted +8, and the dword at 0x4C shifted +0x18
  (0x5A4E75-0x5A4EF8). The V2.1 block consumes 0x68 bytes where the
  rebuild reads 0x50, so downstream sections must sit at least 0x68 past
  the V2.0 equipment offset or the rebuild (written last) clobbers them.

**Caller growth accounting**: the dispatch grows the buffer 0xCA =
0xB2 (sub-header re-base, which shifts every tail section) + 0x18 (the
equipment header's 0x50→0x68 growth). The unit test tiles its tail
sections so all re-based destinations land exactly at the buffer end.

(no V2.0 CRE exists in the shipped data); the unit test is the only
driver. Behavior is pinned by tests/test_creature_upgrade.cpp: 3 cases /
166 assertions (full-tail fighter conversion, 17 class-dispatch
