## Notes

1. The guard is the client's again (session open, not hosting).
2. `bSaveToTemp` chooses `CInfGame::m_sTempDir`; otherwise `CInfGame::sub_5C0B30()` (the
   multiplayer save directory) — the same two paths the save/load code uses.
3. The per-type blocks are the inlined `CResHelper<T,nType>::SetResRef(cResRef, TRUE, TRUE)`
   followed by `GetRes()->Write(...)` and the helper's destructor; the 1014 case calls the
   out-of-line SetResRef (0x43E190), which is why the decompile shows `FUN_0043e190` there. The
   original does not null-check `GetRes()` (the resource is expected to be in the key table); the
   port mirrors that.
4. The `dwSize` argument is unused (the payload is self-describing) — `(void)dwSize` in the port.
5. The decompile was drafted with Ghidra 12.1.4 from the labelled project on the box
   (`tools/oracle.py evidence 0x42A3F0`), whose checkout predates this port, so Ghidra prints the
   function as `FUN_0042a3f0`; the header above keeps the port's name.
6. The oracle case (a session plus a resource write) is still pending — it is not honestly
   fixturable for the oracle; the unit test covers the guard and the parse/write on the private
   view.
