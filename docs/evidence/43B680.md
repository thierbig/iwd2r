# 0x43B680 CBaldurMessage::DeleteArea

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x43B680` and the Ghidra decompile
below; Ghidra names the function `FUN_0043b680`.

## Identity and calling convention

Member of CBaldurMessage in the original's Baldur/CMessage.cpp, dispatched
by 0x4EE020's `DELETEAREA` (k = 107) `/` `d` (100) arm. `__thiscall`,
`ret 0xc`: `(INT nMsgFrom, BYTE* pByteMessage, DWORD dwSize)`; nMsgFrom is
ignored.

**Survey correction:** this row is the handler for subtype `d` (100), the
host's delete/no-delete *result* -- not the "DeleteArea (CScreenWorld::DeleteArea)"
result of a poll the survey's row 51 described as the tally.

## Body

Guards: an established session and `m_bIsHost` false (the result goes to
the clients), else FALSE. Decodes `{BYTE areaLen; char area[]; BYTE
bDelete}`; on a hit from `CInfGame::GetArea` it either calls
`CScreenWorld::DeleteArea(pArea)` (`g_pBaldurChitin->m_pEngineWorld`, the
dword at chitin+0x1C88) when bDelete == 1, or sets the area's `field_AE6`
(+0xAE6, "undeletable" marker) to 1. A miss is a no-op; the handler returns
TRUE either way.
