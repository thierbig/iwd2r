## Vtable check

0x85133C against the base CProjectile vtable 0x84D7B8. This build ships
no RTTI COLs (the dword below each table is the previous table's last
entry), so the bounds come from ctor stamps: our table is bounded above
by the next table at 0x8513BC (its slot 0 is the deleting-dtor thunk
0x580750, and its slots 1-2 repeat the family's 0x45B680/0x4C7BE0 head),
0x8513BC − 0x85133C = 0x80 → exactly 32 entries, slots 0x00–0x7C, the
same count as the base's (0x84D7B8–0x84D834). Over those 32 slots
exactly two differ:

- **slot 0x00 dtor — 0x57F360** (base 0x51EA70): the same ICF-folded
  deleting thunk CProjectile85112C carries (docs/evidence/57E1B0.md) —
  `call 0x57F380`, the flag test, conditional operator delete 0x7FC984,
  `ret 4`, whose scalar half 0x57F380 is a single `jmp 0x51E9B0` —
  straight to CProjectile's own scalar dtor (our ported `// 0x51E9B0`,
  src/CProjectile.cpp:59). No own teardown: ours stays implicit (the
  CProjectile84DAD4 precedent).
- **slot 0x6C Fire — 0x57F390** (base 0x78E740): real logic — the sound
  manager (ds:0x8CF6DC → [eax+0x1C54] + 0x372C in ecx), the byte at
  0x851873 pushed as an argument into 0x599A50 with the stack source/
  target ids, the result compared against byte 0x85186C (the mute test),
  a virtual call [edx+0x1C] on the stack-arg object to fetch the origin,
  the dx²+dy² distance through 0x7E8034/0x7E812C (fild/fsqrt), then
  three 0x5847B0 direction builds with negated components and a
  four-iteration loop — a multi-shot spread fire. Ported at
  docs/evidence/57F390.md; the class now declares that slot.

C++ derivation from CProjectile declares only the dtor (implicit) and
Fire, which reproduces exactly that vtable.
