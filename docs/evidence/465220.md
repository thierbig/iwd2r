# 0x465220 CGameAIBase::GivePartyGoldGlobal

Member of CGameAIBase in the original's CGameAIBaseActions.cpp,
`__thiscall` `SHORT GivePartyGoldGlobal()`, 657 bytes
(0x465220-0x4654B0). Ghidra's CGameSprite_B3AUTO_00465220 name is
wrong: the function reads `this` as a CGameAIBase (m_curAction at
0x476, the sprite tail keyed on the m_objectType byte at +4) and its
caller loads the CGameAIBase pointer into ecx.

Ported in one commit, 5affbea4; the caller arm is the ExecuteAction
commit c5395808 (case 141 of 0x44DC10, 0x44EF53-0x44EF61:
`returnValue = GivePartyGoldGlobal(); goto done`).

## Callers

Exactly one: the case 141 arm of CGameAIBase::ExecuteAction
(0x44EF53-0x44EF61), reached when a script queues
GivePartyGoldGlobal(name, scope). The arm routes the result through
the common done label, so the handler runs with no target share held
and acts on the executing object itself.

## Callees

No new callees: every call is in-tree — CAIAction::GetString1 and
GetString2, CString::MakeUpper, strcmp, CBaldurChitin::GetObjectGame,
CInfGame::GetVariables, the virtual GetObjectType,
CGameSprite::GetLocalVariables, CVariableHash::FindKey (virtual),
CInfGame::GetArea, CGameArea::GetVariables, the CMessagePartyGold
constructor and CMessageHandler::AddMessage. All were ported before
this task.

## Notes

- The amount comes from the variable named by the action's two
  strings, both uppercased: GetString1 is the variable name,
  GetString2 the scope — two separate strings, unlike SetGlobal's
  single "SCOPE+NAME" parsing. GLOBAL reads the game variables; LOCALS
  reads the executing sprite's own locals and reads 0 for a
  non-sprite (gated on the virtual GetObjectType, not the +4 byte);
  MYAREA replaces the scope with the area name read as a C string
  from the start of m_pArea (the header's RESREF, as SetGlobal does)
  and any other scope is an explicit area name through
  CInfGame::GetArea. A missing variable reads 0.
- The second LOCALS compare (0x465330) is dead: its only predecessor
  is the jne from the first LOCALS compare (0x4652cb), taken only when
  the scope is not LOCALS, so it always fails and the game-variables
  lookup under it never runs. Kept as a faithful dead else-if with a
  note.
- The missing-area path reads its amount from an uninitialized spill
  slot ([esp+0x14] at 0x465416; no path to that compare stores it).
  Bounded to the 0 the port initializes the amount to, with a note —
  the same CScreenStore P4-10 precedent.
- The sprite tail is keyed on the m_objectType byte at +4
  (TYPE_SPRITE 0x31), not the virtual: an unsigned compare caps the
  amount at the derived gold (m_nGold at 0x988) and the subtraction
  hits both the base gold (0x5B8) and the derived gold.
- The party gain is a synchronous CMessagePartyGold(TRUE, TRUE,
  amount, m_id, m_id): an adjustment with feedback, whose Run adds
  the amount to the party's gold. Returns ACTION_DONE.
