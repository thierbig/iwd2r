## Port

The fork's body is close in shape but wrong in five readings, all fixed:

- Missing leading `ResolveSourceSprite()` — the exe's very first call after
  the prologue is the virtual slot +0x28; the fork opens directly on the
  m_pSprite cache. Restored (the port's unqualified call dispatches
  virtually, matching slot +0x28).
- `field_190` drives both the AddSummonVisualHit mode and the closing vfx
  switch in his body — the exe reads `m_dwFlags` (+0x1C) at both sites
  (0x55F854 neg/sbb/and 0x15, 0x55F893 cmp 7 + jump table). Both switched
  to m_dwFlags.
- `pUnsummon->m_firstCall = m_firstCall` — the exe copies [this+0xC4] to
  [pUnsummon+0xC4], which is `m_casterLevel` (CGameEffect.h /* 00C0 */ +
  the base shift), not m_firstCall.
- `CanJoinParty` renamed to the in-tree `Icewind586B70::sub_586CA0`; the
  literal 50 becomes `CGameSprite::FEEDBACK_TOOMANYSUMMONED` (its storage
  is the WORD global ds:0x85C10A the exe loads).
- His gate keeps `m_durationType != 1` as a live conjunct; in the exe the
  == 1 compare (ds:0x8491AA) sits after the in-set tests that can only
  enter on 0, 3 or 0x1000, so it is dead — the port keeps the in-set test
  plus `pSpawned != NULL` and records the redundant compare here.

The dice loop, the zero dice-size guard, the roll+1 on both paths, the
signed loop bounds, the /15 seconds (unsigned magic 0x88888889, shr 3),
the AddEffect argument set (EFFECT_LIST_TIMED from ds:0x8485E8, TRUE,
TRUE) and the closing `m_done = TRUE; return TRUE` (ret 0x4) all match
the exe as the fork wrote them.
