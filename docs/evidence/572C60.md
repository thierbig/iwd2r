## Notes

The count is one d4 (`rand() % 4 + 1`) drawn before the walk.

- Failed share skipped; non-sprite released and skipped.
- `IcewindMisc::IsUndead(object)` (`m_typeAI.m_nGeneral == G_UNDEAD`) is the
  exclusion with the opposite polarity from Halt Undead: when it is **true**
  the sprite is released and skipped (0x572D3E branches to the release at
  0x572D40); only a non-undead sprite is inserted into the kept list.
- Insertion is followed immediately by the count test (`inc ebp; cmp ebp,
  ebx`, 0x572D6F-0x572D74); the walk stops on the Nth living sprite, releasing
  that target's share first (0x572DAA).
- After `CProjectileArea::ApplyToTargets` (0x572DD6), the original calls
  `ReleaseShare` once more on the id at the current node (0x572DDB-0x572DFB).
  On the stop path this repeats the id just released; on the exhausted path
  the node is the list sentinel and the "id" is its uninitialised value slot.
  `CGameObjectArray::ReleaseShare` returns at its `THREAD_ASYNCH` test before
  reading the index (src/CGameObjectArray.cpp:223), so neither repeat has an
  observable effect. The port repeats the release only when the walk stopped
  on a real node; a sentinel has no addressable value slot to read.
