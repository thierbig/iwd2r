## Notes

The sibling of `BroadcastUpdateCharacterSlot` (0x42DCF0, ported): the same
slot walk and progress-bar handling, but instead of marking the character for
an effect update it **replies the character to the other players**.

With the session open (`GetSessionOpen`, 0x8CF6D8 + 0x1032) the slots are
0-5 when `bUpdateAllCharacters` is set (`nLastSlot` 5 from 0x42F4E8) and the
one given slot otherwise. For each slot the character is
`game->m_characters[nSlot]` (game + 0x3816, `INVALID_INDEX` for 6 or more),
denied with the usual SHARED/DENIED retry and released at once. `bLocal` is
TRUE when the service provider is 0 (+0x96E) or when the network's local
player (+0x104C) owns the sprite (+0x62). When `bLocal` or hosting (+0x1033):

- the first time, with `bProgressBarInPlace` and a service provider other
  than `SERV_PROV_NULL` (0x85E65C), the bar waits with reason `0x4D03`
  (19715);
- **for every player 0..`CMultiplayerSettings::MAX_PLAYERS`-1** (the byte at
  0x84D59C = 6) whose `GetPlayerID` is not 0, is not the local player, and
  whose `GetPlayerName` is not empty, `DemandCharacterSlotReply(name,
  nSlot, TRUE)` sends PLAYERCHAR/100 with the marshalled character.

With `bProgressBarInPlace` each slot adds 500000 (the DWORD at 0x8518A8) to
`m_nActionProgress` (+0x1976), including the empty slots. After the walk, if
something was sent and the bar is in place, the bar stops waiting (+0x197F)
and `CCacheStatus::InvalidateScreen` runs (+0x1D52).

**Return value:** the exe sets no explicit value on the main path (EAX is
whatever the last call left); the closed-session path leaves 0, and the only
caller ignores it. The port returns TRUE after the walk and FALSE on the
closed session, with a NOTE.

The unused `CString` local (the empty string at 0x8C1758, destroyed on both
paths) is kept as `sUnused` like the sibling's port.

`tests/test_ui_misc.cpp` ("msg: the demand-slot broadcast walks the slots and
drives the progress bar", `[uimisc][msg][data]`) runs it on the engine: the
closed session FALSE with the bar untouched; one slot +500000; all six slots
+3,000,000; without the bar unchanged. The engine's null provider stops the
replies, so the wire bytes stay read-only. **It bites**: with the stub 5 of
the 11 assertions fail.
