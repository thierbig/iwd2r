# 0x5768C0 CProjectileArea850900::ApplyToTargets

Vtable slot 0x94 of the fighter-gated strike (class documented in
docs/evidence/576870.md). The filter in front of the parent's one-shot
strike: walk the gathered list, share each id, and keep only the sprites
whose AI type carries the Fighter class bit (0x10). Everything else is
erased from the list before it is handed to 0x5765F0. Byte-identical
machine shape to the warrior filter 0x5767A0 — same opcodes, same
offsets, same control flow — except the one mask operand.

## Disassembly walkthrough (fresh, this task)

- `mov ebp,[esp+0xC]` — &targets; `mov esi,[head]` the first node; an
  empty list jumps straight to the tail delegate at 0x57697A.
- The loop (0x5768D9): target `GetShare` 0x599A50([esi+8] id,
  THREAD_ASYNCH 0x851873, &out, INFINITE); failure (≠ 0x85186C SUCCESS)
  → plain return at 0x576984 — NOTE: no release, and the parent strike
  never runs.
- `call [edx+4]` — `GetObjectType()` vs 0x31 (TYPE_SPRITE); non-sprite →
  jump to the loop bottom 0x57694C *without advancing esi* — NOTE: the
  node is re-shared and re-tested forever, a genuine spin in the exe
  bytes, unreachable because the gather it filters (0x576310) emits only
  sprite ids.
- Sprite: `call [eax+0x10]` — `CGameObject::GetAIType()` (0x44CB60,
  returns m_typeAI at +0x20); `test byte [eax+0x18],0x10` —
  m_nClassMask & CLASSMASK_FIGHTER. This one operand is the whole
  difference from 0x5767A0 (which tests 0xD1).
- Bit present (0x576927): `mov esi,[esi]` advance, loop bottom.
- Bit absent (0x57692B): the erase — unlink the node (prev->_Next =
  next, next->_Prev = prev), `operator_delete` 0x7FC984, `dec [ebp+8]`
  (--size), esi = the unlinked node's next.
- Loop bottom (0x57694C): `UndoShare` 0x599E70([esi+8], ASYNCH,
  INFINITE) — NOTE: esi has already advanced in both sprite paths, so
  this releases the *next* node's id, a share this iteration never took,
  while the just-taken share is never released; only the non-sprite path
  (no advance) releases the right id. When the advance reached the
  sentinel the bottom still ran UndoShare with the head node's value
  slot before falling through. `cmp esi,[ebp+4]` the sentinel; jne loop.
- Tail (0x57697A): `ecx = this; push ebp; call 0x5765F0` — a direct
  call delegating to the parent strike with the filtered list;
  `ret 0x4`.

## Branch inventory

The GetShare check, the sprite gate, the fighter-bit test and the loop
control are all ported. The no-release failure exit, the non-sprite spin
and the off-by-one loop-bottom release are the original's behaviour, not
port artifacts — each carries a NOTE at the matching source line.

## Port

src/CProjectile.cpp, `// 0x5768C0`: a while loop over the list —
GetShare(*it), failure → return; non-sprite → no advance (the spin,
NOTE'd); sprite with `(GetAIType().m_nClassMask & CLASSMASK_FIGHTER) !=
0` → ++it; else `it = targets.erase(it)`. The loop bottom releases the
id at the *new* position (the exe's off-by-one, NOTE'd; ours skips the
call at the end position, where the exe passed the head node's value
slot). After the loop, `CProjectileArea8507C8::ApplyToTargets(targets)`
— the exe's direct 0x5765F0 call.

## Test

Covered by the type-356 decode row in tests/test_visual_projectiles.cpp
("the plain area effects decode straight to their ctors") — the override
itself has no test hook; its behaviour needs a live area, which the
visual-projectile suite does not start.
