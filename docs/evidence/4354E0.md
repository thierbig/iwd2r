## Notes

The guards are the session pair: `GetSessionOpen()` (0x8CF6D8 + 0x1032, the
`cNetwork.m_bConnectionEstablished` byte `Dialog`/`Interact` read) and
`GetSessionHosting()` (+0x1033, `m_bIsHost`); either being false returns
FALSE. The 9-byte payload goes through `CreateBuffer` (the static
`STATICBUFFER` at 0x8D8FE4 when `STATICBUFFERSIZE` at 0x8ABE0C is at least
9, else `operator_new(9)`; a failed allocation returns FALSE) and is
`{BYTE active; DWORD controller; LONG leavingEdge}` in that order, little
endian, with no padding (the writes are at +0, +1 and +5).

The send is `SendSpecificMessage(CString(""), SEND_ALL_PLAYERS |
SEND_GUARANTEED, MSG_TYPE_MAPWORLD (109), MSG_SUBTYPE_MAPWORLD_ANNOUNCE_STATUS
(115), pByteMessage, 9)` - the flags are the OR of the DWORDs at 0x85E660
(0x100) and 0x85E664 (0x200), the two bytes at 0x84CF8B/0x84CF8E are the type
and subtype, and the empty name (0x8C5CF8) addresses all players. The new
constants are added beside their address neighbours (0x84CF8B/0x84CF8E,
between 0x84CF8A `MPSETTINGS_DEMAND_NIGHTMAREMODE` and 0x84CF98
`MSG_TYPE_OBJECT`); WSO has no names for them (T122 §3). The buffer is freed
with `DestroyBuffer` and the function returns TRUE regardless of
`SendSpecificMessage`'s result - the original returns TRUE even though
`SendMessage_` reports failure in this direct-play-less build.

Wire bytes as `CNetwork::SendSpecificMessage` writes them for a payload under
`MINIMAL_PACKET_SIZE`: `[0] = 0xFF` (`SPEC_MSG_FLAG_ENABLED`), `[1] = 109`,
`[2] = 115`, `[3..11] = the payload` (12 bytes; `SPEC_MSG_HEADER_LENGTH` = 3).
`tests/test_network.cpp` ("msg: MapWorld announce status writes MAPWORLD/115
for the host only", `[network][msg]`) installs the bare-`CChitin` fixture,
selects `SERV_PROV_TCP_IP` so `SendSpecificMessage` writes the static buffer,
and pins the two guards (the buffer untouched), the flag/type/subtype and the
three payload fields (including zeroed values). With both guards false it
writes nothing. Against the stub, 8 of its 17 assertions fail.
