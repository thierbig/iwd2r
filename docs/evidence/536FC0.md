# 0x536FC0 CProjectile::IsTargetImmune

## Decompiled (anchored on the exe; dependency of bundle row 0x57C1D0)

The driver bundle carries nothing for this address — Strike (0x57C1D0) calls
it directly (`call 0x536fc0`), so it is imported as a dependency, anchored on
the exe bytes (see exemption). What the exe does:

1. Reads its WORD projectile type from +0x6E and asks the target's
   projectile-immunity list at sprite+0xAA8 (0x4E7120 `OnList`); a hit
   returns TRUE.
2. Otherwise reads the DWORD spell level from +0x186. Its low BYTE decides:
   9 or more returns FALSE.
3. Otherwise indexes the ten-slot spell-level immunity table at
   sprite+0xAFC with that BYTE; a non-zero slot returns TRUE, an empty one
   FALSE.

`ret 0x4` — one stack argument, this in ECX.

## Port

```cpp
// 0x536FC0
BOOL CProjectile::IsTargetImmune(CGameSprite* pSprite)
{
    if (pSprite->GetDerivedStats()->m_cImmunitiesProjectile.OnList(m_projectileType) == 0
        && ((m_nSpellLevel & 0xFF) > 8
            || pSprite->GetDerivedStats()->m_cImmunitiesSpellLevel.m_levels[m_nSpellLevel & 0xFF] == 0)) {
        return FALSE;
    }

    return TRUE;
}
```

Added in `src/CProjectile.cpp` after `GetDirection` (address order); the
declaration goes into `src/CProjectile.h` next to it.

## Notes

The exe zero-extends the WORD projectile type into the OnList argument
(`xor eax,eax; mov ax,[esi+0x6e]`); the port's implicit integer promotion
does the same. The spell-level compare is on the low BYTE of the DWORD
field (`cmp al,0x9`), which the `& 0xFF` mask reproduces for both the
bound and the index.
