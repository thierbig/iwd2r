## Body

The first compare is `strcmp(m_sAreaString, "NO_AREA")` against
`s_NO_AREA_008abfa0` (0x50D678-0x50D68B); equal takes the 0x50D6C7 arm
and returns 1. That is the exact sentinel `Run` (0x50D6F0) stores for a
sprite in no area (`m_sAreaString = "NO_AREA"`, src/CMessage.cpp). Only
when it differs does the body call `CompareStrings(param_1,
m_sAreaString)` (0x50D690-0x50D6A0; 0x7E8182 is lstrcmpi, case
insensitive): a zero compare returns 1 through the same arm, any other
result returns 0 from the 0x50D6A2 arm. So TRUE means "this update
applies here" -- the message has no area, or its area is the argument's
area -- and FALSE means another area.

The argument is a **by-value** `CString`, which fixes the signature: the
callee runs a `__try` frame (SEH entry 0x818E58, `ret 4`), destroys its
own copy of the parameter at `[esp+0x14]` with `CString_Destruct`
0x7FCC1A on both exits (0x50D6AE for the FALSE arm, 0x50D6D3 for TRUE),
and the only other use of that slot is the dword load that gives
`CompareStrings` its first buffer (0x50D690) -- the layout of a
four-byte CString whose `m_pchData` sits at +0. The port writes the
comparison as `_stricmp`, the tree's spelling of lstrcmpi (the 0x407E
and 0x40D0 trigger arms, src/CGameAIBase.cpp).

The port keeps the exe's order: the sentinel test is a plain `strcmp`, so
a captured `"no_area"` is not the sentinel and falls through to the area
compare, where it does match the argument `"NO_AREA"` case-insensitively.

## Test

`tests/test_message_sprite_update.cpp`, "sprite update: sub_50D660
matches NO_AREA or the area name" `[msg]`: a ctor-built message with
`m_sAreaString` set directly. Cases: the sentinel against a real name,
the empty name and `"no_area"` (all TRUE); a real name against itself
and a differently-cased copy (TRUE); a different area and the empty
name (FALSE); the empty captured area against the empty name (TRUE) and
a real name (FALSE); and `"no_area"` against `"NO_AREA"` (TRUE) but a
real name (FALSE), proving the sentinel compare is case-sensitive while
the area compare is not.

## Notes

- The branch not taken is the sentinel short-circuit: when
  `m_sAreaString == "NO_AREA"` the body never reaches `CompareStrings`,
  and when it is not the sentinel the first arm never runs. The test
  drives both, so no branch is unexercised.
- `strcmp` here is the exe's 0x7E7A54 and `CompareStrings` its 0x7E8182
  (lstrcmpi); the tree has no `CompareStrings` helper, so the port uses
  `_stricmp` as elsewhere.
- `Run` 0x50D6F0 compares the same member to the same sentinel with
  `strcmp` again (src/CMessage.cpp); this helper does not replace that.
- `delete` of the by-value copy is compiler work (the exe's CString
  dtor call, the port's CString parameter); it is not a source call.
