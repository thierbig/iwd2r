## Payload (the bytes rule; the report's sketch said "length-prefixed")

The demand is `{DWORD nType; char resref[]}` — the resref has **no** length prefix; the packet's
size (4 + resref length) carries it. Verified against the host-side parser in
`OnResourceDemanded` (0x429BB3: `ebx = *(DWORD*)(pData + SPEC_MSG_HEADER_LENGTH)`, then
`dwSize - 7` bytes of resref), so the report's "length-prefixed resref" was a misreading and the
port follows the exe. The buffer is created as 0x1E bytes but only 4 + length are sent.

## Notes

1. Guards: session open and not hosting; an empty host name aborts (the inlined
   `CNetwork::GetHostPlayerName`: `m_nHostPlayer == -1` -> "", else `m_psPlayerName[n]`).
2. `bSendMessage` sends; `bWaitForMessage` polls `PeekSpecificMessage(host, 82, 82)` with
   `HandleBlockingMessages` + `m_bDisplayStale = TRUE` + `SleepEx(60, FALSE)` (the same loop as
   `DemandCharacterSlot`), then fetches and hands the payload to `sub_42A3F0`, deleting the
   fetched buffer. A closed session after the loop returns FALSE.
3. Follow-up when the box returns: the Ghidra decompile draft and the oracle case (the
   static-buffer capture; the wait path needs a session and cannot be fixtured honestly).
