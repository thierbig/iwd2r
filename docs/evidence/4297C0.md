## Payload (the bytes rule; the report's sketch said "length-prefixed")

The demand is `{DWORD nType; char resref[]}` — the resref has **no** length prefix; the packet's
size (4 + resref length) carries it. Verified against the host-side parser in
`OnResourceDemanded` (0x429BB3: `ebx = *(DWORD*)(pData + SPEC_MSG_HEADER_LENGTH)`, then
`dwSize - 7` bytes of resref), so the report's "length-prefixed resref" was a misreading and the
port follows the exe. The buffer is created as 0x1E bytes but only 4 + length are sent.

   fetched buffer. A closed session after the loop returns FALSE.

   processor still appears there as `FUN_0042a3f0`.
