## Notes

- The single-player arm (no connection, 0x5C9F5E-0x5C9FA7) builds
  CStore(resref) and re-marshals it to the temp folder unchanged: the
  three markup arguments are never read on this path, so a
  ChangeStoreMarkup action in a single-player game is a no-op rewrite.
- The replay gate differs from the sibling AddItemToBag (0x5C7B10):
  bStoreDemanded is NOT set when the client's local copy is fresh
  (verified 0x5C9DC7-0x5C9E64), and no ReleaseServerStore follows for
  the host -- the demand message is sent only when the client already
  holds a valid local copy ("STORV9.0"), as the replay gate's
  notification to the server.
- The markup broadcast carries the local store's resref, not the
  parameter (0x5C9E64-0x5C9EA7) -- the same store identity the host then
  looks up in its server table and the client invalidates.
- The host writes the three markups straight into the server store's
  header (m_nBuyMarkUp/m_nSellMarkDown/m_nAdditionalMarkDown at
  header+0xC/0x10/0x14) and keeps the slot demanded; the client's
  InvalidateStore cuts its temp copy to the 8-byte "STOOV9.0".
