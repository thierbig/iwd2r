# 0x42ABA0 CBaldurMessage::OnResourceSuggest

The client's receive of a resource suggestion (survey-121 row 1, PR group G20).

## Identity / route

- The exe's receive dispatcher is `CMessageHandler::AsynchronousUpdate`
  (0x4EE020, ported). Its `MSG_TYPE_RESOURCE` (82) arm at 0x4F3BE7 keys on the
  subtype byte (`[0x85E67C]`, the `CNetwork::SPEC_MSG_SUBTYPE` byte) and indexes
  the jump table 0x4F4CBC through the index table 0x4F4CD0:
  subtype 0x43 (67) -> 0x4F3C38 (0x42ADF0, OnResourceRequest),
  subtype 0x44 (68) -> 0x4F3C0D (0x429A90, OnResourceDemanded, already ported),
  subtype 0x52 (82) -> 0x4F3C24 (0x42A3F0, the demand's reply processor),
  subtype 0x53 (83) -> 0x4F3C4F -> **0x42ABA0 this function**.
- The sender is `ResourceSuggestLoad` (0x42AA10, ported at
  src/CMessage.cpp): it packs `{UINT nType; DWORD dwFlags; char sResRef[]}`
  after the 3-byte spec header and computes
  `dwFlags = m_nTravelScreenImageToUse | (bProgressBarInPlace | bProgressBarRequired) << 8`
  (src/CInfGame.cpp, the ported LoadArea path). That is exactly what the
  receiver parses here.

## Port

`BOOLEAN OnResourceSuggest(INT nMsgFrom, BYTE* pData, DWORD dwSize)` (ret 0xC):
the guard reads `g_pChitin+0x1032` (= `cNetwork.GetSessionOpen()`) and has no
hosting requirement (it is the client's receive); the payload is
`{UINT nType; DWORD dwFlags; char sResRef[]}` after the 3-byte spec header,
and only `nType == 1010` (CAreaFile) acts: it sets `CInfGame::field_4BD4`
(`+0x4BD4`, the flag the ported AsynchronousUpdate reads to suppress the queued
messages while a suggested area loads), calls
`CInfGame::LoadArea(sResName, (BYTE)dwFlags, ((dwFlags >> 8) & 1) != 0, FALSE)`
and clears field_4BD4. Every other type is accepted and dropped; the function
returns TRUE.

The original also declares two `CResHelper<...>` locals at the top; their
default ctor/dtor run but nothing else (no SetResRef call), so they are born
dead and the port omits them (see the parity waiver).

## Callers

- 0x4F3C4F, the subtype-83 arm of `CMessageHandler::AsynchronousUpdate`
  (0x4EE020). The network dispatch block is omitted in the port (single player,
  docs/adr/0002-single-player-only.md), so the handler is a callable method like
  every other receive handler in this layer.

## Callees

- 0x40CB10 CBaldurChitin::GetObjectGame
- 0x5A24D0 CInfGame::LoadArea
- CResRef/CRes/CResHelper/CDimm/CString shapes of the dead locals and the
  sResName temporary (see the waiver)

## Notes

- fd row 1 survey identity confirmed: the function loads the area a client is
  told to fetch; the `dwFlags` low byte is the travel-screen image and bit 8 is
  the progress-bar request (`(bProgressBarInPlace | bProgressBarRequired) << 8`
  on the sender).
- The name length is `dwSize - SPEC_MSG_HEADER_LENGTH - 8`, as the exe computes
  it; there is no bounds check (as in the original).
- Exe md5 200f038bec3ed50a964d68b3f0f1f0e7.
