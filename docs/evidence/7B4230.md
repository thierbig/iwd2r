## Notes

Unnamed in the original; ours names it CVidImage::GetTint (#guess, after
CVidPalette's GetTint, GetAdd and GetLight, which compute the same factors
for palettes). `__thiscall` on the CVidImage (ecx; m_paletteAffects at
+0x28), the factors returned through pointers, TRUE when any factor applies.
Its only caller is CVidBitmap::BltBmp24To32Tint (0x7CD870), which ours needed
to render portraits (see 7CD870.md).

Flags: 0x10000 (the global tint, CVidMode::GetGlobalTintColor) and 0x20000 (the image's rgbTintColor); both multiply (shift 16, maximum 255*255). Then m_paletteAffects.pRangeTints[0] multiplies by the range tint (pulsing with aRangeTintPeriods[0] when it is not 1), adding 8 to the shift; with m_paletteAffects.suppressTints & CVidPalette::m_SuppressTintMasks[0] (the byte at 0x8BD6D8) a pulsing range add or light pulls the factors towards the maximum.

The pulse phase is `(g_pChitin->nAUCounter + this) % (2 * period)`, folded
back above the period: it starts from the image's address, in the original
as in ours (truncated to 32 bits), so a pulsing range is not deterministic
across runs on either side.

No oracle case: it reads the active engine's CVidMode through g_pChitin.
`oracle.py replay compare scenarios/chargen_replay.txt` runs it.
