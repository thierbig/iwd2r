# 0x4D0B20 CGameSpy::sub_4D0B20

Member of CGameSpy in the original's GameSpy.cpp, `__thiscall`
`BOOLEAN sub_4D0B20(SOCKET* pSocket, BYTE bDatagram)` (callee cleans both
stack arguments), 92 bytes (0x4D0B20-0x4D0B7C). Ported in this run.

## Body

The byte at +0x0 (m_bWSAStarted) gates everything: zero returns FALSE with
no winsock call made (0x4D0B20-0x4D0B24). Otherwise the second argument
picks the transport — 1 opens a datagram socket
(`socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP)`, 0x4D0B2D-0x4D0B31), anything
else a stream socket (`socket(AF_INET, SOCK_STREAM, 0)`, 0x4D0B33-0x4D0B35).
INVALID_SOCKET returns FALSE (0x4D0B41). The socket is then switched to
non-blocking: `ioctlsocket(s, FIONBIO, &1)` — the argument slot written at
0x4D0B51 — and a failure there closes the socket (0x4D0B6F-0x4D0B70) and
returns FALSE. On success the handle is stored through the first argument
(0x4D0B63-0x4D0B67) and the function returns TRUE.

## Callers

Not wired: the sole call site is 0x600CC1 in
CScreenConnection::HandleEMEvent (event 2, stage 1 — the join path), inside
the block the tree renders as the placeholder

    if (g_pChitin->cGameSpy.m_bWSAStarted == 1) {
        // NOTE: GameSpy is not ported (multiplayer, ADR 0002).

That placeholder stands for the whole handshake — this call plus inet_addr
of the copied address (IAT 0x847548), htons of the port, the
connect/sendto sequence and the WSAAsyncSelect loop (0x600C63-0x600E2B) —
none of which is reconstructed. Wiring only the socket creation would open
a real socket nothing uses, so the NOTE stays; the port follows the class
pattern (header note in src/CGameSpy.h): bodies whole, call sites omitted,
the platform's winsock inert by default. The caller passes esi = 0 (set at
the function's 0x600B6E prologue and untouched since), i.e. the stream
transport.

## Test

Three cases in tests/test_gamespy.cpp [gamespy], driven through the
existing iwd2r_SetGameSpySockets fakes (SocketLog gained the recorded
(af, type, protocol) triples, a bAllowStream switch for the stream arm —
the datagram-only fake rejected it — and a bIoctlFails switch):

- "the socket helper refuses to run before winsock starts": m_bWSAStarted
  FALSE, both transports return FALSE and no socket call is made;
- "the socket helper opens a non-blocking socket for either transport":
  both calls return TRUE, hand back successive handles, and the fake saw
  (AF_INET, SOCK_STREAM, 0) and (AF_INET, SOCK_DGRAM, IPPROTO_UDP);
  nothing is closed;
- "the socket helper fails closed when the socket or the ioctl fails":
  INVALID_SOCKET leaves the out-parameter untouched with no close, and an
  ioctl failure closes exactly the handle that was opened.
