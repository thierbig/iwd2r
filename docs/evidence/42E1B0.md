## Notes

The reply body of PLAYERCHAR/85, the richer sibling of
`DemandCharacterSlotReply` (0x42F750, 80/100): same 3-byte header and the same
party-creature/creature-data/bio tail, but with the derived stats, the
animation id and the portrait icons inserted before the creature block.

Needs an open session (`GetSessionOpen`), else FALSE. With `bSendCharInfo`:
the slot's character (`GetCharacterSlot`) is shared (retry on
SHARED/DENIED); on success the payload is built, on failure `bSendCharInfo`
becomes FALSE and only the 3-byte header is sent. The blocks, in order:

```
SHORT  nCharacterSlot
BYTE   bSendCharInfo
BYTE   stats[sizeof(CDerivedStatsTemplate)]   CDerivedStats::Marshal
WORD   animationId                            m_animation.GetAnimationId()
WORD   nPortraitIcons                         m_portraitIcons count (< 128)
DWORD  icons[nPortraitIcons]                  the list's ints
       CSavedGamePartyCreature (0x340)        CGameSprite::Marshal(.., TRUE)
BYTE   creatureData[m_creatureSize]
DWORD  nCustomBio                             TLK override Fetch(bio)
char   bio[nCustomBio]
```

`UTIL_ASSERT_MSG(nPortraitIcons < 128, "nPortraitIcons < 128")` guards the
local icon array (CBaldurMessage.cpp line 3968). The creature block's
`m_creatureOffset` is overwritten with the payload offset of the data (our
`MarshalPtr` handle is resolved first, `compat/marshal_ptr.h`, and a stale
handle sends zeros as in the sibling). The buffer is freed with
`DestroyBuffer`.

The send: `PLAYERCHAR/117` - type 80 `MSG_TYPE_PLAYERCHAR` (0x84CF9F),
subtype 117 `MSG_SUBTYPE_PLAYERCHAR_UPDATE_REPLY` (0x84CFA1) - with
`SEND_GUARANTEED`, `| SEND_ALL_PLAYERS` when the requesting name is empty
(the exe's `strcmp(name, "")`), to `sSendTo`. Afterwards the exe pre-sizes
the caller's name buffer (`GetBuffer(0x80)`); kept with a NOTE. The unused
`CSound` local is constructed and destroyed with no effect (as in
`DemandCharacterSlotReply`) and is omitted, as the sibling's port does.

`tests/test_ui_misc.cpp` ("msg: the demand-slot update answers a closed
session and drives the reply") exercises the helper through
`OnUpdateDemandCharacterSlot`: the party's slot 0 takes this full path on the
running engine (the null provider stops the send before the buffer) and a
slot without a character takes the header-only path. **It bites**: with the
stub 2 of the 4 assertions fail.
