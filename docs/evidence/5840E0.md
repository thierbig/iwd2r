# 0x5840E0 CLUAConsole::ParseArgs

The console's argument parser: splits the text the dispatcher hands after
the command word into the value table (+0x10, counted by field_8) and the
token store (+0x24, counted by field_C), rejecting malformed text with
field_0 = -2 and the shared report. 475 bytes (0x5840E0-0x5842BA); new
method declaration on the CLUAConsole class in src/CLUAConsole.h, body in
src/CLUAConsole.cpp; ported in commit (see report).

## Naming

Not named by any string; the body identifies it. It parses the parenthesized
argument list of a console line, so `ParseArgs`.

## Body

SEH prologue, edi = this. The by-value parameter is trimmed in place
(TrimRight 0x7FAEFB at 0x584116, TrimLeft 0x7FAF47 at 0x58411F). The
pre-scan at 0x584124-0x584150 then locates the closing paren before any
parsing: `sArgs[0] == ')'` (0x58412C) skips straight to the loop; otherwise
i walks from 0 and the scan wants `sArgs[i+1] == ')'` (0x584148), failing
the line (-2 + CommandNotFound 0x58427C) when i hits 0x80 (0x584131) or
len-1 (0x58413C-0x584142, no paren before the end).

The main loop at 0x584152: an empty remainder is the silent return
(0x58415B). sToken is copy-assigned from sArgs (operator= 0x7FCD07 at
0x58416A) and the first ",)" (literal 0x8AF714) is found (0x7FD0D0 at
0x584178). A hit n splits: sToken = sToken.Left(n) (0x7FAA72 at 0x58418D),
sArgs = sArgs.Right(len-n-1) (0x7FA9F6 at 0x5841C3) — dropping the token
and the ',' before the ')'. A miss leaves sArgs whole (0x584181 jl). Then
sToken.TrimRight (0x5841E9), sArgs.TrimLeft (0x5841F2), and an empty token
loops back (0x584200) — that TrimLeft is what lets an all-blank remainder
drain instead of spinning.

A token opening with '"' (0x584208) of length >= 2 (0x584210) must end
with '"' (0x584212-0x584217) or the line is rejected (0x58427C); the inner
text is filed through AddTextArg as Mid(1, len-2) — the length re-read
through the GetLength thunk 0x41E160 at 0x58421D, Mid 0x7FA960 at 0x584234
building the argument in a stack slot that doubles as the by-value
parameter of the AddTextArg call at 0x58423B. Otherwise the token must
start with a digit (isdigit 0x7E93D9 at 0x584249) or '-' (0x584259): its
atoi value (0x7E7B8E at 0x58425F) is grown into the value table at the
current size — the m_nSize read from [this+0x18] at 0x58426B feeding
SetAtGrow 0x7FB967 at 0x58426F — and field_8 counts it (0x584274). Any
other first character, including the bare ')' tail every well-formed line
ends with, is the silent return at 0x584289.

NOTE: the split is CString::FindOneOf (0x7FD0D0 wraps _mbspbrk), so any
',' or ')' ends a token and is consumed with it: "5, 6)" files 5, then 6,
then ends on the empty remainder (0x58415B). A miss leaves sArgs whole, so
a numeric token past the closing paren with no further delimiter ("5)7")
re-appends forever — the exe's behavior, mirrored; the pre-scan only
guarantees some ')' after the first character. (85c first ported this as
CString::Find, a substring search for ",)"; corrected at landing.)
A quote-only token (len < 2) falls through to the digit branch and
silently returns, as in the exe (0x584210 jl).

## ecx / calling convention

thiscall: ecx is the console (from the dispatcher); reads this+0x18
(through the array header), writes this+0x0 (reject arms), this+0x8,
this+0x10 and this+0xC (through AddTextArg). One by-value CString
parameter, callee-cleaned by `ret 4` at 0x5842B8.

## Test

ParseArgs cases in tests/test_cluaconsole.cpp [clua] call it on a stack
console: "5,)" leaves field_8 = 1 with the value 5 in the table,
"5, 6)" files both values, `"potn08", -3)` files one token and -3,
`"name",)` leaves field_C = 1 with the token "name" in the store, and ")"
returns silently with both counters untouched. The two reject arms print
(CommandNotFound -> live world screen) and the "5)7" infinite-reparse input is
excluded by design; all three are pinned by the listing only.
