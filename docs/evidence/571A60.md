## Notes

`this` is a CProjectile: `[esi+0x72]` is `m_sourceId`. The body shares the
source once with `THREAD_ASYNCH` and `INFINITE` (`[0x851873]` is 0), asserts
that the share succeeded (the original source string is
`IcewindCProjectileAreas.cpp`, line 0x18B = 395), and reads the source's
virtual object type (`call [vtable+4]`). The sprite type constant
`[0x84C507]` is 0x31 (49, `CGameObject::TYPE_SPRITE`).

- A sprite: the level count is
  `m_derivedStats.SumSorcererWizardLevels()` at object+0x920, the distribution
  helper 0x4478C0. Its floor of 1 means at least one draw.
- Anything else: the level count is 11.
- The share is released before any `rand()` call (0x571AFB precedes the loop).
- `rand() & 3` with the signed-remainder fixup is `rand() % 4`; the
  accumulator adds `rand() % 4 + 1` once per level, i.e. one d4 per level.
- The `movsx di` / `jle` pair skips the loop for a level count of zero or
  below; neither path produces that.

The port keeps the original's single `GetShare` and assert instead of the
retry loop other ports use on `SHARED`/`DENIED`. `CUtil::UtilAssert` never
returns, so the original's continuation on a bad share is dead; ours returns
0 there so the unset pointer is never read.

## Runtime coverage limits

No oracle/emulator case: the body needs a live object array, a real source
sprite, and the VC6 `rand` sequence. The focused tests drive the port with
the engine's own world: a wizard source (3 d4), a source with no
sorcerer/wizard class bits (the helper's floor, 1 d4), and a container source
(11 d4), checking the exact draws and budget for every seed. They do not run
the original body, so this is read-only evidence plus a native test, not an
oracle measurement.
