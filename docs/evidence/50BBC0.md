## Notes

Identity: vtable 0x84D510 slot 0x18 (Marshal 0x10, Unmarshal 0x14).
The survey's row 104 names this address correctly.

Takes a deny share of m_targetId and hands the message's 51 equipment slots
over to the sprite. It keeps the launcher the sprite's current weapon needs
(demanding that weapon, reading its selected ability and resolving a launcher
slot; when the selected weapon slot is empty it selects the fist), then per
slot: an equal item (usage counts, wear, file flags and resref all match) is
disposed through CInfGame::AddDisposableItem; otherwise the current item is
unequipped first when the slot is a worn equipment slot, or an ammo/weapon
slot holding the selected weapon or the launcher, and is disposed; the
message item moves into the slot, is equipped for slots below 10 and, when it
lands in the selected weapon slot, its ability is selected. Finally it
rebuilds the sprite's quick weapon buttons for m_nWeaponSet
(CGameSprite::sub_726810), tells the active engine to update the personal
item status and releases the deny. When the deny fails it deletes the
message's items.

Not executed: no received message reaches it in the single-player build; the
test calls it directly. No oracle case or replay.

Fixture note: the tail's sub_726810/GetQuickWeapon walk dereferences the
quick weapon button state that character generation normally fills; the test
seeds the eight buttons (itemNum 10, the fist) so the walk uses the same
state a created character has.
