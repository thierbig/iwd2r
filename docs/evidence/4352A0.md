# 0x4352A0 CBaldurMessage::OnMapWorldStartRequest

Receive handler of CBaldurMessage (CMessage.cpp), 188 bytes
(0x4352A0-0x43535F). Ghidra labels it FUN_004352a0; annotate.py
misattributed it as CInfGame::sub_59FA00-style helper — the dispatch site
proves the receiver class (below). Ported in this run as
`CBaldurMessage::OnMapWorldStartRequest` in src/CMessage.cpp.

## Body

`__thiscall BOOLEAN f(CBaldurMessage* this, INT nMsgFrom, BYTE*
pByteMessage, DWORD dwSize)`, ret 0xC (three stack args). `this` is never
touched: ebp is loaded with g_pChitin at 0x4352AA-0x4352AD and every state
is reached through the globals.

- Gates (0x4352B2-0x4352BC): `g_pChitin->cNetwork.m_bConnectionEstablished`
  (CChitin+0x952 + CNetwork+0x6E0) and `m_bIsHost` (+0x6E1) must both be
  nonzero, else return FALSE.
- 0x4352BE-0x4352C5: `nFacing = *(DWORD*)(pByteMessage +
  CNetwork::SPEC_MSG_HEADER_LENGTH)` — the message body is the requester's
  facing dword just past the 3-byte specific-message header. 0x85E670 is
  that constant (a static const INT holding 3 in .data), used as the
  addressing base.
- Permission (0x4352CE-0x4352F0): bPermitted starts TRUE and drops to FALSE
  when `g_pBaldurChitin->m_pObjectGame->GetGameSave()->m_mode`
  (CInfGame+0x422C embedded CGameSave, m_mode at +0x1B6) is 386 or 1282,
  or when `GetMultiplayerSettings()->m_bHostPermittedDialog` (embedded at
  CInfGame+0x1BB2) is TRUE. The value table saves 386/1282 are the world-
  map travel modes; the same triple guard exists in-tree at
  src/CScreenWorld.cpp:2199-2218.

- Dispatch (0x435302-0x435322): if `pWorld->m_bHardPaused` (CScreenWorld
