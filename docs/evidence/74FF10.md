## Notes

Ported from the Ghidra listing and the disassembly (0x74FF10-0x7500E3, `__thiscall` with no
arguments, plain `ret`), called from `CGameSprite::ExecuteAction` at 0x729563 (case 17, then the
dispatcher's `done` at 0x72B30B).

The Ghidra decompile renders the `GetAllInRange` argument list out of order, because the compiler
pushed the trailing arguments before the two virtual calls whose results are also arguments: the
three pushes at 0x74FF43-0x74FF47 are `targets`, `FALSE`, `FALSE`; the call at 0x74FF59 is
`GetTerrainTable` (sprite vtable +0xA0, 0x6F2C60, no arguments) and its result is pushed; the call at
0x74FF65 is `GetHelpRange` (+0xA8, 0x6F2C30, no arguments) and its result is pushed at 0x74FF6E; then
0x74FF6F/0x74FF74 push the type and the center, and `CGameArea::GetAllInRange` (0x46D140) runs with
the full seven arguments. The source is therefore the `CGameAIBase::Shout` pattern (0x460110):

```
m_pArea->GetAllInRange(m_pos, CAIObjectType::ANYONE, GetHelpRange(), GetTerrainTable(),
    targets, FALSE, FALSE);
```

(`GetTerrainTable` ends up in the stack slot under the call, which is why the decompiler printed the
two calls as if they were separate statements before it.)

Then the trigger: the word at 0x847D9E is 3, TRIGGER.IDS's `Help(O:Object*)` (`CAITrigger::HELP`),
with `m_typeAI` as the cause and 0 as the specifics (0x74FF7D-0x74FF90). Each id from the list gets
a `CMessageSetTrigger(trigger, m_id, nId)` (the message's +8 is `m_id`, +4 is the found id) queued
through `g_pBaldurChitin->GetMessageHandler()->AddMessage(message, FALSE)` (the handler at
+0x4980); the handler returns ACTION_DONE (the word at 0x8485C4). Nothing draws `rand()`.

## Evidence

No oracle case: the handler needs a populated area, the object array and the message handler
(`CGameArea::GetAllInRange` 0x46D140 is itself read-only, docs/evidence/46D140.md). Proof is the
Catch2 data test `sprite: Help sends the Help trigger to the sprites in range`
(`tests/test_sprite_actions.cpp`, `[ai][data]`, `IWD2_DATA`): the party member in the start area
answers ACTION_DONE, the queued `CMessageSetTrigger`s all carry trigger id 3 / the caller's AI type /
specifics 0 / the caller as source, at least one targets the caller itself (distance 0), and running
the queued message lands the HELP trigger on the target.
