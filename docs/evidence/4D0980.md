## Notes

A CGameSpy member (ECX is the object; it reads and writes +0x00, +0x06 and
+0x26). It starts winsock when +0x00 is clear, checks the WSADATA's wVersion for
2 (not the call's return), resolves `master.gamespy.com` with
WSAAsyncGetHostByName(hwnd, 0x402, name, buffer, 0x400) and waits for the
window procedure's completion flag (+0x26) in up to ten 300 ms SleepEx slices,
cancelling the request when they run out. The first HOSTENT address
(h_addr_list[0] at buffer+0x0C, three loads: list, entry, first dword) becomes
the master address at +0x06.

The completion arrives as the 0x402 message; CChitin::WndProc's arm for it is
0x78D960 (its own evidence): it sets +0x26 for every error except the ten
listed there.

**Divergence, NOTE in the code:** the original returns from its two failure
paths without LeaveCriticalSection (#design-flaw). The port leaves the
section: the paths are unreachable on a machine with winsock, and here the
platform's inert WSAStartup always takes the first one, so the original's
leak would strand the reply section.

The platform's winsock calls are inert by default (platform/win32_api.h,
ADR 0002); tests install a fake table with iwd2r_SetGameSpySockets. The unit
tests cover the failed startup (no async request) and the success path (the
HOSTENT address copied, the version check passed). There is no oracle: the
master servers are gone and the socket state is not comparable.
