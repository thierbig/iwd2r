# 0x500CE0 CMessageSpellHitEffectSecondaryProjectile::Run

Receives a queued secondary-projectile message: it denies the target object, leaves when it has no area, decodes the message's projectile type with the object as the AI sprite when the object is an AI base, replicates the tornado's wander seed for the 305 decode, fires the projectile from the object's area and id at the message's stored point and height, and releases the deny. Unlike CMessageFireProjectile::Run (0x5007F0) there is no service-provider/local-player early out: the receive side always fires, because this message is only handled on the machines that did not fire it.

## Branch notes

- 0x500D09 GetDeny loop: repeats while the answer is 0x04 (SHARED) or 0x05 (DENIED); anything but 0x00 (SUCCESS) returns at 0x500E02 without a release.
- 0x500D41: the object's `m_pArea` (+0x12); NULL releases the deny (0x500D68) and returns.
- 0x500D70: virtual slot +4 `GetObjectType`; bit 0 is `TYPE_AIBASE`, so the AI branch passes the object as the projectile's sprite, the other branch passes NULL.
- 0x500DA4: the decoded projectile's `m_projectileType` (+0x6E) is compared to 0x130 (304). `DecodeProjectile` stamps the requested type minus one, so this is the 305 (whirling tornado) decode; 0x500DAC stores the message's field_20 (+0x20) into the projectile's +0x356 (`CProjectileWhirlwind::m_wanderSeed`).
- 0x500DB5: Fire with the object's `m_pArea`, its `m_id` (+0x5C), the message's projectileTargetId (+0xE), target point (+0x12/+0x16), height (+0x1A) and 0 as the type; the point is passed by value.
- 0x500DFC: ReleaseDeny with THREAD_ASYNCH, then return. No other action is taken.
- No RNG is read. The test pins the message type, target id, point and height; the decoded projectile's Fire is the only external effect, and the test observes its single object-array/area addition and removes it.
- Untested: the type-304 branch (message type 305, the wandering tornado's Fire path); the missing-object GetDeny failure and null-area tails are not separately staged.
