## Arm notes

- The two chains are deliberately asymmetric, and the port keeps it:
  chain A (string2) has NO answering exit -- an absent variable, LOCALS
  on a non-sprite and an unknown area all silently leave lValue 0 --
  while chain B (string1) answers FALSE outright for LOCALS on a
  non-sprite (0x458202) and an unknown area (0x458255). So
  `"GLOBAL:X" / "AR1200:Y"` with X absent still answers specifics == 0
  TRUE, but `"AR1200:X" / "GLOBAL:Y"` answers FALSE whatever X would
  have been.
- The OR (specifics 2) and XOR (specifics 3) compares are dead code in
  the original: each copy sits behind the same `cmp eax,1` gate as its
  AND sibling. Ported verbatim as 84g did for 0x40A5 -- the case answers
  FALSE for those specifics rather than computing the comparison.
- lValue is zeroed by `mov [esp+0xb0], esi` at 0x457E76 with esi still
  the bResult init 0 -- a reused zero, not a store of bResult.
- The miss tail at 0x4582A7 is the usual neg/sbb/inc:
  `bResult = (GetSpecifics() == 0)`.
- MYAREA reads the caller's area name as a C string from the start of
  the area header (its RESREF), the same convention as 0x40C9; NOTE
  comments in the case.
- With this arm ported, the dispatcher's remaining unported arms are
  0x4067 HappinessLT (0x4567C0) and 0x40E6 CheckSkill (0x455EDD),
  verified against the byte table 0x45B0C4 (238 entries indexing
  0x400A-0x40F7 into the jump table 0x45AE40; 74 entries select index
  0xA0, whose target 0x45AD4C is the FALSE/release tail; the `cmp 0xED,
  ja` bounds check sends anything higher to default). The rewritten
  `default:` comment records both facts.
