## Notes

Ported as `CItem* CGameSprite::DropItemFromBag(CString sName)`, 220 bytes
(`0x722740-0x72281C`). The by-value name is uppercased once. The loop visits
all 51 equipment slots in increasing order. Only a non-NULL item with item
type `0x3A` (58, a bag) is considered. For each bag it constructs the target
`CResRef` from the name and calls `RemoveItemFromBag(bag.cResRef, target)`.
The first non-NULL result is returned immediately; exhausted bags continue
the scan, and no matching item returns NULL.

The action-9 dispatcher obtains the name again for this call only when
`FindItemPersonal(name, 0, FALSE)` returned -1. Its result is passed straight
to the already recovered `DropItem(CItem*)` (`0x7618E0`), so no item produces
ACTION_ERROR. The original GiveItem body also calls this helper, but its
negative-slot storage behavior is deliberately not enabled by this change.

The data test `sprite: DropItem (9) drops personal and bagged items onto the
ground pile` covers a lowercase name, a gem removed from a real `00GBGA01`
bag, preservation of the bag itself, the resulting ground-pile item, and the
no-match NULL/error path. No original-runtime oracle or emulator case was
run; `kind: read-only` is intentional.
