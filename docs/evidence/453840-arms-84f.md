# 0x453840 CGameAIBase::EvaluateStatusTrigger, Task 84f arms

The dispatcher itself is 453840.md; this file records the four arms Task
84f ported, all in commit fe12d237. Register roles as in the other arm
batches: edi = this (mov edi, ecx at 0x453869) and ebx = 0 (NULL), esi =
bResult, the decoded CAITrigger copy at [esp+0x34], the CString temps
sScope/sName/sString on the stack. None of the four arms Decodes the
trigger copy -- the GlobalTimer trio reads its strings raw (as the
ported sibling 0x4040 does) and 0x40F6 reads nothing from it at all.

## Arm notes

- The three GlobalTimer arms are one resolution spelled thrice, as the
  VS trio was in 84e; the port spells all three with comments saying so,
  no shared helper, per the house rule for byte-adjacent arms. They
  differ only in the final comparison and, on 0x40E3, in never reading
  the value. They take the scope from string2 and the name from string1
  -- the 0x400F/0x4034 family parses one string instead; do not merge
  them.
- The Ghidra decompile renders 0x403F's tail as a less-than; the
  listing's sub/neg/sbb/inc is the equality idiom (and the trigger's
  name agrees). The listing is the authority, as in the 83x batch.
- 0x4040 answers TRUE for a missing variable (timer never started =
  expired); all three of these arms answer FALSE instead -- the port
  keeps each arm's own miss handling rather than sharing 0x4040's.
- 0x40F6's skip-on-unshareable is 0x40C5's behavior (84e), not 0x407A's
  give-up; the case comment names both. The walk breaks only on an exact
  SeeTarget answer of 1 -- any other truthy answer keeps walking with
  the previous result standing, which is why the port tests
  `bResult == 1`, not `bResult != 0`.
