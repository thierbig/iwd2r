# 0x453840 CGameAIBase::EvaluateStatusTrigger, Task 83x arms

The dispatcher itself is 453840.md; this file records the eight small arms
Task 83x ported, in commits 5fa33cc9 (0x4028, 0x4029, 0x402A, 0x402C) and
9438e509 (0x400A, 0x40AC/0x40AD, 0x40D9, 0x40ED). Register roles as in the
other arm batches: edi = this (mov edi, ecx at 0x453869) and ebx = 0 (NULL),
esi = bResult, the decoded CAITrigger copy at [esp+0x34], pSprite/pObject at
[esp+0x10], pObject2 at [esp+0x18], bNoRelease at [esp+0x28]. Two arms
resolve the trigger sprite through the vtable+0xA4 call (0x402C, 0x40AD) and
leave through the early epilogue 0x45AB7A when it comes back NULL; the
NumCreature trio never resolves anything (straight to the release tail);
0x400A decodes only the cause spec; 0x40D9 and 0x40ED resolve their decoded
cause into pObject2.

with NumCreatureLT at 0x4029 and NumCreatureGT at 0x402A, HPPercent(O:Object*,

exe's jump table sends both 0x40AC and 0x40AD to the same arm 0x4588ED, the
same shared-arm pattern as 0x40E1/0x40F4 in an earlier batch.

## Arm notes

- The NumCreature trio is three separate arms in the listing that push
  the same seven GetAllInRange arguments in a different interleave
  (0x4028 even has four pushes outstanding when it takes
  `lea ecx,[esp+0x44]` -- with esp 16 below the frame that is
  &triggerCopy); they differ only in the final normalizer (equality
  idiom for 0x4028, setg for 0x402A, setl for 0x4029), so the port is
  one case body picking the test by trigger ID, the same convention as
  the Morale and Level trios.
- 0x402C computes the percentage with the multiply idiom (lea x5, lea
  x5, shl 2 = x100) and normalizes with the equality idiom; 83w's
  HPPERCENTLT (0x402D) shares these loads exactly and jumps back to a
  setl tail earlier in the listing.
- 0x40AC/0x40AD is one arm for two trigger IDs; the port carries both
  case labels into the shared body and notes the IDS gap at 0x40AC in
  the case comment.
- 0x40D9's null path is IsRotation's (0x40D8 from 83w): jump straight
  to the release tail 0x45AD4C with bResult still zero from dispatch.
  The comparison itself is 16-bit (sub si,ax before the neg/sbb/inc).
- 0x40ED stores 0xFFFFFFFE (-2) rather than 1 or 0 when there is no
  object to test -- -2 is still TRUE for a BOOL, so a non-trigger
  caller gets a truthy answer for any cause. The test pins the exact
  value (== -2), not just truth.
- 0x400A never resolves an object at all -- it decodes the spec and
  reads the spec's own alignment byte, which is why an unnamed spec
  with a set alignment survives CAIObjectType::Decode's early return
  (m_SpecialCase[0] == 0 with no name) and the test can observe the
  byte directly.
