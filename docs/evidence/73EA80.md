## Notes

- **The contract**: a NULL target or `m_derivedStats.m_nEncumberance == 2` answers
  `ACTION_ERROR` (the encumbrance case with `FeedBack(FEEDBACK_TOOHEAVY_STOPPED,
  0, 0, 0, -1, 0, 0)`, as in `MoveToObject`/`CAIGroup`). Otherwise the mover's
  formation slot is `m_curAction.m_specificID2 & 0xFF`, clamped by the group's
  member count (at least 6, the byte the exe reads from the list); an
  out-of-range slot takes offset 0. The formation type is
  `m_curAction.m_specificID & 0xFF`.
- **The destination**: the target's facing rotates the formation
  (`(m_nDirection + 8) * 360 / 16 % 360`), `CAIGroup::GetOffsets(type, angle,
  TRUE)` gives the slots, and the point is the target's `GetNextWaypoint` cell
  plus the slot offset (`/ CAIGroup::OFFSET_MULTIPLIER`), centred in the cell
  (the grid size's halves; the exe divides by 16 and 12, the byte constants
  0x84D6A0/0x84D6A1).
- **The request**: issued only when the destination's cell differs from the
  mover's and (from the current destination or no request is pending or there
  is no path and no current request), and every eighth call (`field_5616 % 8`,
  the same cadence as `MoveToObject`). It is a **points** request
  (`m_nTargetPoints = 1`, `m_targetPoints = new POINT[1]`), unlike
  `MoveToObject`'s target ids, with `m_sourceSide = m_typeAI.GetEnemyAlly()`
  after the point allocation. `SetTarget(request, FALSE, LIST_FRONT)`.
- The handler returns `ACTION_INTERRUPTABLE` (1) on success, `ACTION_ERROR`
  (the `CGameAIBase::ACTION_ERROR` static at 0x8485CA) on the failures above.
- **Unit test**: `tests/test_sprite_actions.cpp` "action 215 asks for a
  formation slot around the target sprite" builds the action through a real
  sprite in AR1000 (formation type 0, slot 2), runs `ExecuteAction`, and checks
  the request's shape, its point, the source side, the return value and that the
  same destination does not re-ask. With the handler's return forced to
  `ACTION_DONE` the test fails 2 of 14 assertions. (The formation-offset term
  is (0, 0) for a one-member party — `GetOffsets` has no member-id list then —
  so the test cannot distinguish that summand; the arithmetic itself is the
  disassembly's, cited above.)
