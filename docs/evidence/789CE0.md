# 0x789CE0 CResFile::LoadCache

Member of CResourceManagerBIFEntry in the original's ChDimm.cpp (our
CResFile), `__thiscall` `BOOL LoadCache()`, 923 bytes
(0x789CE0-0x78A07A), plain `ret`.
Ported in commit c7e97c740.

## Body

Resolves the resource cache (`pResCache = &g_pChitin->cDimm.cResCache`,
asserted non-NULL and initialized), then refuses when the BIF is already
referenced by an open resource (`m_nRefCount != 0` → FALSE). Saves the
current directory through `_getcwd` (0x7E9BF7; failure → FALSE) — the
buffer is only restored via `_chdir` (0x7E9D2A) on the copy paths.

`GetResFileName(m_nIndex, ...)` maps the KEY index to a file name and
drive. The KEY file-name entry is copied into a local when the key table
is initialized and the index is in range (skipped, not failed, when not).
Bit 0 (hd0) means the file is already local → FALSE. Bit 0x200 (already
in the cache directory) is the cheap path: AddCacheCount,
AccessFileInCache, clear the pending-cache flag under g_pChitin+0x35C's
critical section, return TRUE — no `_chdir` and no copy.

Otherwise `lAliases.ResolveFileName` maps the CD path into the install
and `CDimm::WriteSetUp(dirName + keyName, &sCacheFileName)` computes the
cache destination. The function then waits out any synchronous
update/display refresh (SleepEx(5) loop), takes the cache count via
AddCacheCount (its contention failure → FALSE), and hands the copy to
`CResCache::CopyFile(m_nIndex, sKeyName, sResolved, sCacheFileName)`. A
copy failure rolls the cache count back under the critical section and
`_chdir`s home before returning FALSE; success clears the pending-cache
flag, `_chdir`s home, and returns TRUE.

## Test

Driven in tests/test_gam.cpp [gam][data] (commit dd0191d32): a stack
CResFile with `m_nRefCount = 1` returns FALSE before any file is
touched; `m_nIndex = 0x7FFFFFFF` fails GetResFileName's bounds check;
and KEY entry 0's BIF is hd0-resident on the test install, so its drive
gate returns FALSE right after GetResFileName succeeds. The bit-0x200
cheap path and the copy path mutate the installed game's resource cache
(AddCacheCount / AccessFileInCache / CResCache::CopyFile) and are never
driven from a test; the `_getcwd`/ResolveFileName/WriteSetUp failure
arms need an environment the test install cannot present.
