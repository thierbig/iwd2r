# 0x453840 CGameAIBase::EvaluateStatusTrigger, Task 83r arms

The dispatcher itself is 453840.md; this file records the eight small arms
Task 83r ported, in commits f29450a8 (0x4017, 0x401D, 0x40AE, 0x40EE) and
cc56fdb1 (0x4083, 0x4084, 0x4085, 0x4086). Register roles as in the other
arm batches: ebx = this, esi = bResult, edi = pObject2, the decoded
CAITrigger copy at [esp+0x34] (the `push edi` before Decode 0x45B490 is
that call's this-argument, callee-cleaned, so esp is back at base after
it). No arm of this batch shares an object or touches pObject or
bNoRelease; every arm ends `jmp 0x45AD4C`, the shared release tail whose
`mov eax, esi` hands esi to the caller raw.

## Notes

- 0x4017 and 0x401D are the same arm reading a different byte of the
  decoded cause (race at +6, specific at +0x13) and jumping to the same
  equality tail 0x454F87 (`sub/neg/sbb/inc`: 1 iff equal, the byte
  zero-extended before the compare). Per the task's instruction the two
  cases say so in comments rather than share a helper the exe does not
  have.
- 0x4084 and 0x4085 compute nothing themselves: each loads the counter
  and jumps into another arm's compare tail (setl at 0x456AA3, setg at
  0x459A21) -- shared code, reproduced as the plain operators.
- 0x4086 (0x45741D-0x457433): `xor esi,esi; mov si, [header+0x40]` then
  `and eax, 0xffff; and esi, eax` -- the specifics' low word AND the area
  type word, and the raw AND value is the answer (0x0045 & 0x45 answers
  0x45, not 1). The unit test pins the raw value and the high-word drop.
- 0x40AE (0x45895C) and 0x40EE (0x45A610-0x45A616) likewise answer the
  raw value: the option dword itself, and the byte at header+0x40 AND
  0x40. Neither normalizes.
- The area arms read [edi+0x12] (m_pArea) with no NULL check in the exe;
  the test sets pCaller->m_pArea explicitly.
- Tests (6c689004): 21 assertions, run alone under IWD2_DATA. The
  Race/Specifics causes are built with the CAIObjectType 11-arg ctor
  (race third, specific sixth), empty-named and instance-less, so Decode
  returns with the type unchanged; the area state (m_nBattleSongCounter,
  m_header.m_areaType) and the option are set and restored around the
  CHECKs.
