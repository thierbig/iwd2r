## Body notes

1. After the field stores the helper writes `m_posExact.x = m_pos.x << 10`
   and `m_posExact.y = (m_pos.y << 12) / 3` (0x6F3BC7-0x6F3BE8: signed
   division by 3 through `0x55555556`, with the sign correction at
   0x6F3BDD). It then copies `m_pos` into `m_posOld` (0x6F3C0B/0x6F3C11).
2. Unlike `AddToArea` (0x6F40F0) it does not call `CGameObject::AddToArea`,
   does not store `field_562C = 1`, and never writes `m_currentArea`
   (no store to this+0x4c4a in the listing).
3. `CheckIfVisible` runs only for the live trio `m_active && m_activeAI &&
   m_activeImprisonment` (0x6F3BEE-0x6F3C2F).
4. List dispatch: 0 = front (markers + `CSearchBitmap::AddObject` when the
   trio is live and `STATE_DEAD` is clear), 1 = back (`IncrHeightDynamic`),
   2 = flight (no-op), anything else `UTIL_ASSERT(FALSE)` at ObjCreature.cpp
   line 1386 (0x56A).
5. `SetFootstepChannel` always runs; the ready sound is re-requested only
   when not `STATE_SILENCED` and either footstep sounds are enabled or the
   character has no portrait, and only when `GetSndReady()` is non-empty.
6. The `m_bGlobal` block differs from `AddToArea`: it also requires
   `!GetGameSave()->field_1AC || InControl()` inside the portrait check
   (0x6F3F40-0x6F3F67), like `RemoveReplacementFromArea`; the BYTE
   `m_nCharacters` compare is against 0xFF (0x6F3FA4), not -1. Otherwise
   `m_type == 1` increments `m_nRandomMonster`.
7. ObjectAdd and the sprite update are skipped when any load flag or
   `CBaldurMessage::m_bInOnObjectAdd` is set (0x6F3FCB-0x6F3FFF). When they
   run, `MarshalMessage`/`ObjectAdd` precede
   `CGameSpriteLastUpdate::Initialize(TRUE)` and the new
   `CMessageSpriteUpdate(this, m_id, m_id)`.

## Runtime limits

The native macOS test (`tests/test_ui_misc.cpp`, `[uimisc][sprite][data]`)
builds the saved character from the install's `Characters` folder, puts it
into AR1000 through the existing game fixture, and calls this helper directly:
front list with a forced-off search flag, then back list with a zeroed
dynamic-height cell. It checks the exact field values, the two `m_posExact`
formulas, `m_posOld`, that `m_currentArea` is untouched, the search flag and
bitmap removal, `m_nCharacters`, `m_posLastVisMapEntry`, the dynamic-height
step, `m_cLastSpriteUpdate`, and that no message is queued. The caller-side
case runs the full `OnUpdateCharacterSlotReply` with that saved character and
checks the restored area/position/list/z/vert-list/infravision, the suppressed
sprite update and the old sprite's only allowed message.

Not executed by these native tests: the default-list assert, the LIST_FLIGHT
branch, the `m_bGlobal == FALSE && m_type == 1` random-monster increment, the
`m_nCharacters == 0xFF` reset, the silenced/empty-ready-sound skips, and the
`field_1AC != 0 && !InControl()` visibility skip. The listing has no RNG call;
the tests pin the helper's only formulas (`m_posExact.x = x << 10`,
`m_posExact.y = (y << 12) / 3`) with the exact grid point they pass, and the
dynamic-height index with the area's grid width. Remote Linux parity and the
oracle/gates were not run because the Linux host was unreachable for this
pass; no MAP/recovery data was regenerated.
