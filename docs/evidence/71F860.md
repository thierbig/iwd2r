# 0x71F860 CGameSprite::ApplyProjectileEffects

Member of CGameSprite in the original's ObjCreature.cpp, `__thiscall`
`void (CProjectile* pProjectile, CItem* pItem, SHORT nAbility,

Ported in b485c9f7; the target-type switch was corrected at landing.

## Body

A NULL item returns at once. Otherwise the item is demanded and its
ability `nAbility` fetched (NULL: release the item and return). The
launcher comes from GetLauncher(pAbility, &slot) (0x718650); when there
is one it is demanded and its ability 0 kept.

For every effect of the ammunition's ability (count at ability +0x1E):
GetAbilityEffect(nAbility, i, this), stamp m_source = m_pos (+0x7C),
m_target = targetPos (+0x84), m_sourceID = m_id (+0x10C), pass it
through IcewindMisc::sub_5860F0, then switch on m_targetType (+0x10)
through the table at 0x71FB60:

- 1: CMessageAddEffect(effect, m_id, m_id) queued; the effect is handed over.
- 2: CProjectile::AddEffect; handed over.
- 3: ApplyEffectToParty, then the effect is deleted.
- 4: ApplyEffectToSprites(e, FALSE, FALSE, 0, NULL), deleted.
- 5: ApplyEffectToSprites(e, TRUE, FALSE, 0, NULL), deleted.
- 6: ApplyEffectToSprites(e, FALSE, TRUE, m_typeAI.m_nSpecific (+0x33), NULL), deleted.
- 7: nothing applied, deleted.
- 8: ApplyEffectToSprites(e, FALSE, FALSE, 0, this), deleted.
- other: UTIL_ASSERT(FALSE) (line 0x5617), the effect is kept.

The ammunition is released, then the same loop runs over the launcher's
ability 0 effects (table 0x71FB80, assert line 0x5650), and the launcher
is released.
