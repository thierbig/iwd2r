# 0x43B1A0 CBaldurMessage::SendDeleteAreaVote

Read-only evidence from the MD5-pinned original via
`python3 -I tools/parity/annotate.py 0x43B1A0` and the Ghidra decompile
below; Ghidra names the function `FUN_0043b1a0`.

## Identity and calling convention

Member of CBaldurMessage in the original's Baldur/CMessage.cpp; the client's
answer to the `DELETEAREA` (k = 107) poll (subtype `s` = 115). `__thiscall`,
`ret 8`: `(CString sArea, BOOLEAN bVote)` -- the first argument is the
by-value area CString (the exe reads its length from the data pointer at
`param_1 - 8`).

## Body

Maps `bVote` to the wire character (`'y'` = 0x79, `'n'` = 0x6e) first, then
the guards: an established session and `m_bIsHost` false, else FALSE. The
host player's name comes from `CNetwork::GetHostPlayerName`; an empty name
means there is no host to answer, FALSE. The payload is
`{BYTE areaLen; char area[]; BYTE vote}` and goes out with
`CNetwork::SendSpecificMessage(hostName, SEND_GUARANTEED, MSG_TYPE_DELETEAREA,
MSG_SUBTYPE_DELETEAREA_VOTE (114), ...)`; TRUE after the send.

**Survey correction:** the survey listed this row as subtype `d` (100).
The disassembly pushes subtype **0x72 = 114** (`MSG_SUBTYPE_DELETEAREA_VOTE`,
the byte at 0x84CF74, which the tree's constant set was missing between the
poll 0x84CF73 and the result 0x84CF75); 100 (`MSG_SUBTYPE_DELETEAREA_RESULT`)
is the host's delete/no-delete *result* message that row 52's handler
receives.
