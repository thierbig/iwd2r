# 0x5765F0 CProjectileArea8507C8::ApplyToTargets

Vtable slot 0x94 of the one-shot area strike (class documented in
docs/evidence/576080.md). The strike itself — and unlike the base
0x5701B0's per-node CreateSecondary loop, this one shares the source,
asks allegiance, and strikes only the *first* target that qualifies.
Four of its exits skip the source release entirely; one releases a
share it never took. All five quirks are kept faithfully and NOTE'd in
the port.

## Disassembly walkthrough (fresh, this task)

- `push ecx` — the incoming &targets argument slot is reused as the
  pSource out-param.
- Source `GetShare` 0x599A50(m_sourceId, THREAD_ASYNCH, &out, INFINITE);
  failure (0x576649) → `ReleaseShare` 0x599E70(m_sourceId) and return —
  NOTE: a release of a share this path never took.
- `call [edx+0x4]` — `GetObjectType()` vs byte [0x84C507] = 0x31
  (TYPE_SPRITE); a non-sprite source → ReleaseShare(m_sourceId) and
  return.
- ebx = &targets cached ([esp+0x14]); esi = first node. An empty list
  returns at 0x576767 with no source release (NOTE, 0x57669D path).
- The loop (0x5766A3): target `GetShare`([esi+8] nId, ASYNCH, the same
  reused slot as pTarget out, INFINITE); failure → plain return at
  0x576767 with nothing released (NOTE, 0x5766D3).
- `cmp al,0x31; jne 0x5766FC` — non-sprite: ReleaseShare(nId), next
  node, sentinel compare, loop.
- Sprite: `sub_5852A0` 0x5852A0, cdecl — pSource pushed first, so the
  argument order is (pTarget, pSource) — IcewindMisc's opposite-sides
  allegiance probe (already ported, src/IcewindMisc.h:54);
  `add esp,8`; `cmp al,0x1; jne 0x5766FC` — same side: release, next,
  loop.
- 0x576734, opposite side: `CreateSecondary` via `call [edi+0x98]` with
  nId, `ReleaseShare` 0x599E70(nId), fall to 0x576767 — return after
  the first qualifying secondary, no source release (NOTE).
- Loop exhausted (0x57672D): return, no source release (NOTE).

`ret 0x4` — one stack argument, the targets list.

## Branch inventory

The GetShare checks, the sprite gates, the allegiance test and the loop
control are all ported. The five no-release/phantom-release exits are
the original's behaviour, not port artifacts — each carries a NOTE at
the matching source line.
