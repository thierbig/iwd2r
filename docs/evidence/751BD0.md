## Notes

The port keeps the function separate as `CGameSprite::sub_751BD0()` (declared in `CGameSprite.h` beside `LeaveParty`) because the original calls it as a function from `LeaveParty`'s overflow refill (0x751CD0; its only direct caller in the call graph), on the sprite it has just denied.

It is the join bookkeeping the normal JoinParty path performs inline: `CMessageChangeDirection(1, m_id, m_id)`, the area's `m_nCharacters` incremented (0xFF → 1), the connection-established `CharacterPartyOrderRequest` (0x432050) — the only unported callee, left as `// TODO: 0x432050` — `CGameStatsSprite::RecordJoinParty()` (0x4CB000), and, when `g_pChitin->cNetwork.m_bIsHost`, the six-slot scan with `CInfGame::GetCharacterSlot` (0x5BD650) assigning the matching slot: `SetCharacterControlledByPlayer(slot, 0, FALSE, FALSE)` (0x518710), `SignalCharacterStatus(slot, 11, TRUE, FALSE)` (0x518BA0) and `SetCharacterReady(slot, TRUE, FALSE)` (0x518A70).

Tested indirectly by the LeaveParty overflow test (the newly admitted sprite goes through this function; the party slot, the area count and the overflow list are checked).
