## Arm notes

- 0x407D's two early `push 0` (0x456C5A/0x456C5C) sit BEFORE the
  vert-list branch and serve BOTH search calls -- a8 (nearest index) and
  a9 (ignore dead) are zero for GetNearest and sub_46DAE0 alike. MSVC
  interleave: pushes before a branch can belong to either path.
- 0x407D hardcodes seeInvisible TRUE where the front-path resolver
  sub_40CED0 (CAIObjectType.cpp) passes the caller's
  GetCanSeeInvisible() -- the trigger sees invisible creatures the
  script resolver would hide.
- The bytes at 0x456E7B are shared: 0x4075 Contains' TRUE path jumps
  into 0x407D's instance-path release-by-GetId sequence (84b recorded
  the jump; this batch owns the bytes it lands in).
- 0x4090's instance-path GetShare ignores its return code and
  dereferences pObject2 regardless -- a failing share there faults in
  the original too; the port mirrors. The no-instance path DOES check
  (SUCCESS only) and answers FALSE without a release on failure.
- 0x4090 re-derives the slot id through sub_45B610 before each release
  (0x457699/0x4576BB); the value cannot differ from the first read, so
  the port reads it once -- the 0x40DA precedent.
