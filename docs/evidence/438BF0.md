## Notes

The host's half of the leave-area-by-name pair (the sender is
`sub_438710`/0x438710, already ported). Needs the session open **and** owned;
otherwise FALSE.

**Payload** (`pMessage + 3`):
`{PLAYER_ID remotePlayer; LONG remoteObject; PLAYER_ID remotePlayer2; LONG
remoteObject2; BYTE areaNameLength; char areaName[length]}`. The two remote
pairs go through `CGameRemoteObjectArray::Find` and become the character and
the trigger (the area's object), `INVALID_INDEX` on a miss; the name is a
`CString` from the length-prefixed bytes.

**The permit** starts TRUE. It is cleared:

- when `sub_518560()` (the settings' still-not-ready slots) is > 0 - the
  shared character gets `FeedBack(26826, 0, 0, 0, -1, 0, 0)` - or, failing
  that, when `sub_5186A0()` is > 0 with strref 41398;
- when `m_bInHandleBlockingMessages` is set (the chitin's message block at
  +0x488E, i.e. `m_cBaldurMessage` + 6) - this is the guard that refuses when
  the request comes through `HandleBlockingMessages` instead of the
  asynchronous poll;
- when the world is paused (`m_pEngineWorld->m_bPaused`);
- in a dialog mode (`m_gameSave.m_mode` 0x182 or 0x502);
- without the player's `CGamePermission::AREA_TRANSITION` (the byte at
  0x84C535 = 1) via `GetPermission(nMsgFrom, ...)`;
- when `m_multiplayerSettings.m_bHostPermittedDialog` (game + 0x1C58) is set.

If the permit survives, the host makes the transition:
`CInfGame::sub_5C4AD0(nCharacterId, nTriggerId, CString(sAreaName))`.

**The reply** is one byte (the permit) sent with `SEND_GUARANTEED` as
`LEAVEAREANAME/114`: type 120 `MSG_TYPE_LEAVEAREANAME` (0x84CFDB, existing)
and the new subtype 114 `MSG_SUBTYPE_LEAVEAREANAME_PERMIT_REPLY` (0x84CFDD)
to the requester's name. A failed buffer returns FALSE; otherwise TRUE.

`tests/test_ui_misc.cpp` ("msg: the leave-area-name request answers the
guards and refuses a paused game", `[uimisc][msg][data]`) runs it on the
engine: a closed session and a client FALSE; a host with the game paused and
with a pending host dialog both TRUE (the permit refused, no transition).
The reply byte and the transition are read-only. **It bites**: with the stub
2 of the 5 assertions fail.
