## Port

The fork declares this vtable slot but ships no body for it, so the port
is written from the exe. It is the same share-loop idiom the tree already
uses (e.g. the marshals of this batch), with the two shape details the
disassembly pins down: the out parameter is the member itself — the exe
passes `&[esi+0x18c]` directly, so every SHARED/DENIED retry rewrites
m_pSprite in place — and BAD_INDEX returns silently while only SUCCESS
(and the assert path falling through) reaches ReleaseShare. The member
`field_18C` is renamed m_pSprite in src/IcewindCGameEffects.h (the ctor
zero-initialization rides along); the class also gains the virtual
declarations for the three bodies this batch imports next
(SpawnFromResRef slot +0x2C) and the non-virtual PlayGroupVFX /
ApplyEffect, matching the 0x84F0A8 vtable.
