# 0x43F9B0 CProjectorSubtitles::Render

## What it is

The subtitle renderer. `thiscall`, no stack args, plain `ret`: draws
`m_sText` into the overlay surface `pSurfaces[8]` through the projector
engine's `CVidFont` (member +0x14A), word-wrapping into up to four bands of
`rcRect` height when the line is wider than the movie. Called from
sub_43E300's per-frame advance (wired here) right after the erase blt.

## Decode (annotate 0x43F9B0-0x43FCF4)

- Guard: `if (m_sText.GetLength() <= 0) return;` - buffer ptr at [this+0],
  length at buffer-8 (0x43F9CB-0x43F9D2).
- Font: `g_pBaldurChitin->m_pEngineProjector->field_14A` (chain
  [0x8CF6DC]+0x1C5C+0x14A, reloaded before every call - the port holds one
  reference).
- `nTextWidth = cFont.GetStringLength(m_sText, 1)` (ebx = this = &m_sText).
- `CopyRect` [0x8474D8] is called twice; only the local-0x20 copy (`rcClip`)
  is ever read (centering math + TextOut clip arg). The local-0x40 copy is
  dead - not ported, noted in the code.
- `nMaxWidth = rcRect.right - rcRect.left` (member +0x1C/+0x14).
- Fits check: `bFits = nTextWidth < nMaxWidth` (`jl`), `nLineCount = 1` with
  it; the wrap path constructs a working copy `sText` (copy-ctor 0x7FC98F),
  an empty `sBuilding` ([0x8C1758]) and `CString asLines[4]`
  (construct_array 0x7E79D2 with the CString ctor thunk 0x403310) before the
  branch - the port declares the array outside the if/else to match.
- Wrap loop, `nLine` 0..3 (ebp): `nLength = sText.GetLength()`; `nLength < 0`
  skips to the next line (defensive `jl`); inner scan `nIndex` 0..nLength-1
  (esi): `sBuilding += sText.GetAt(nIndex)` (char at a local, then
  operator_plus_equ 0x7FCFD1); when `cFont.GetStringLength(sBuilding, 1) >
  nMaxWidth` (`jg`) the line outgrew the band: walk `nIndex` back while
  `nIndex >= 0` and `sBuilding.GetAt(nIndex) != ' '` (`jns` loop); `nIndex <
  0` means no space - the line is DROPPED (jmp to the loop tail, next band);
  otherwise `asLines[nLine] = sBuilding.Left(nIndex)` (0x7FAA72),
  `sText = sText.Right(sText.GetLength() - nIndex - 1)` (0x7FA9F6),
  `nLineCount++`, `sBuilding = ""` (LPCSTR op= 0x7FCD57 / 0x8C5CF8), next
  line. The inner loop exiting with `nIndex == nLength` (0x43FB74) means the
  rest fits: `asLines[nLine] = sText; nLineCount++; break` (the exe sets
  ebp = 4 to force the outer exit).
- Render phase: `nFontHeight = cFont.GetFontHeight(1)` (movsx; computed
  before the branch - y starts at the same value in both paths).
- bFits: `nX = (rcClip.right - rcClip.left) / 2 - nTextWidth / 2` (each term
  halved separately via cdq/sub/sar); `cFont.SetColor(m_rgbColor, 0, 0)`;
  `cFont.TextOut(m_sText, nX, nFontHeight, rcClip, 8)` - surface slot 8, the
  subtitle surface the ctor created and Unload releases; jmp epilogue.
- `nLineCount <= 0` (`jle`): fall straight to the epilogue (locals destruct).
- Multi-line: `pLine = asLines`; `do { SetColor(m_rgbColor, 0, 0);
  TextOut(*pLine, 0, nFontHeight, rcClip, 8); nFontHeight +=
  cFont.GetFontHeight(1); pLine++; } while (--nLineCount != 0);` The exe
  calls GetFontHeight(1) TWICE per iteration (0x43FC83's eax is overwritten
  by the reload at 0x43FC88 before use) - the port keeps one call, noted in
  the code.
- Epilogue: destruct sText (EH state 1), sBuilding (state 0), array_destruct
  0x7E78DE over asLines - plain C++ scope ends in the port.

## Port

`src/CBaldurProjector.cpp` `CProjectorSubtitles::Render` (declaration already
in the header). `CVidFont& cFont` reference instead of the exe's per-call
reload of the same global chain.

## Callers wired (sub_43E300 0x43E300)

The `// TODO: Incomplete (subtitles).` line between the field_65A/EraseScreen
block and `m_pfnBinkDoFrame(bnk)` is replaced with the 0x43E3F7 advance:
`if (pProjectorSubtitles != NULL) { field_4++; if (m_pLines != NULL) {
pLine = &m_pLines[field_C]; if (pLine->field_0 > 0 && field_4 >=
pLine->field_0) { m_sText = pLine->m_sText; field_C++; <erase blt on
pSurfaces[8] with &rcRect, the ctor's exact DDBLTFX/Blt/CheckResults idiom>;
Render(); } } }`. field_4 is stored before the m_pLines NULL check (exe order
at 0x43E40C-0x43E412); the exe computes `&m_pLines[field_C]` once
(lea eax,[eax+ecx*8]) and reads both fields through it - kept as a local line
pointer. The follow-up commit adds the composite the same NULL test guards
(0x43E4DD-0x43E57C): every frame after the advance,
`pSurfaces[0]->BltFast(nDestXWide, nBandY, pSurfaces[8], &rcRect,
DDBLTFAST_WAIT)` - the band this renderer draws is composited onto the movie
back buffer because BinkCopyToBuffer overwrites it each frame; see
docs/evidence/43E300.md.

## Tests

None added: Render needs the registered CVidFont (GetStringLength/
GetFontHeight on real glyph data), the pSurfaces[8] DirectDraw surface and
the blitter - the test harness has no video stack, and stubbing the font
would only re-test the stub. The advance wiring sits behind a live BINK
frame loop, unreachable without binkw32 and a movie. The wrap algorithm's
observable surface (Left/Right/space walk-back) is pure MFC CString
plumbing, already covered by the compat string tests.
