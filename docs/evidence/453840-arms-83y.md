# 0x453840 CGameAIBase::EvaluateStatusTrigger, Task 83y arms

The dispatcher itself is 453840.md; this file records the eight small arms
Task 83y ported, in commits c39f5368 (0x4080, 0x4081, 0x402E, 0x401A) and
ee25361e (0x4097, 0x407F, 0x40C7, 0x40D0). Register roles as in the other
arm batches: edi = this (mov edi, ecx at 0x453869) and ebx = 0 (NULL),
esi = bResult, the decoded CAITrigger copy at [esp+0x34], pSprite/pObject at
[esp+0x10], pObject2 at [esp+0x18], bNoRelease at [esp+0x28]. Two arms
resolve the trigger sprite through the vtable+0xA4 call (0x402E, 0x401A) and
leave through the early epilogue 0x45AB7A when it comes back NULL; two
resolve their decoded cause into pObject2 through sub_40CB20 with the
TYPE_AIBASE byte 0x84C501 (0x407F -- NULL leaves through the early epilogue;
0x40D0 -- NULL falls to the release tail with the result still zero, the
IsFacingSavedRotation pattern); the other four resolve nothing at all.

## Arm notes

- 0x4080/0x4081 is the NumCreature trio's shape with a subtraction: the
  same seven GetAllInRange arguments in the same interleave, then
  list count minus GetNumCharacters() before the compare. They are two
  adjacent arms (0x4550F2 and 0x455151) differing only in the final
  normalizer -- equality through the shared tail at 0x45451D for 0x4080,
  setl entering the 0x4551AF block for 0x4081 -- so the port is one case
  body with both labels picking the test by trigger ID, the convention the
  trio set.
- 0x402E is byte-for-byte 0x402C HPPercent's computation (lea x5, lea x5,
  shl 2 = x100, then idiv) with setg instead of the equality idiom;
  a null sprite leaves through the early epilogue 0x45AB7A on both.
- 0x4097 does not break out of the list walk on a match -- it keeps
  scanning (which cannot change the answer once it is TRUE) and skips
  NULL node data; an empty list takes the release-tail jump from the
  head-position zero test with the result still zero.
- 0x407F's two FALSE paths differ: an unresolved cause leaves through the
  early epilogue with nothing released, while a resolved non-sprite falls
  through the type gate to the release tail with the result still zero;
  the sprite path releases its share inline (0x4570A3) before the same
  tail -- the net effect of leaving pObject2 set for the release label.
- 0x40C7's band is the area header's party-level band (field_4C lower,
  field_4D upper, field_4E the party level) -- the same fields and idiom
  as the CGameArea spawn load (0x460E9F). Specifics 3's TRUE comes from
  jumping to the release tail's mov esi,1 at 0x45AD47; the trailing
  cmp/jb at 0x459B2F is jump-threading, always true on that path.
- 0x40D0 compares case-insensitively through lstrcmpi; the original
  builds a CString of explicit length 32 from the script name to marshal
  both buffers, which changes nothing, so the port is _stricmp on
  m_string1 against the SCRIPTNAME directly, the 0x407E precedent.
