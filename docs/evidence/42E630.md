# 0x42E630 CBaldurMessage::OnUpdateCharacterSlotReply

## Disassembly reading

`llvm-objdump` of the vanilla exe, 0x42E630-0x42F0E3, read only far enough to
place the stub (the box is off; there is no Ghidra decompile for this function
yet). It is a `CBaldurMessage` method (0x42E64E stores `ecx` as `this`), with a
0x350-byte frame. It reads `g_pChitin->cNetwork.m_bConnectionEstablished`
(chitin+0x1032) at 0x42E692 and returns FALSE when the session is closed. Its
first actions construct a `CSound` (0x7A8BB0/0x7A8E20), so it plays the
character's update sound; the body then unmarshals the character slot data. The
exports call it `CBaldurMessage_OnUpdateCharacterSlotReply`.

## Callers

- 0x42D860 `CBaldurMessage::UpdateDemandCharacters` (both reply paths).
- 0x4EE020 `CMessageHandler::AsynchronousUpdate` (the omitted receive
  dispatcher).

## Callees

2,766 bytes with a large callee set (0x599C70/0x59A010 for the object array,
0x5AF4E0/0x5AFD90 for the portrait, 0x4D2CA0/0x4D4000, the sound constructors,
`operator_new` 0x7FC95B, `CString` helpers). Not mapped here beyond the entry.

## Notes

This task only declares `OnUpdateCharacterSlotReply` in `src/CMessage.h` and
defines a stub at 0x42E630 in `src/CMessage.cpp`:

```
// TODO: Incomplete. ...
delete pMessage;
return FALSE;
```

`UpdateDemandCharacters` calls it with `(playerSlot, pMessage, dwSize)` exactly
as the original does. The original callee consumes the fetched buffer (there is
no `operator_delete` call in its body, so it either hands the buffer to a callee
or leaks); the stub frees it so the placeholder does not leak.

The real port is a separate task: it must unmarshal the PLAYERCHAR 80/117
payload, update the local character/party state and play the update sound.
