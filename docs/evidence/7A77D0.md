# 0x7A77D0 CNetwork::SlidingWindowTimeouts

## Decompiled

Bundle row 0x7A77D0. The port is anchored on the exe bytes (see
exemption). What the exe does, in order:

1. Returns immediately unless the connection is established
   (`m_bConnectionEstablished == TRUE`).
2. Walks the six player slots. A slot with a non-zero
   `m_pPlayerID[nPlayer]` and an initialized sliding window gets
   `m_pSlidingWindow[nPlayer].TimeoutCall()`.
3. If we are the host (`m_nHostPlayer == m_nLocalPlayer`), every
   other player whose `m_nPlayerTimeout` has expired (unsigned
   `< GetTickCount()`) is kicked.
4. Otherwise (we are a client), when the host's slot
   (`m_nHostPlayer == nPlayer`) has an expired `m_nPlayerTimeout`,
   the session is closing: `OnMultiplayerSessionToClose()` through
   the CChitin vtable, a one-second `SleepEx`, and — if the
   connection is still flagged established — `OnCloseSession()`.
5. The sweep continues over all six slots regardless.

## Notes

The early-out at the top (0x7a77d3 → 0x7a7887) skips the three
register pops — they sit below the gate at 0x7a77e0-0x7a77e2 — and
lands directly on `pop edi; ret`; the port's outermost `if` has
the same shape.

The re-gate before `OnCloseSession` (0x7a7861) matters because the
1000 ms wait (`SleepEx(1000, FALSE)` — `bAlertable` is FALSE, so no
APCs fire during it) gives the network thread a window in which the
shutdown path can flip `m_bConnectionEstablished`; the port
reproduces the re-test exactly rather than hoisting it.

Both expiry tests are unsigned (`jae` skips when
`m_nPlayerTimeout >= tick`); a stale `m_nPlayerTimeout` of 0 always
counts as expired. The port's `DWORD` comparison keeps that.
