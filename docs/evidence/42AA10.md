## Notes

The server's suggestion that every player load a resource: a *real* service
provider is required (`GetServiceProvider() != SERV_PROV_NULL`, 0x42AA35 vs
the DWORD at 0x85E65C) and the session must be open
(`GetSessionOpen`, 0x8CF6D8 + 0x1032) - no hosting test here. The original
also refuses while the multiplayer screen's startup flag is set
(`g_pBaldurChitin + 0x1C90` is that screen, `+0x488 == 1`); ADR 0002 removed
the screen and the flag is never set in single player, so the port keeps the
two provider/session tests alone, with a NOTE (the same omission recorded for
`CBaldurChitin` 0x5AC430).

The payload is **not** length-prefixed, contrary to report-T122 §2.1's
shorthand: the exe writes two DWORDs - `nType` at +0, `dwFlags` at +4 - then
the raw resref bytes at +8 from a `CString` copy of `sResName`
(`CResRef`-style length from the string), and sends `len + 8` bytes. The
buffer itself is allocated with the constant `0x1E` (the compiler inlined
`CreateBuffer(0x1E)` at 0x42AA77), not with the computed size; since a resref
is at most 8 characters the packet never exceeds 16 payload bytes.

The wire is the existing `MSG_TYPE_RESOURCE` (82, the byte at 0x84CFB0) and
the new `MSG_SUBTYPE_RESOURCE_SUGGEST` (83, 0x84CFB3), to the empty player
name with `SEND_ALL_PLAYERS | SEND_GUARANTEED`; a failed buffer returns FALSE,
otherwise TRUE regardless of the send result (the original does the same -
`SendMessage_` reports failure in this direct-play-less build).

Wire bytes under `MINIMAL_PACKET_SIZE`: `[0] = 0xFF`, `[1] = 82`, `[2] = 83`,
`[3..6] = nType`, `[7..10] = dwFlags`, `[11..10+len] = the resref`
(18 bytes for "ARE1000"). `tests/test_network.cpp` ("msg: the resource suggest
carries the type, flags and resref on RESOURCE/83", `[network][msg]`) selects
the fixtures and pins the null-provider and closed-session guards (nothing
written), the type/flags/resref bytes and the empty resref. Against the stub,
8 of its 14 assertions fail.
