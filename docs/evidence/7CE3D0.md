# 0x7CE3D0 CVidTile::BltDualTile8To24

## What it is

The 24-bpp target of the dual-tile Render dispatcher 0x7B1F70's bpp switch
(`case 24`, jump at 0x7B222B). Thiscall on the CVidTile, `ret 0x24` = nine
stack args, same signature shape as BltDualTile8To16 0x7B25E0:
`BltDualTile8To24(DWORD* pSurface, LONG lPitch, BYTE* pData, BYTE*
pDualData, CResTile* pResDualTile, BYTE nDitherSeed, const CSize& blitSize,
LONG nDataJump, DWORD dwFlags)`. It blends this tile's palette with the
dual tile's palette per pixel through the 64x64x32 blend cube, dithered by
the seed's phase, writing 3 bytes per pixel. 1,116 bytes
(0x7CE3D0-0x7CE82B).

## Decode (annotate 0x7CE3D0-0x7CE82B)

- Setup as the 16-bpp blitter: local `CVidPalette cDualPalette` (ctor
  0x7BEEA0); six NULL-guarded video-mode reads (masks +0x18/+0x1C/+0x20,
  shifts as bytes +0xAA/+0xAE/+0xB2); m_pBlendTable [0x9060F0] NULL ->
  BuildBlendTable 0x7ACCB0 called directly (0x7CE4A8) - NOT an inlined
  fill loop as in 0x7B25E0; failure runs the local dtor and returns 0
  (0x7CE4BE) before any SetPalette.
- nDitherSeed >>= 3 (sar/shr loop 0x7CE4DD) -> dither phase 0-31.
- SetPalette #1 0x7CE50A: m_cPalette (this+4).SetPalette(pRes->m_pPalette
  (+0x50), 0x100, TYPE_RESOURCE); #2 0x7CE528: cDualPalette.SetPalette(
  pResDualTile->m_pPalette, ...).
- Realize #1 0x7CE54D: m_cPalette.Realize(rgbTempPal 0x9064F8, 24,
  dwFlags|0x400000, &m_paletteAffects (this+0x28), 255); #2 0x7CE564:
  cDualPalette.Realize(rgbDualTempPal 0x9060F4, 24, ...) - bpp 0x18, not
  0x7B25E0's 16.
- nSurfaceJump = lPitch - 3*width (0x7CE569-0x7CE576) - no /4*4 rounding,
  unlike BltTile8To24 0x7CDD00. Height <= 0 -> local dtor, return 1
  (0x7CE57A-0x7CE580, epilogue target 0x7CE801) - AFTER both Realizes,
  kept.
- Fast loop 0x7CE602-0x7CE6DE over width-1 pixels: the row-head counter is
  width-1 (dec ecx 0x7CE59B), and jle 0x7CE5D0 jumps a width of one
  straight to the tail. One cursor walks the dual data (row base += width-1
  at 0x7CE5E3); the primary byte is read at [delta+cursor] with delta =
  pData - pDualData (0x7CE5DD). Palette entries are DWORDs ([byte*4 +
  0x9064F8] / [byte*4 + 0x9060F4]); per channel the 16-bpp cube lookup
  (((x<<6)+y)<<5 + phase); the reassembled DWORD is written OVERLAPPING at
  the cursor (mov [eax-3], 0x7CE6CB) with dest += 3, so each pixel's
  fourth byte is overwritten by its successor.
- Unconditional tail pixel 0x7CE6F0-0x7CE7DA (a full duplicate of the
  blend math): the row base is NOT advanced when the fast loop was skipped
  (the jle at 0x7CE5D0 precedes the += width-1), so the tail index is
  max(0, width-1); it is written as a word plus its third byte
  (0x7CE7D4-0x7CE7DA). Dest row advance lea eax,[ecx+edx+3] (0x7CE7DD) =
  tail + 3 + nSurfaceJump, so rows land exactly lPitch apart.
- Source row advance: row base += nDataJump (0x7CE7F0) on top of the
  width-1 step at 0x7CE5E3, i.e. (width-1) + nDataJump per row - ONE PIXEL
  SHORT of the 16/32-bpp siblings' width + nDataJump, an original
  off-by-one ported as-is (NOTE in the source). Height loop jne 0x7CE5C6;
  success epilogue returns 1 (0x7CE819, ret 0x24 at 0x7CE829).

## Port

`src/CVidImage.cpp` `CVidTile::BltDualTile8To24`, declaration in
`src/CVidImage.h` after BltStencilTile8To24. Palette plumbing and channel
math mirror the 16-bpp port; the DWORD palette entries feed the blend
directly (no WORD truncation). The overlapping-DWORD fast loop, the
unconditional word+byte tail at max(0, width-1) and the (width-1)+nDataJump
source stride are faithful. Parity ran 0 RED without a waiver.

## Callers

The dual-tile Render 0x7B1F70's `case 24` (0x7B222B), wired in this task;
sole ultimate caller CInfTileSet::RenderToPrimary 0x5CB260's default-tile
arm.
