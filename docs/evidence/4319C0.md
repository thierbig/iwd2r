# 0x4319C0 CBaldurMessage::OnSwapItemRequest

## Disassembly reading

`llvm-objdump` of the vanilla exe, 0x4319C0-0x431C90 (723 bytes, `__thiscall`, `ret 0xc`), read
instruction by instruction (the box is off; there is no Ghidra decompile for this function yet).

- Frame: `this` spilled at 0x34; args `nMsgFrom` 0x58, `pMessage` 0x5C, `dwSize` 0x60; locals: the
  source byte at 0x5C (reusing the pMessage slot after the pointer is copied to ebx), the Find
  result `bResult` at 0x10 (started at 1), the error code at 0x14, the new `CItem*` at 0x18, the
  local object id at 0x1C, `bFromServer` at 0x60, the CResRef buffer at 0x3C (12 zeroed bytes).
- Parse (after the 3-byte header, `CNetwork::SPEC_MSG_HEADER_LENGTH`):
  `{BYTE source; DWORD remotePlayerID; DWORD remoteObjectID; SHORT slotNum; SHORT count;
  BYTE hasItem; [BYTE resRefLen; char resRef[]; WORD use1; WORD use2; WORD use3; WORD wear;
  DWORD flags]}`. The handler reads the source byte, calls
  `g_pBaldurChitin->GetObjectGame()->GetRemoteObjectArray()->Find(remotePlayerID, remoteObjectID,
  localObjectID)` (0x59B300), then the slots and the item block. For `hasItem == 1` it copies the
  resref into a zeroed 12-byte stack buffer (no length check, 0x431A52-0x431A88), reads the five
  item fields, and builds `new CItem(CResRef(resRef), use1, use2, use3, wear, flags)` (0x78A990
  CResRef ctor, 0x4E7E90 the CItem ctor; `operator_new(0xEE)`). Otherwise `pItem = NULL`.
- Assert (0x431B3C): `cnt == dwSize` (CBaldurMessage.cpp:6751) after the parse.
- `bFromServer = nMsgFrom == g_pChitin->cNetwork.m_nHostPlayer` (chitin+0x10E0).
- Gate (0x431B44-0x431B52): if `m_bInHandleBlockingMessages` (the byte at
  g_pBaldurChitin+0x488E = `m_cBaldurMessage`+6) is 1, `bResult = FALSE` and the swap is skipped.
- `STRREF errorCode = -1`; if `bResult` is still true, the source byte selects:
  - 0x47 (`'G'`) `SwapItemGround(localObjectID, slotNum, pItem, errorCode, count, bFromServer)`
    (0x5B7850);
  - 0x67 (`'g'`) `GetCharacterPortraitNum(localObjectID)` then `SwapItemPersonalInventory(portrait,
    pItem, slotNum, errorCode, count, bFromServer, TRUE)` (0x5BAD70);
  - 0x50 (`'P'`) `GetCharacterPortraitNum(localObjectID)` then `SwapItemPersonal(portrait,
    slotNum, pItem, errorCode, count, bFromServer)` (0x5B81C0); a -1 portrait is a failure.
  A missing local object or another source leaves `bResult = FALSE`.
- Tail (0x431C63-0x431C90): `SwapItemReply(nMsgFrom, bResult, pItem, errorCode)` (the helper at
  0x431CA0) and return TRUE, whatever the swap answered.

## Notes

The port is `CBaldurMessage::OnSwapItemRequest` in `src/CMessage.cpp`, plus the reply helper
`SwapItemReply` (0x431CA0). It keeps the wire layout, the remote-object Find, the CItem
construction, the `m_bInHandleBlockingMessages` refusal, the three source codes, the `-1` error
default and the always-TRUE answer; the reply helper carries the final `bResult`/`errorCode` back
to the requester.

The `'G'`/`'g'`/`'P'` source bytes match the callers of the (unported) request sender
`FUN_00431560` in the swap functions: `SwapItemGround` sends 0x47, `SwapItemPersonal` 0x50,
`SwapItemPersonalInventory` 0x67 (see docs/evidence/5B7850.md, 5B81C0.md, 5BAD70.md), so the
handler's switch is the receive side of the same protocol.

The CItem constructor (0x4E7E90) draws `rand()` for a MISC07 resref when `use1 != 0`; the handler
itself draws none, but a replay comparing rand state with this path must account for the ctor.

Proof is the unit test
`CBaldurMessage::OnSwapItemRequest replies a miss for an unknown remote object` in
`tests/test_network.cpp` (`[msg][network]`, no `IWD2_DATA`, 12 assertions): a zeroed
`g_pBaldurChitin`/`CInfGame` (the remote array size is 0) makes the Find miss, so the handler
answers TRUE with the SWAPITEM 73/114 reply `{BYTE 0, DWORD -1}` in
`CNetwork::STATIC_MESSAGE_BUFFER` (`0xFF, 73, 114, 0, FF FF FF FF`), and the
`m_bInHandleBlockingMessages` gate produces the same miss. The item and swap paths need a real
game, hence the read-only kind.
