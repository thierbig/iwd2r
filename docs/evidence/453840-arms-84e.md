# 0x453840 CGameAIBase::EvaluateStatusTrigger, Task 84e arms

The dispatcher itself is 453840.md; this file records the five arms Task
84e ported, in commits 6268d601 (0x40B8, 0x40B9, 0x40C0) and 38991621
(0x40C4, 0x40C5). Register roles as in the other arm batches: edi = this
(mov edi, ecx at 0x453869) and ebx = 0 (NULL), esi = bResult, the decoded
CAITrigger copy at [esp+0x34], pObject2 at [esp+0x18], the member share
at [esp+0x10]. The VS trio (0x40B8/0x40B9/0x40C0) and 0x40C5 decode the
whole trigger copy; the VS trio resolves its cause through
sub_40CB20(this, TYPE_AIBASE, FALSE) into pObject2 while 0x40C5 resolves
nothing (its IDS signature carries an object the arm never reads) and
0x40C4 resolves nothing at all -- it does not even Decode, reading int1
raw from the copy.

## Arm notes

- The VS trio is one body spelled thrice and the port spells all three
  with comments saying so, no shared helper, per the house rule for
  byte-adjacent arms. 0x40B9 is byte-identical to 0x40B8 except the
  final setcc (verified by an address-normalized diff of the two
  ranges); 0x40C0 differs only in the member contribution and its final
  setl. STAT_CLASSLEVELSUM reads the same byte the trio folds, so a
  sprite target always equals its own contribution for 0x40B8 -- the
  test leans on that for the equal-TRUE asserts.
- All four walking arms divide by a party count read FRESH after the
  walk (0x40C5 never divides); the exe divides by zero on an empty
  party and the port mirrors it, so the test seats a member before
  every resolved evaluation rather than asserting the empty-party
  crash. Only 0x40C5 answers an empty party FALSE, which the test
  asserts.
- 0x40C5's FindItemBags hit returns the BAG's own equipment slot, so
  the flags bit the arm tests after a bag hit is the bag's, not the
  carried item's -- mirrored without comment beyond the case comment.
- The item constructor force-identifies items with no lore value
  (GetLoreValue() == 0 sets m_flags bit 0, src/CItem.cpp 0x4E7E90), so
  the harness gem cannot be built unidentified from the constructor;
  the test clears the bit by hand and the comment says why.
