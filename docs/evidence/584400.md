# 0x584400 CLUAConsole::GetCommandWord

Returns the console's raw command word — the CString member at +0x4 that
the resolver 0x583E60 stores each entered word into — by value. 32 bytes
(0x584400-0x58441F); new method declaration on the CLUAConsole class in
src/CLUAConsole.h, body in src/CLUAConsole.cpp; ported in commit (see
report).

## Naming

Not named by any string; the body identifies it. It is the thiscall at
0x584400 taking ecx as the console and returning the +0x4 member by value,
and its one caller is 0x584320's unknown-word arm (this run's
`CommandNotFound`), which concatenates the result after the "Command not
found : " literal at 0x8AF7DC — the command word of the line that failed to
resolve. `GetCommandWord` after the member's role (field_4 is the console's
command word).

## Body

Thirty-two bytes: the hidden return buffer (pushed by the caller) is read
from the stack at 0x584402 (`mov esi,[esp+0xC]` after the two pushes), ecx
becomes this+0x4 (`add ecx,4` at 0x584406) and is pushed as the source, and
the CString copy ctor 0x7FC98F runs at 0x584414 with the buffer as its this.
The buffer pointer is returned in eax and `ret 4` (0x58441D) cleans the
buffer argument. No other member is touched. The tree's spelling is
`return field_4;`, which carries the same copy.

## ecx / calling convention

thiscall: ecx is the console (the dispatcher's this), read at this+0x4. The
callee cleans the one stack argument (the hidden CString return buffer) with
`ret 4`.

## Callers

In tree: `CLUAConsole::CommandNotFound` (0x584320, ported in this run) calls
it on the -1 arm. In the exe the same call is 0x584320's only use of it; no
other site references the address, so no TODO marks it.

## Test

No dedicated case: the observable effect is the returned string, which the
resolver/command-word tests in tests/test_cluaconsole.cpp exercise (the
resolver stores the word into the same member and CommandNotFound's message
arm reads it back). See the report's Task 85c section.
