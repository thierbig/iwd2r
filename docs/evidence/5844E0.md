# 0x5844E0 EncodeCommandWord

Scrambles a command word for the resolver's compare chain: every byte is
doubled after a fixed +8 offset, in place. 140 bytes (0x5844E0-0x58456B);
free-function declaration after the CLUAConsole class in src/CLUAConsole.h,
body in src/CLUAConsole.cpp; ported in commit (see report).

## Naming

Ghidra labels it `Encode_CString_Weirdness`; the tree names it after its
role for its one caller — the resolver 0x583E60 encodes the entered word
once (0x583EA6) and compares it against the same transform baked into each
command literal, so this is the console's command-word encoder,
`EncodeCommandWord`.

## Body

SEH prologue, then a counting loop over the argument's bytes. The length
check never calls GetLength: it is inlined as the CString header read
[eax-8], taken before the loop (0x584503) and again after each SetAt
(0x584526, which cannot change it). The loop body 0x584514-0x58451F is
register-only — al = sText[i], al += 8, al <<= 1, byte-truncated — and
SetAt (0x7FD114, called at 0x584521) stores the byte back. `test ecx,ecx;
jle` at 0x584508-0x584512 skips empty words. The tail at 0x584532-0x584569
copies the transformed string into the hidden return buffer (copy ctor
0x7FC98F at 0x58453D), destructs the argument (dtor 0x7FCC1A at 0x584553)
and returns.

The map (ch+8)*2 = 2*ch+0x10 is injective over the range the doubling keeps
inside a byte (all ASCII letters; "FIRSTAID" encodes to 9C A2 B4 B6 B8 92
A2 98), which is what lets the resolver compare encoded strings instead of
hashing.

## ecx / calling convention

Free function: the resolver passes ecx = the console at 0x583EA6, but the
body never reads it. Two callee-cleaned stack slots — the hidden CString
return buffer and the by-value CString parameter — give `ret 8` at 0x584569.

## Callers

In tree: `CLUAConsole::ResolveCommand` (0x583E60, ported later in this run)
encodes the entered word through it. In the exe: that call (0x583EA6) is the
only reference.

## Test

Encoder cases in tests/test_cluaconsole.cpp [clua]: "FIRSTAID" → 9C A2 B4 B6
B8 92 A2 98, "A" → 92, and the empty word passing through unchanged-length
(zero iterations). The transform itself has no engine state, so the string
in/out pair is the complete behaviour.
