# 0x7432 CGameSpriteLastUpdate

The sprite's last-sent sprite-update record: `CGameSprite::m_cLastSpriteUpdate`
at CGameSprite+0x7432, **0xFC bytes** (ends 0x752E, the next member
`m_bSendSpriteUpdate`). `CMessageSpriteUpdate::MarshalMessage` (0x50C550)
compares a message against it and sends only the differing groups, updating it
as it goes; `CGameSpriteLastUpdate::Initialize` (0x723B20) clears it and sets
the full-update flag; `~CGameSprite` (0x6F2F69/0x6F2F81/0x6F2F94) frees its
path and portrait arrays and its CString.

The member offsets/types are pinned three ways, all agreeing:

1. **Initialize 0x723B20** (198 bytes): its clear stores and its
   `operator_delete` calls name every offset, including the CString at +0x44,
   the two pointer members (+0x00 path, +0x3C portrait array), the
   `std::bitset<256>` block (+0x4E) and the flag at +0xF8. The full disassembly
   is in 723B20.md.
2. **the encoder 0x50C550**: its differential comparisons read every member
   (e.g. +0x7436 path count, +0x743A/+0x743E destination, +0x7444 sequence,
   +0x7454/+0x7456 hit points, +0x7476 area CString, +0x7480 spell states,
   +0x74A0 fade, +0x74A2 visual effects, +0x74A6 translucency, +0x74A8/+0x74E8
   skills, +0x7528 field_106, +0x752A flag) and its write-back stores land on
   the same offsets.
3. **the decoder 0x50D290** writes the message fields in the group order the
   encoder emits, fixing each member's semantic name (sequence, position,
   facing, state, hit points, flags, AC block, enemy/ally, level-up/HP bonus,
   portrait icons, path/currPath/destination/move scale, area name, skills,
   field_106, field_85).

Modelled in src/CGameSprite.h with the original offsets as `/* 7432 */`
comments and the `// 0x7432` marker. The **full Initialize body** is now
ported (src/CGameSprite.cpp, `CGameSpriteLastUpdate::Initialize`, 0x723B20;
see 723B20.md): it frees the path/portrait buffers and clears every field the
encoder compares, except the skill arrays and `field_106` (+0x76/+0xB6/+0xF6),
which the exe deliberately leaves for the full update to refresh. The class's
declared member initializers give a newly constructed sprite the same state,
and the destructor performs the free sites (equivalent to ~CGameSprite's
+0x7432/+0x746E/+0x7476 frees). The runtime clear on area moves is no longer
open.
