# 0x428AD0 CProjectorSubtitles::LoadLines

## What it is

The movie-subtitle loader the projector engine calls from EngineActivated's
subtitle block (0x43EC20, wired in this task's commits). `cdecl`, `ret` with no
immediate, three stack args: `CResRef cMovie` (8 bytes, by value), `int*
pnColor`, `int nWidth` (never read). No `this` anywhere — a free/static helper.

Class verification (task requirement): the body only touches globals
(`g_pBaldurChitin->m_cTlkTable` at 0x8CF6DC + 0x1CAC) and its args, and its
whole purpose is to build the `CProjectorSubtitlesLine[]` that
`CProjectorSubtitles` owns at +0x08 (element layout: DWORD + CString, 8 bytes;
the array-destructor 0x428F80 destroys the CString at +4 — same dtor token
`Unload` 0x43F900 documents). The original compiled it into
`CBaldurChitin.cpp` — its own assert says so:
`UtilAssert(0x127B, "C:\Projects\Icewind2\src\Baldur\CBaldurChitin.cpp", ...)`
at 0x428E35 — so it is NOT `CBaldurProjector` code despite the cluster row's
guess; ported as a static member of `CProjectorSubtitles`.

## Decode (annotate 0x428AD0-0x428F65)

- 0x428AF3-0x428B78: local `C2DArray c2dArray` (+ base ctor traffic), local
  `STR_RES strRes` (CString at +0x54, CSound at +0x58 — the CSound is
  `Fetch`'s out-param shape, not a dead sound), local `CString sError`
  (+0x1C); `c2dArray.Load(cMovie)` (arg at +0xCC passed by address).
- 0x428B81 `C2DArray::Demand`; `test eax,eax; jne` → on FALSE, unwind locals
  and `xor eax,eax` return NULL (0x428B8E-0x428C1F).
- 0x428C28 `C2DArray::Release`.
- 0x428C2D: `esi = GetHeight() - 2` (word at +0x42); `operator_new(esi*8+4)`
  with count dword at p-4 and `construct_array(0x428F70, 0x428F80, 8, esi)`
  → `new CProjectorSubtitlesLine[nRows - 2]`; user pointer kept at +0x44,
  returned at 0x428F4A.
- 0x428C79-0x428CEE: color packing. One `CPoint pt{0,0}` at +0x10 is reused:
  `GetAtLong(pt)` → al; pt.y=1 → `GetAtLong` → al; pt.y=2 → `GetAtLong` → al;
  pt.y=3 (0x428CDE) — then `*pnColor = b0 | b1<<8 | b2<<16` from the three low
  bytes (stored at +0x48/+0x1B/+ch). `*pnColor` is written BEFORE the NULL
  check: on failed `new` the color is still stored, then NULL returns
  (0x428CF0-0x428D87).
- 0x428D8C: loop guard `nRows - 3 <= 0` skips to the sentinel; otherwise
  `for (i = 0; i < nRows-3; i++, pLines += 8)`:
  - `field_0 = GetAtLong(pt)` (0x428D9C; column 0 = frame threshold),
  - `nStrRef = GetAtLong(CPoint(1, pt.y))` (0x428DB6-0x428DCE; the compiler
    scribbles 1 into pt.x and restores 0 at the loop tail 0x428E55, then
    pt.y++ at 0x428CDE-style `inc esi`),
  - `g_pBaldurChitin->m_cTlkTable.Fetch(nStrRef, strRes)` (0x428DD6) — on
    TRUE `pLines[i].m_sText = strRes.szText` (CString op= 0x7FCD07);
  - on FALSE: `new char[9]`, `cMovie.CopyToString(buf)` (0x428E02,
    char* overload), `sError.Format("STR REF %d not found while playing %s
    movie", nStrRef, buf)` (0x428E21, string at 0x8A76E0),
    `CUtil::UtilAssert(0x127B, "C:\Projects\Icewind2\src\Baldur\
    \CBaldurChitin.cpp", "FALSE", sError)` (0x428E3A). The 9-byte buffer is
    never deleted — leaked in the original; port keeps it with a NOTE.
- 0x428E67: sentinel `pLines[nRows-3].field_0 = 0; m_sText = ""` (LPCSTR
  op= 0x7FCD57) — the stop marker the per-frame advance gates on
  (`field_0 > 0`), matching `CProjectorSubtitles`'s use at sub_43E300.
- Epilogue: inlined `C2DArray` dtor (three array_destruct + operator_delete
  over m_pNamesX/m_pNamesY/m_pArray, m_default CString dtor), `strRes` /
  `sError` dtors, `mov eax, ebp` (the array), plain `ret`.

`nWidth` (+0xD8) is never read — it exists for the surface geometry handled by
the caller and `CProjectorSubtitles`'s ctor (0x43F6D0).

## Tests

None added: driving this needs a movie 2DA under `IWD2_DATA` plus the TLK
table (Fetch) and the resource manager (C2DArray::Load/Demand), none of which
the harness spins up for a unit test; an assertion-free test would prove
nothing. `Demand` failure → NULL is the only game-data-free arm and it merely
exercises the already-tested C2DArray/return path.
