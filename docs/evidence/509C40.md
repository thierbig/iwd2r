## Body

`__thiscall void MarshalMessage(BYTE** pData, DWORD* dwSize)`, 1548 bytes,
`ret 8`. Share the target (a failed share zeroes the size), write its
remote pair, m_triggerID and m_specificID, then the cause as one
CAIObjectType block (the object is used as it is: unlike
CMessageAddAction's body, no CAIObjectType::Set normalization copy is
made), the three fixed LONGs and the two strings. The size is
0xE + (name length + 2) + 0x26 (the block's 0x1A fixed bytes plus the 0xC
for the LONGs) + 2 + string1 length + 2 + string2 length; the closing
assert is `cnt == *dwSize` (0x50A03A). The quoted 0x26 form is the exe's
own size arithmetic (0x509D63), not a defect: the additions after it keep
adding to it.
## Wire format

Payload (without the 3-byte SPEC_MSG_HEADER): the target's remote pair
(PLAYER_ID m_remotePlayerID, LONG m_remoteObjectID; (0, 0xFFFFFFFF) when the
target does not resolve), SHORT m_triggerID, LONG m_specificID, then the
cause as one CAIObjectType block (SHORT name length and name, nine
one-byte selectors, DWORD m_nClassMask, the cause's m_nInstance as a remote
pair ((0, 0xFFFFFFFF) when it does not resolve), five m_SpecialCase bytes),
then the LONGs m_flags, m_specific2 and m_specific3, and the two
length-prefixed strings m_string1 and m_string2.
